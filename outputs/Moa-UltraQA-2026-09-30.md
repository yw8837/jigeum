# UltraQA Report — 모아 Android MVP 0.1.2

점검일: 2026-09-30 · 대상: `com.moa.babylanguage` · 제품명 `모아`는 확정 상표가 아닌 작업명

## 목표와 판정 범위

KOTA QA 문서는 **재현 사실과 추정의 분리, 중복 데이터, 폴백, 큰 글씨, 오프라인, 장애 시 복귀**의 점검 패턴만 참고했다. 해당 문서의 7장 `Codex 전달문`은 이번 프로젝트의 지시로 취급하지 않았다.

API 35 x86_64 Android 에뮬레이터에서 소리·카메라→보호자 맥락→문장→저장·삭제, 권한 거부, 앱 중단, 손상된 기록, 반복 사용, 200% 글자, 비행기 모드, APK와 홍보 영상까지 동적으로 확인했다. 테스트는 전용 에뮬레이터와 테스트 기록에 한정했다. 같은 실패가 3회 반복되거나 수정 주기 5회에 도달하면 중단하는 경계로 진행했고, 주요 수정·회귀 주기는 3회였다.

**판정:** 이 에뮬레이터 범위의 동적 QA는 완료했다. ARM 실기기의 영아 음성·얼굴 모델 품질, 저사양·16KB 페이지 기기 동작, 스토어 배포 준비는 통과 판정하지 않는다. 현재 APK에는 서버 통신 경로가 없어 운영 서버 장애·동시접속 부하 시험은 적용 대상이 아니다.

첫 오프라인 Lint 시도는 캐시되지 않은 Lint Gradle 의존성을 `--offline`에서 가져오지 못해 실패했다. 온라인 재실행에서 실제 코드 오류 1건이 드러났고 수정했다. 초기 권한·화면 확대 시험의 실패 중 일부는 Android가 권한 철회 시 앱을 강제 중지하는 동작, 하네스의 고정 스와이프 좌표·구형 MediaPipe 폴백 전제 때문이었다. 이를 제품 결함과 분리해 하네스를 수정하고 재실행했다.

## 발견한 결함과 수정

1. **P1 — 한 기록의 JSON 손상 시 정상 기록까지 전부 사라짐.** 배열 전체를 하나의 `try`로 읽던 코드를 항목별 파싱으로 바꾸고, 중복 ID를 건너뛰도록 했다. 정상 2건·손상 1건·중복 1건 주입 후 정상 2건 보존을 확인했다.
2. **P1 — 글자 200%·좁은 화면에서 카메라 행동 버튼에 접근하기 어려움.** 고정 화면을 세로 스크롤로 바꾸고 월령 선택을 세로 배치했다. 720×1280/200%에서 카메라 시작→문장 화면 및 13~18개월 선택을 확인했다.
3. **P2 — 마이크 권한을 반복 거부하면 녹음 경로 복구 안내가 부족함.** 앱 권한 설정으로 이동하는 버튼을 추가했다. 거부 상태와 권한 복구 후 녹음 종료를 확인했다.
4. **P2 — 같은 밀리초의 기록 ID 충돌 가능성.** 새 ID를 현재 시각과 기존 최대 ID+1 중 큰 값으로 생성한다. 주입된 중복 ID는 한 건만 렌더링된다.
5. **P2 — Lint 오류와 앱 아이콘 누락.** 카메라 하드웨어 선택 선언과 벡터 아이콘을 추가했다. 최종 Lint 오류는 0건이다.
6. **출시 호환성 — MediaPipe 0.10.21 ARM 라이브러리의 16KB 정렬 경고.** 1.0.0으로 갱신해 Lint의 해당 경고를 0건으로 줄였다. APK 자체의 `zipalign -P 16` 검증도 통과했다. x86_64 에뮬레이터에서 카메라 관찰과 10초 오디오 검토 화면을 다시 시험했다.

최종 Lint에는 업데이트 권고·화면 방향 등 **경고 14건**이 남고 오류는 없다. 16KB 실제 ARM 기기에서의 설치·추론 성공을 이 정적 검사로 대신하지 않는다.

## 장애·병목·사용 쏠림 판단

**현재 MVP:** APK에는 `INTERNET` 권한이 없고 소리·카메라 분석 및 문장 생성은 기기 안에서 처리된다. 중앙 서버 장애, 서버 동시접속, 큐 폭주가 이 버전의 핵심 흐름을 멈추게 하지는 않는다. 비행기 모드의 전체 수동 번역·저장·삭제 경로가 통과했다.

**기기 내 병목:** 음성은 최대 10초/16kHz 메모리 버퍼로 제한되고, 카메라 분석은 최신 프레임만 유지하는 backpressure와 약 180ms 관찰 간격을 사용한다. 최종 앱의 카메라 PSS는 시작 88.5MB, 5회 135.6MB, 10회 143.6MB였다. 같은 프로세스의 후속 측정은 15회 139.5MB, 20회 140.8MB였다. 워밍업 뒤 계속 선형 증가하는 패턴은 이 시험에서 보이지 않았으나, 에뮬레이터의 메모리 관리 결과만으로 모든 기기의 누수를 배제할 수는 없다. 기록 2,000건을 주입해 첫 화면과 최신 기록을 확인했고 충돌은 없었다. `SharedPreferences` JSON 전체를 UI 스레드에서 읽고 저장하는 구조는 기록이 더 늘면 지연 위험이 있어 실제 사용량을 보며 Room과 백그라운드 쓰기로 옮겨야 한다. 단일 `am start -W` 값(빈 기록 2,306ms, 2,000건 2,226ms)은 워밍업이 통제되지 않아 성능 비교 수치로 사용하지 않는다.

**서버 기능을 추가할 때의 출시 조건:** 기본 기기 내 경로를 유지하고, 영아 원본 업로드는 별도 명시 동의를 받는다. 업로드 크기·길이를 제한하고 오디오/영상 추론 작업 풀을 분리한다. 진입부에 동시 실행 상한과 대기열 상한을 두고 초과 시 `429`와 재시도 시각을 반환한다. 클라이언트 재시도는 지수 백오프·무작위 지연·횟수 상한을 사용해 재시도 폭주를 막는다. 요청별 고유 키로 중복 과금·중복 기록을 막고, 타임아웃·회로 차단·수동 문장 폴백을 제공한다. 1×/5×/10× 예상 피크와 30분 지속 부하, 추론 작업자 1대 중단, 큐 포화, 저장소 지연, 중복 요청을 스테이징에서 시험한다. p95 지연·오류율·큐 대기·거부율·모바일 메모리를 계측하고 파일럿 트래픽으로 수용 기준을 정한다. 현재는 서버와 실제 유입량이 없으므로 처리량·SLA 수치를 검증값으로 제시하지 않는다.

## 정리·롤백

- 손상·2,000건 주입 전 prefs를 각각 백업하고 `finally`에서 복원했다. 최종적으로 전용 에뮬레이터의 앱 테스트 데이터만 `pm clear`로 초기화했다. 사용자 PC의 다른 앱·KOTA 서비스 데이터는 변경하지 않았다.
- 화면 크기는 물리 1080×2400, 글자 배율 1.0, 비행기 모드 0, Wi‑Fi 1로 복원했다. 하네스에서 장기 실행 중인 녹음·카메라 작업은 없다. QA용 에뮬레이터는 종료했고 `adb devices`가 빈 목록을 반환했다. 이 실행의 OMX 상태도 `complete` 확인 후 `clear`했고 재조회에서 `exists=false`였다.
- 문제를 일으킨 테스트 하네스 시도와 스크린샷도 증거 ZIP에 보존했다. 배포 APK와 Android Studio 소스 ZIP은 0.1.2로 다시 생성했다.

## 남은 위험과 다음 검증

1. **출시 전 필수:** ARM64 실기기 2종 이상(가능하면 16KB 페이지 기기 포함)에서 모델 로딩, 10초 녹음, 카메라 시작·회전·20회 재진입, 발열·배터리·메모리 측정. Play 배포용 서명·정책 검토는 별도다.
2. **제품 약속:** 현재 `영상으로 번역하기`는 실시간 전면 카메라 장면 관찰이다. 기존 영상 파일 가져오기, 소리·영상 동시 분석은 없다. 실제 아기의 배고픔·졸림·감정이나 의도를 검증된 정확도로 판독하지 않는다. 스토어·홍보 문구는 `가능한 표현 예시`와 이 입력 범위에 맞춰야 한다.
3. **성능:** 기록 2,000건 이상의 장기 저장, 저사양 ARM 기기에서의 모델 지연·발열, 백그라운드 분석 중 시스템 강제 종료는 아직 측정하지 않았다. 단위 테스트 소스가 없어 회귀 방어는 현 동적 하네스에 의존한다.
4. **추후 서버:** 현재 서버가 없으므로 장애·피크 부하 수치 시험은 불가하다. 서버를 도입할 때 위 조건을 구현·계측한 뒤 다시 부하 QA를 한다.
