## 독립 검토 후 배포 gate 보강

위 Node **55/55** 결과는 유지한다. 별도의 PowerShell 배포 gate 하네스 **21/21 PASS**이며, 실제 Cloud 작업을 대역으로 바꿔 시험했다. 실제 Cloud 작업은0개다. 재현 명령은 `powershell -NoProfile -File tools/deploy/test-deployment-preflight.ps1`, 상세 결과는 `tools/deploy/QA-preflight-20261001.json`이다. 이 결과를 Cloud 인프라의 gate가 실제 충족됐다는 뜻으로 사용하지 않는다.

`-Execute`에는 `-OperationalGatesConfirmed`가 필수다. 운영자는 최소 IAM·Play 앱 권한·공개 정책·요청 메타데이터 30일 보존·예산·이미지/Android QA를 직접 확인해야 한다. 스크립트는 이미지 push 전에 billingEnabled, API6개, 지정 secret 숫자 버전2개의 ENABLED 상태, DOCKER 저장소, runtime/build 계정의 존재·활성, 기존 Run service 및 invoker IAM을 실제 읽고 현재 source의 Node 시험도 실행한다.

기존 공개 service는 `-PublishPublicService` 또는 `-ReuseExistingPublicService` 없이는 중단한다. allUsers invoker와 invoker IAM 검사 비활성을 모두 탐지한다. 정확한 대상의 not-found 진단만 신규 private 생성 경로로 허용하며, permission/network 오류를 service 없음으로 처리하지 않는다. 신규 private에는 명시적으로 `--no-allow-unauthenticated`를 사용하고 기존 service에는 이 회수 flag를 붙이지 않는다.

하네스는 dry-run, 수동 확인 누락, billing/API/secret/저장소/계정 오류, service/IAM 권한 오류, 다른 대상 not-found, 기존 공개·invoker 검사 비활성, Node 실패, build/digest/deploy 중간 실패, private existing/new 및 public reuse/publish 선택을 확인한다. 성공/실패 exit뿐 아니라 정확한 실패 문구·호출 수·후속 build/deploy/URL 중단·immutable digest·공개 IAM flag까지 검사한다. Windows PowerShell의 UTF8 로그 읽기와 native stderr ErrorRecord를 처리해 엉뚱한 초기 실패가 PASS로 계산되지 않도록 했다.

빌드 중 외부 관리자가 인프라를 바꿀 수 있다. 이 preflight는 상태를 원자적으로 잠그는 운영 보장이 아니며, IAM/Play를 대신 승인하거나 비용 연결을 수행하지 않는다.
