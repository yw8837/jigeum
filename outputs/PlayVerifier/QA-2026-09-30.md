# 결제 검증 서비스 로컬 QA — 2026-09-30

## 범위

통합 빌드 후보의 결제 클라이언트와 무상태 검증 서버를 점검했습니다. 배포·Play 제출·실결제를 실행하지 않았습니다.
Android 계측 실행 및 앱 전체 QA 결과는 통합 보고서가 최종 근거입니다.

## 발견한 결함과 수정

1. 서명 검사 함수가 주어진 시간을 무시해 만료 경계 검증이 불가능했습니다. 전달된 시각으로 검사하고 만료·미래발급·유효기간 상한 경계 테스트를 추가했습니다.
2. 이미 표시한 유료 권한이 화면을 오래 열어 둔 동안 만료되어도 남았습니다. 캐시 만료 타이머와 재진입 재검사를 추가했습니다.
3. 상품 조회 완료가 결제 중·보류·검증 중 상태를 덮었습니다. 진행 상태 유지와 구매 연타 가드를 추가했습니다.
4. 오래 걸린 이전 검증 응답이 최신 상태 이후에 캐시를 쓸 수 있었습니다. 네트워크 함수에서 캐시 수정을 제거하고 현재 세대의 응답만 적용합니다.
5. 명시적 구독 권한 거절과 일시적 서버 장애가 구분되지 않았습니다. 전자는 이전 권한 제거, 후자는 서명된 기존 권한의 남은 시간만 허용합니다.
6. 서버에 본문 대기·동시 요청·연결·대외 응답 크기 상한이 없었습니다. 시간·크기·동시성 제한과 과부하 빠른 응답을 추가했습니다.
7. 몰릴 때 OAuth 토큰 발급과 같은 구매 토큰 조회가 반복됐습니다. 진행 중 요청을 합치고 완료 상태는 재사용하지 않아 다음 조회가 환불/만료를 확인합니다.
8. 프록시 뒤 기본 IP 제한이 전체 사용자를 묶을 수 있어 원본 한도 설정과 실제 사용자별 edge 제한 요구를 문서화했습니다.

## 실행 결과

명령: `node --test` (Node v25.9.0, Windows, 로컬 루프백)

**16개 통과, 실패 0, 취소 0, 건너뜀 0.** 최신 실행 약 0.43초.

| 시나리오 | 실행과 관찰 |
|---|---|
| 정상·권한없음·장애 | HTTP 200 / 403 / 503 구분, 응답에 구매 토큰 없음, no-store |
| 손상·비정상 입력 | 잘못된 JSON·null·배열·식별자·상품 400, Content-Type 415, 16 KiB 초과 413 |
| 몰림과 회복 | 실제 로컬 HTTP 60건 동시 전송, 테스트 슬롯 상한 4개 유지, 4건 200·56건 503, health 200, 이후 요청 성공 |
| 제한 회피 | 위조 X-Forwarded-For로 한도 회피 불가, 429·Retry-After, 1분 창 이후 정상 |
| 느린 본문 | 중단된 chunked 본문 408, 초대형 chunked 본문 413, 이후 요청 정상 |
| 검증 지연 | 설정된 테스트 기한 후 503·AbortSignal, 슬롯 회수 후 정상 |
| 구독 상태 | 활성·유예·취소 후 잔여기간 허용, 보류·일시정지·만료·기간끝 거절 |
| 서명 | P-256 서명 검증, 설치 바인딩, 이용권 만료 상한 확인 |
| 중복 몰림 | 같은 토큰 20건에서 OAuth 1회·Play 조회 1회, 다음 조회는 회수 상태 반영 |
| 서로 다른 토큰 | 20건에서도 OAuth 발급은 1회 |
| Google 장애 분류 | 400/404/410은 거절, 401/403/429/500/503은 일시불가 |
| 대외 호출 timeout | 제한 시간 종료·진행 상태 정리·다음 요청 성공 |
| 취소·입력·키 | 취소된 요청·틀린키 종류·너무 긴 토큰이 권한 생성 못 함 |
| 토큰 경로 | URL 경로 인코딩, 패키지·설치별 서명 내용 검증 |

로컬 HTTP 테스트의 Google 응답은 메모리 대역입니다. 측정치는 운영 처리량 또는 실제 Play 구매 성공률을 뜻하지 않습니다.

## 정리

테스트가 생성한 서버·소켓은 각각 종료합니다. 테스트 키는 메모리에서만 생성합니다. 운영 비밀·계정·DB를 사용하지 않았습니다.
로그는 통합 QA 폴더의 `billing-node-tests.log`에 남깁니다.
