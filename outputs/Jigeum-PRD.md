# 지금 내 기분이 그래 — 6~18개월 아기 소리·표정 관찰 앱 실행 기획서

작성: 2026-09-30. 앱 이름은 사용자가 정한 `지금 내 기분이 그래`이며 스토어·상표 검토 전이다.

**저장 정책 확정:** 기록·메모는 기기 안에만 저장한다. 외부 DB·계정·자동 동기화 없이 동작하며 파일 내보내기·가져오기는 후속 개발이다. [현재 구조와 실제 엔진 사용 현황](Jigeum-OnDevice-Architecture.md)을 함께 참조한다.

## 현재 구현 상태 (직접 설치 후보 0.2.1)

Android 8.0 이상용 Android Studio 프로젝트와 설치용 디버그 APK를 만들었다. **소리 흐름**은 최대 10초 PCM을 기기 메모리에서 수집하고 번들된 YAMNet으로 일반 소리 후보를 구한다. 보호자가 후보를 확인하고 직전 상황을 고르면 아이 시점 문장 3개 중 하나를 선택하거나 고칠 수 있다. **영상 흐름**은 후면 기본·전후면 전환이 가능한 카메라 또는 시스템 파일 선택기에서 고른 30초·50MB 이하 영상이다. MediaPipe로 얼굴 존재·입 움직임이라는 제한된 단서를 관찰하며, 저장 영상은 최대 5개 프레임을 살펴본 뒤 첫 최대 10초의 소리를 YAMNet으로 분류한다. 후보가 있어도 보호자가 직접 듣고 확인해야 한다. 월령 범위 선택, 로컬 기록, 개별·전체 삭제와 개인정보처리방침 화면이 들어 있다. 원본 음성·영상 파일은 생성하거나 복사하지 않는다.

이 버전은 마이크 녹음, 실시간 카메라, 저장 영상 중 입력 경로를 고른다. 저장 영상의 얼굴 관찰과 소리 분류는 메모리 사용을 제한하도록 순서대로 실행한다. 학습된 영상·음성 결합 모델, 개인화 학습, 앱 내 TTS·공유, 아기의 실제 뜻을 판독하는 모델은 구현하지 않았다. 문장은 관찰 신호와 보호자 맥락을 바탕으로 작성된 **고정 표현 예시 3개**다. 최종 통합 QA 결과는 릴리스 보고서에 기록한다. 실제 ARM 기기의 추론 성능과 실제 영아 입력에 대한 분류 품질은 아직 검증이 필요하다.

출시 후보의 검증 범위와 발견·수정한 오류는 [최종 QA 기록](./Jigeum-QA-0.2.1.md), 가격·리텐션 설계는 [최신 BM 실행안](./Jigeum-BM-Retention-Pricing.md), 시장 근거는 [시장 진입안](./Jigeum-BM-Market.md)에 분리해 기록했다. 26.5초 세로형 동영상과 실제 앱 화면을 넣은 홍보 이미지는 `Marketing/`에 있다. 아래 기능·비즈니스 항목 중 공유·개인화·과금은 후속 기획이며 현재 구현 범위에는 포함되지 않는다.

## 1. 제품 판단

**한 줄 정의:** 6~18개월 아기의 짧은 영상·옹알이를 아이 시점의 자연스러운 한국어 문장으로 풀어 주고, 보호자가 실제 상황에 맞게 확인·수정하는 안드로이드 앱.

핵심 사용자는 한국에서 6~18개월 아기를 돌보는 엄마·아빠다. 아기가 특정 순간 무엇을 표현하려는지 궁금하다. 성공 경험은 영상·소리를 넣은 직후 아이가 말하는 듯한 짧은 문장을 읽고, 그 문장이 상황에 맞는지 바로 확인하며 적절히 반응하는 것이다.

**CEO 범위 검토:** 냥톡·멍톡류의 핵심 매력은 불분명한 소리를 한 문장으로 돌려주는 즉각적인 재미와 공감이다. 아기 앱에서는 같은 문장이 실제 돌봄 판단으로 이어질 수 있으므로 표현 품질과 근거 표시를 함께 설계한다. 6~18개월은 울음 외에 옹알이, 몸짓, 상호작용이 빠르게 바뀐다. 12개월 후 이상적인 상태는 각 아이의 영상·소리·맥락을 보호자가 교정하면서 가족만의 표현 패턴이 쌓이는 개인화 번역기다. 현재 MVP는 번역 순간의 유용함과 안전한 수정 루프를 검증한다.

### 구현 대안

| 접근 | 범위 | 노력 | 위험 | 장점 | 한계 |
|---|---|---:|---:|---|---|
| A. 보호자 맥락 기반 문장 | 음성/영상 포착 후 보호자가 상황을 고르면 1인칭 문장 생성 | 낮음 | 낮음 | 즉시 재미와 피드백 검증 | 자동 해석의 깊이가 얕음 |
| B. 온디바이스 단서 + 맥락 번역 **선택** | 짧은 입력의 관찰 신호를 추출하고 상황을 함께 받아 후보 문장 생성·수정 | 중간 | 중간 | 번역 경험과 설명 가능성을 동시에 시험 | 영아 데이터로 별도 성능 검증 필요 |
| C. 완전 자동 원인 번역 | 영상·소리만으로 욕구·감정을 확정하는 생성형 번역 | 높음 | 높음 | 사용 단계가 짧음 | 근거·라벨·안전·프라이버시 위험이 큼 |

선택 이유: B는 사용자가 원하는 즉각적인 아이 시점 번역을 제공하면서 입력 신호와 보호자 맥락을 분리한다. 모델이 준비되지 않거나 신뢰가 낮으면 A의 질문형 흐름으로 정상 작동한다. C는 영아 전용 검증셋, 교차 기기 시험, 발달 전문가 검토 없이는 제품 주장으로 채택하지 않는다.

## 2. 첫 버전의 약속

1. 보호자가 앱을 열고 두 번 이내의 탭으로 10~15초 `아기말 번역`을 시작한다.
2. 마이크나 카메라는 요청한 순간에만 접근한다. 원본은 기본적으로 저장·전송하지 않는다.
3. 결과의 주인공은 **아이 시점 번역 문장**이다. 예: “엄마, 나 이제 좀 쉬고 싶어. 잠깐 안아줄래?” 하단에 `이렇게 해석한 이유`와 `다른 뜻일 수도 있어요`를 표시한다. 진단 표현은 사용하지 않는다.
4. 수면·수유·놀이 등 맥락, 번역 문장, 실제 보호자 해석을 수정·삭제할 수 있다. 최소 2개의 다른 표현 후보를 제공한다.
5. 번역 결과를 다시 보고, 개별 기록과 앱 데이터 전체를 삭제할 수 있다. 공유는 보호자의 명시적인 선택으로만 한다.

### 제품 흐름

현재 구현: `홈` → `소리/실시간 카메라/저장된 영상` → `보호자 확인·직전 상황 선택` → `1인칭 표현 예시 + 대안` → `보호자 수정` → `기기 내 저장/삭제`. 월령 선택은 선택 사항이다. 동시 분석·공유는 후속 기획이다.

**홈:** 큰 `아기말 번역하기` 버튼, 소리/카메라 진입, 최근 번역 카드. 입력이 없을 때 예시 번역 한 장으로 기대치를 전달한다. 빽빽한 그래프는 사용하지 않는다.

**소리:** 권한 설명 후 녹음. 진행 중 파동 애니메이션과 명확한 종료 버튼. 휴대전화 통화, 권한 거부, 다른 앱의 마이크 점유, 너무 짧거나 소음이 큰 입력 처리. 자동 분류 결과는 번역 단서임을 표시하고 수정 가능해야 한다.

**표정:** 전면 카메라의 짧은 실시간 화면. 얼굴이 안 보이면 각도를 바꾸도록 안내. 입/눈/얼굴 위치 변화 등 관찰 가능한 출력에 한정한다. 촬영 파일은 기본 생성하지 않는다. 표정 하나를 곧바로 특정 욕구에 매핑하지 않는다.

**번역 엔진:** 입력 모드, 신호 유형(옹알이, 웃음, 울음, 기타), 직전 상황(수유, 수면, 놀이, 이동, 모름), 시간대 및 보호자 피드백으로 문장 후보를 고른다. 기본 문장은 1인칭, 1~2문장, 구체적이되 단정하지 않는 반응 요청 형태다. 예: “아빠, 저 소리가 궁금해. 한 번 더 같이 봐 줄래?” 같은 신호라도 맥락에 따라 문장이 달라진다. 무음/얼굴 미검출/소음에서는 뜻을 지어내지 않고 맥락 선택을 요청한다. 아기/성인 분리는 검증 전에는 주장하지 않는다.

**기록:** 입력 신호 후보 또는 수동 선택, 직전 상황, 선택한 번역 문장, 보호자 수정문, 시각. 원본 미디어는 저장하지 않는다.

**다음 반응:** 번역 바로 아래에 부모가 시도할 수 있는 한 가지 짧은 제안. 예: “아기가 낸 소리를 한 번 따라하고 잠시 기다려 보세요.” 특정 발성과 진단을 연결하지 않는다.

### UI·그래픽·모션 기준

레퍼런스 잠금: MeowTalk/멍냥톡의 `짧은 녹음 → 한눈에 읽히는 번역 문장 → 기록`이라는 리듬을 가져온다. 아기 앱 특성에 맞게 `근거/다른 해석/보호자 수정`을 결과 카드 안에 배치한다. Material 3의 큰 조작 영역과 운영체제 권한 흐름을 따른다. Refero 디자인 가이드의 기능 중심 색상·모션 원칙을 적용한다.

브랜드 방향은 `포근하지만 장난감 같지 않은 육아 도구`다. 따뜻한 크림 바탕, 짙은 녹회색 본문, 세이지색 보조, 살구색의 단일 주요 행동. 본문은 16sp 이상, 결과 문장은 24~28sp, 대부분의 인터랙션은 48dp 이상. 화면당 주요 CTA 하나만 눈에 띄게 둔다. 반복 카드 장식과 과장된 그림자를 피하고, 아기 사진을 요구하지 않는다.

마이크를 켠 동안만 파형/호흡 펄스를 보여 주고 종료 즉시 멈춘다. 상태 전환은 대략 160~240ms로 짧게 둔다. 애니메이션은 녹음 중임을 알리는 피드백이 목적이며 의미 없는 대기 연출을 만들지 않는다. 큰 글씨/화면 읽기에서는 상태 문장을 별도로 제공한다.

### 번역 문장 생성 규칙

| 관찰·맥락 | 첫 문장 예시 | 다른 가능성 | 금지할 주장 |
|---|---|---|---|
| 옹알이 + 놀이 중 | “엄마, 이거 재미있어. 나랑 한 번 더 해 줄래?” | “나 지금 말 걸고 있어. 내 소리 들어줘!” | 특정 단어를 실제로 발화했다는 표시 |
| 울음 + 마지막 수유가 오래됨(보호자 입력) | “아빠, 배가 고픈 걸까? 먹을 시간이 됐는지 봐 줄래?” | “잠깐 안아주면 좋겠어.” | 소리만으로 배고픔 확정 |
| 울음 + 잠들기 전(보호자 입력) | “엄마, 이제 좀 쉬고 싶어. 조용히 안아 줄래?” | “뭔가 불편한 게 있을지도 몰라.” | 수면 부족/질환 진단 |
| 웃음 + 놀이 중 | “아빠, 그거 또 해줘! 재미있어.” | “나랑 계속 이야기해 줘.” | 웃음의 원인을 특정 사건으로 확정 |
| 신호 불명/맥락 없음 | “내 소리 들었어? 지금 내 이야기를 들어줘.” | “내가 뭘 원하는지 함께 살펴봐 줘.” | 근거 없는 배고픔·통증·감정 판정 |

질문형 문장만 반복하지 않는다. 중심 문장은 아이 시점의 자연스러운 말로 쓰되, 해석 가능성 표시는 UI의 제목/설명에서 한다. 보호자가 수정한 문장은 이후 기록에 보존되지만, 명시적 학습 동의와 검증 이전에 “개인화 모델이 배웠다”고 말하지 않는다.

## 3. 기술 판정

| 레퍼런스 | 실제 역할 | 첫 버전에서의 사용 판단 |
|---|---|---|
| YAMNet | AudioSet 521개 일반 소리 사건 분류/임베딩 | 울음 등 소리 후보의 제한적 보조. 욕구 의미 추론 금지. 영아 데이터 시험 전 정확도 수치 노출 금지. |
| MediaPipe | Face Landmarker와 오디오 태스크 | 얼굴 랜드마크/블렌드셰이프 관찰. 영아 감정 판독 금지. |
| LiteRT | 모바일 추론 런타임 | 자체 검증 모델을 배포할 때 사용. 자체 모델이 없으면 별도 계층으로 과도하게 도입하지 않음. |
| librosa | Python 음향 분석·실험 | 연구/평가 파이프라인에 사용. Android 앱 런타임에 직접 넣지 않음. |
| voc2vec | 비언어적 발성 임베딩 연구 | 후속 실험 후보. 한국어 6~18개월 욕구 분류 모델로 간주하지 않음. |

모델의 코드 라이선스, 가중치 라이선스, 학습 데이터 재사용 권한은 각각 확인한다. Donate-a-Cry 등 보호자 추정 라벨을 사실 정답으로 삼지 않는다. 한국어/월령/기기/소음/복수 화자 별 홀드아웃 테스트를 만들기 전에는 원인 추정 기능을 출시하지 않는다.

## 4. 데이터와 프라이버시

`Translation`: `id`, `createdAt`, `ageMonths`, `inputMode`, `observableTag`, `tagSource`(보호자/모델후보), `context`, `candidateText`, `chosenText`, `caregiverEdit`, `responseTried`, `feedback`. 원본 음성·영상 경로는 기본 모델에서 제외한다. 녹음과 카메라 프레임은 처리 후 버린다. 네트워크 계정 없이 로컬에서 작동한다. 권한 철회·기록 개별 삭제·전체 삭제를 제공한다. 로그/분석 SDK에는 얼굴, 음성, 메모를 보내지 않는다.

이 앱은 의료기기나 발달 진단 도구가 아니다. 보호자가 청각, 언어 발달, 통증 등에 우려가 있으면 소아청소년과/전문가에게 상담하도록 명확히 안내한다. Play 정책과 국내 아동 개인정보 관련 요건은 스토어 배포 전 검토한다.

## 5. 출시 전 검증 게이트

### 기능

- Android 8+ 대표 기기에서 첫 실행, 권한 허용/거부/철회, 녹음 종료, 카메라 미검출, 저장/수정/삭제, 앱 재실행 후 기록 지속을 확인한다.
- 비행기 모드에서 주요 기능을 수행한다. 원본의 자동 전송 경로가 없음을 네트워크/코드로 확인한다.
- 화면 읽기, 큰 글씨, 터치 영역 48dp, 가로폭이 좁은 기기를 확인한다.

### 모델 후보

- 실제 아기 음성의 보호자 동의 기반 시험셋을 먼저 확보한다. 최소 단위는 아이 단위 분리이며, 같은 아이의 샘플이 학습/평가에 동시에 들어가지 않는다.
- 울음/웃음/옹알이/성인 말/무음/환경 소음 별 정밀도·재현율, 불확실 처리 비율을 월령·기기·소음별로 보고한다.
- 모델 분류가 불확실하면 결과를 비우고 보호자 선택으로 넘어간다. 감정/욕구 추정 지표는 별도 윤리·전문가 검토 후에만 정의한다.

### 제품

- 보호자 5명 이상이 10초 촬영/녹음→아이 시점 문장 확인→대안 선택/수정→저장을 도움 없이 완료하는지 확인한다.
- 번역 결과를 보고 보호자가 `맞는 것 같다/다른 뜻 같다/모르겠다` 중 하나를 선택하도록 한다. 번역 만족도와 잘못된 확신을 별도로 측정한다.
- 7일 동안 번역 재사용률, 수정 비율, “앱이 아이 마음을 단정한다고 느낀다” 응답을 추적한다.

## 6. 구현 순서

1. Android Compose UI/권한/아이 시점 문장 엔진/결과 수정/로컬 기록 완성.
2. 온디바이스 소리 사건 후보와 얼굴 랜드마크를 번역의 단서로 제한적으로 연결, 실패 시 맥락 기반 문장 생성 유지.
3. 실제 기기 QA와 사용자 테스트.
4. 전문가와 함께 응답 문구·데이터 정책·모델 성능 검토 후 베타 배포.

## 7. 열린 제품 결정

- 첫 고객을 6~18개월 한국 보호자로 둘지 확정.
- 첫 지표를 관찰 기록 지속성, 분류 후보 유용성, 보호자 안심도 중 어디에 둘지 확정.
- 저장 정책 확정: 기록·메모는 온디바이스에만 저장. 외부 DB·자동 동기화는 제외하고 무료 파일 내보내기·가져오기를 후속 개발한다. 현재 버전에는 파일 백업·복원이 없다.

## 9. 구현 계약

```mermaid
flowchart LR
  A[마이크 또는 전면 카메라] --> B[기기 내 관찰 신호]
  B --> C[신호 품질 확인]
  C --> D[보호자 맥락 1탭]
  D --> E[검수된 한국어 문장 후보]
  E --> F[대안 선택 또는 직접 수정]
  F --> G[로컬 번역 기록]
```

화면과 저장소가 주고받는 최소 객체는 `TranslationDraft(inputMode, observedSignal, signalSource, context, ageMonths?, faceVisible?, mouthOpen?, note)`와 `TranslationResult(candidates, selectedText, evidence, feedback)`이다. `signalSource`는 보호자 선택과 모델 후보를 반드시 구분한다. 모델이 검출하지 않은 신호를 `자동 분석`이라고 표기하지 않는다. `faceVisible`이나 `mouthOpen`은 특정 감정/욕구 클래스가 아니다.

후보 선택은 단계적으로 구현한다: (1) 신호 품질이 부족하면 보호자에게 관찰 유형/맥락을 묻는다. (2) 소리 사건 또는 얼굴 움직임을 기록한다. (3) 보호자 맥락이 있을 때만 해당 맥락에 맞는 검수 문장을 제시한다. (4) 근거 및 대안을 항상 함께 제공한다. 자유 생성 모델을 넣을 경우 금지 문구 필터, 개인정보 전송 동의, 품질 평가를 별도 티켓으로 다룬다.

### 개발 티켓과 완료 기준

| 순서 | 티켓 | 완료 기준 |
|---:|---|---|
| 1 | 녹음·권한·품질 | 10초 포착/취소/권한 거부/짧은 입력/백그라운드 종료가 안전하게 처리됨. 원본 자동 보관 없음 |
| 2 | 소리 사건 후보 | 실제 기기 입력이 분류기로 전달됨. 모델 실패 시 보호자 선택으로 복구. 결과 UI가 사건과 의미를 구분 |
| 3 | 카메라 관찰 | 후면 기본·전후면 전환 카메라에서 얼굴 존재·기초 움직임 확인, 미검출 안내, 저장/업로드 없음 |
| 4 | 아이 시점 번역 | 1인칭 문장 1개와 다른 후보 최소 2개, 선택/직접 수정, 근거 표시 |
| 5 | 로컬 기록/삭제 | 결과 보존, 개별 삭제, 전체 삭제, 앱 재실행 후 유지, 데이터 백업 비활성 |
| 6 | 평가 | 월령·기기·소음별 오분류 점검, 보호자 5명 사용성 평가, 부정확 결과 수정률 기록 |

## 10. 콘텐츠 운영 원칙

문구는 `아이 시점의 한마디` → `관찰된 신호` → `보호자에게 확인할 질문` → `다음 반응 한 가지`의 네 층으로 편집한다. “정확한 아기말”, “의학적 상태 판별”, “아이의 생각을 읽었다” 같은 표현은 마케팅과 앱 화면에 사용하지 않는다. 결과는 보호자가 보고 고치는 **가능한 번역**이다. 불안이나 질병을 암시하는 문장은 넣지 않고, 평소와 다른 심한 울음·건강 우려에서는 보호자 확인과 진료 상담 안내를 우선한다.
