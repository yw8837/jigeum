# Gemma Android research runner

Standalone Java Android application, `com.agattok.gemmaprobe`, minSdk26 / target36.
The product application's dependencies, sources, policies and signing are separate.
This is infrastructure for a model candidate whose semantic quality has **failed**.
APK installation or native execution never approves quality, beta deployment, or physical-device performance.

Build with the existing repository Gradle wrapper and
`-p tools/research/gemma_android_probe assembleDebug` (the integration owner runs it).
Set the Android SDK using the environment or an ignored local.properties in this project.
All release tasks explicitly refuse execution, including aggregate tasks that select release tasks.
AGP8.13.2 is pinned. There is no Kotlin compiler/plugin in this independent project;
Java calls the SDK's Kotlin bytecode and the SDK brings its own runtime dependencies.
`verifyPinnedSdk`, required by preBuild, checks the original Maven AAR's version, size and SHA.

- SDK: `com.google.ai.edge.litertlm:litertlm-android:0.17.1`.
- AAR: 20,493,837 bytes, SHA256 `a8aeaa6b128e9b0f1c7fe5e620932a7030cfff1ac9c0dc133d8c79711de5cf4d`.
- Official API reference commit: `5e58e9a0aef7abf7091207a8b1d1063a1c800f08`.
- Model: 2,588,147,712 bytes, SHA256 `181938105e0eefd105961417e8da75903eacda102c4fce9ce90f50b97139a63c`.
- Packaged ABIs: arm64-v8a and x86_64. S25 Ultra ARM evidence remains required.

## Launch and input

An explicit ADB serial must be selected by the parent launcher. Example arguments:

```text
adb -s SERIAL shell am instrument -w
  -e run_id UNIQUE_ID -e mode av -e backend cpu
  -e vision_backend gpu -e context_tokens 8192 -e output_tokens 700
  -e cancel_after_ms 0 -e video_only false -e media_order legacy
  com.agattok.gemmaprobe/com.agattok.gemmaprobe.ProbeInstrumentation
```

The example is one command with continued arguments, not several shell commands.
run_id is mandatory `[a-zA-Z0-9_-]{1,40}`. mode=text|av and backend=cpu|gpu are mandatory.
vision_backend=gpu|cpu defaults gpu. context_tokens accepts only4096/8192/16384 (default4096).
output_tokens is1..700 (default700). cancel_after_ms is0..10000 (default0 disables cancellation).
video_only=true|false defaults false and is allowed only in av mode.
media_order=legacy|recommended defaults legacy. Other values fail validation.

The launcher places the pinned model at app-private `files/model.litertlm` and a UTF8 JSON
at `files/input/bundle.json`:

Only the pinned public model is staged under a random `/data/local/tmp/agattok-public-model-UUID.litertlm`
with ADB's file-transfer protocol, then copied into the checked private destination. The public stage
is removed and its absence checked even on failure. This avoids observed Windows ADB truncation when
`exec-in` inherits a large regular-file stdin. Prepared WAV/PNG/JSON use bounded byte pipes directly
into the private directory; transferred sizes are checked. Native model SHA validation remains mandatory.
No user media or prompt uses shell staging. Failed subprocess output is retained only in a private log.

```json
{"duration_ms":1000,"prompt":"Explicit local prompt","audio":"audio.wav",
 "frames":[{"offset_ms":0,"path":"frame-000.png"}]}
```

duration_ms is an integer1000..20000, prompt is nonempty and at most12000 UTF16 code units.
No private prompt is generated by the Android runner. Audio may be null only when video_only=true;
otherwise its basename must be audio.wav. WAV must contain exactly duration_ms*16 samples
of mono16kHz PCM16, with consistent RIFF/chunks/byte rate/alignment and no extra/truncated PCM.
Frames number1..40 for av (0..40 for text); offsets are strictly increasing integers in
0..duration_ms-1; paths are unique `frame-NNN.png` basenames. PNG signature, full chunk CRCs,
IHDR/IDAT/IEND, decode and dimensions1..512 each are checked. File sizes are bounded.
Input/result child symlinks, traversal and paths outside the context-provided canonical app root fail.
All input validation precedes model hashing and any SDK/native calls.
Both text and av modes validate the entire bundle. Text sends only its explicit prompt;
the host text smoke supplies a synthetic1s WAV and empty frames. No media/model enters Git.

AV ordering is exactly Python `build_contents` ordering:

- legacy: prompt, audio if present, then chronological `[Frame at N ms, image]` pairs.
- recommended: chronological `[image, Frame at N ms]` pairs, prompt, audio if present.

## SDK execution and cancellation

EngineConfig uses the selected text backend, selected vision backend for av, CPU audio for av
with audio, explicit context token limit, max(1,frame_count) images and app cache directory.
SDK Capabilities are read and closed before Engine.initialize. Capabilities include separate
text/vision/audio/video flags; image sequences with captions do not claim native video input.
SamplerConfig is topK1/topP1.0/temperature0/seed17. Empty tools, automatic tool calling=false,
enable_thinking=false, bounded output, no response grammar, null channels and no preface prefill.
ExperimentalFlags enables benchmarks before the engine is initialized.

MessageCallback is used for async native generation. Response text chunks are concatenated in
callback order into a private response file. SDK channel metadata is not treated as answer text,
matching the Python baseline's content-text extraction. Empty answer text fails.
first_token_ms is the elapsed time to the first nonempty **text callback**; it does not measure
individual native tokens. Its label is included. first_callback_ms measures the first onMessage,
onDone or onError callback, including an error/done with no generated text. Terminal callbacks use
the same captured monotonic timestamp for first-callback and terminal timing.
SDK benchmark TTFT/tokens/rates are separate optional measurements and may be unavailable.

After cancel_after_ms a separate thread calls Conversation.cancelProcess while inference is active.
The request time, native cancel-call return time and terminal callback time are separate.
Bytecode inspection of0.17.1 confirms native cancellation error code1 is mapped to
java.util.concurrent.CancellationException. Only that terminal callback after a request produces
status=cancelled. Its terminal timestamp must be at or after the request; the request must be at or
after inference start, and the cancel call must have returned at or after the request. These checks
keep every cancelled timing nonnegative. The cancellation thread rechecks completion before issuing
the request; timestamp validation rejects a terminal callback racing ahead of that request.
A normal completion after a cancel request fails with cancel_not_acknowledged;
cancellation racing with generation is therefore not proof of native cancellation.
Cancellation is for conversation generation only; no supported init-cancel API is assumed.

The integration owner must supervise a wall-clock timeout and force-stop the research package on
timeout/crash. The runner waits for terminal callbacks and joins the cancel thread before closing
conversation and engine. Hanging JNI, fatal native errors and killed processes may produce no
terminal JSON and must be recorded as failed by the parent. No synthetic success file is created.

## Results and privacy

Only after cleanup, the runner atomically renames a new JSON temporary file to
`files/results/ID.json`. Existing IDs are refused. Private generated text, including partial/empty
cancelled output, is stored at sibling `ID-response.txt` and never emitted in instrumentation status.
Response bytes, SHA256 and relative output path are recorded. Exception messages/stack traces
are excluded; error_kind is the exception class or a fixed runner error, with error_stage.
The instrumentation terminal bundle contains run_id and status only.
Native runtime diagnostic logs are external SDK behavior; treat raw process/logcat evidence as
private and never infer that native diagnostic text is sanitized by this Java runner.

Terminal JSON contract:

- run_id; status=completed|cancelled|failed; cleanup_complete; inference_ms; response_bytes.
- cancel_requested; cancel_request_ms; cancel_call_ms; cancel_terminal_ms; optional cancel error class.
- model bytes/hash; input_validation_ms; verify_model_ms (includes hashing separately from loading);
  capabilities_ms; load_ms; conversation_create_ms; cleanup_ms; total_ms.
- mode/backend/vision_backend/audio_backend/context/output limit/duration/frame count/media order.
- device_model/device_api/device_abi/device_total_ram_bytes; thermal_before/after (null beforeAPI29).
- peak/start/end PSS from Debug.MemoryInfo; native PSS and selfRSS sampled every250ms;
  process-lifetime VmHWM; after-cleanup native heap allocated bytes. Samples include validation/hash
  and cleanup. These are sampled process metrics, not exact inference peaks or GPU allocations.
- quality_validated=false; semantic_validation=not_performed; is_physical_device_verified=false.
  Parent records physical-device evidence independently; model identity is not a hardware allowlist.

Completed requires nonempty text, no cancellation/error, and successful cleanup. Cancelled requires
a requested cancellation and the SDK cancellation terminal callback plus successful cleanup.
Parent must independently check run ID, terminal status, cleanup, response size/hash and process
termination. JSON schema/semantic content is not evaluated by this runner.

No INTERNET, CAMERA or microphone permission is declared. Backup and device transfer explicitly
exclude all storage domains, and allowBackup=false. There is no upload endpoint, account, app UI,
product record migration or persistent purchase entitlement. Optional GPU native-library declarations
do not require GPU support or establish GPU compatibility. This instrumentation-only APK does not
measure product UI/capture/save responsiveness, contention, repeated-run recovery or battery drain.
