# Play 비공개 테스트 진행 상태 — 0.5.6/code20

확인일: 2026-10-02. 계정 Yeolmae, 앱 **아가톡 - 지금 내 기분이 그래**, 패키지 `com.moa.babylanguage`.

## 현재 결론

**정식 AAB 업로드, 공개 전화 인증·저장, 한국 개발자 추가 정보 저장, Alpha의 14개 변경사항 검토 제출과 게시까지 완료됐다. 현재 비공개 Alpha는 ‘활성’이고 최신 출시는0.5.6 (20)이다. 테스터 참여 링크도 활성화됐으며 등록된 운영자 계정에서 실제 ‘Become a tester’ 안내가 열리는 것을 확인했다.** 현재 허용 목록은1명이며 외부 테스터 명단은 아직 없다. 12명·14일은 충족되지 않았다.

## 완료한 작업

- 한국어 기본 등록정보의 앱명·설명·아이콘·그래픽·실제 release 스크린샷 4장을 최종 저장했다.
- 비공개 Alpha의 대상 국가는 대한민국으로 지정했다. 프로덕션과 동기화하지 않았다.
- `아가톡 비공개 테스트` 이메일 목록을 만들고 운영자 계정 하나만 넣었다. 목록에 있는 1명은 참여 완료 수가 아니다. 외부 테스터 명단은 아직 없다.
- 의견 수신 주소는 기존 공개 지원 이메일로 저장했다.
- 최신 `outputs/Agattok-0.5.6-release-code20.aab`를 업로드했다. SHA256 `586a2bd08b97093da0bc65efdf1245d0de69d5aac994d4d17e465e4c6333af42`.
- Console이 **20 (0.5.6), 최소 API26, target36**으로 인식했다. 이전code18은 새 출시에서 제외했다.
- 출시명 **`0.5.6 (20) - 앨범 저장 테스트`**, 한국어 출시 노트를 저장하고 ‘변경사항이 저장되었습니다’ 모달을 확인했다. 전체 기능 sideload preview는 업로드하지 않았다.
- 게시 개요에release20 Alpha 출시·국가·테스터·스토어·기존 선언 등 **14개 변경사항**이 표시됐다. [업로드·저장 증거](play-release20-saved.jpg). 관리형 게시가 꺼져 있으므로 승인 후 해당 비공개 트랙에 게시되는 구성이다. Console의 ‘전체 출시 시작’은 Alpha의 표시이며 공개 프로덕션 출시를 뜻하지 않는다.
- 한국 개발자 추가 정보 저장 후 차단 안내가 사라지고 ‘이제 검토를 위해 변경사항을 전송할 수 있습니다’와 활성 제출 버튼을 확인했다. 승인된 14개 변경사항의 전송 버튼과 최종 확인을 완료했다. 이어서 자동 검사 진행 상태가 끝나고 **‘변경사항을 검토 중입니다’**가 표시됐으며, Alpha 출시 화면에서도 **0.5.6 (20) 검토 중**을 확인했다. [제출 완료 증거](play-release20-review-submitted.jpg).
- 이후 게시 개요를 새로고침해 **최근 게시일2026-10-02**와 ‘앱 업데이트가 게시되었습니다’ 알림을 확인했다. Alpha 테스터 탭은 **활성 / 최신 출시0.5.6 (20) - 앨범 저장 테스트**로 바뀌고 Android·웹 참여 링크 복사 버튼이 활성화됐다. [활성 트랙과 목록1명](play-release20-alpha-active.png) / [참여 링크](play-release20-opt-in-links.png).
- 실제 웹 참여 URL을 열어 등록된 운영자 Google 계정에서 앱명·Yeolmae 초대 안내·**‘Become a tester’ 버튼**을 확인했다. 에이전트가 참여 버튼을 누르거나 설치하지는 않았다. [실제 참여 안내](play-release20-opt-in-ready.png).
- Console 경고2개(가독화 파일 없음, native debug symbols 없음)는 남아 있다. 현재 minifyfalse이므로 첫 경고의 가독화 파일은 생성하지 않는다. 이 경고를 제출 차단이나 Google 심사 승인으로 해석하지 않는다.

## 해결한 제출 차단과 공식 안내 정정

release20 저장 직후에는 **‘문제1개가 모든 변경사항에 영향을 미칩니다’**와 **계정 세부정보 업데이트 — 한국 개발자 추가 정보**가 표시됐고 전송 버튼이 비활성이었다([당시 차단 화면](play-release20-blocker.jpg)). 이는 아래 보완 후 해결한 과거 상태다. 이전code18 때의4/5·참여0명 표시를 새 버전의 최신 실측으로 재사용하지 않는다.

현재 계정은 **개인**이다. 결제 인증 통과 보고 직후에는 공개 전화가 빈칸이었다([당시 화면](play-release20-status-recheck.jpg)). 이후 사용자가 기존 번호의 공개 등록·문자 요청을 명시적으로 승인했고, 국제 형식의 국내 번호 앞 `0`을 제거해 형식 오류를 해결했다. 문자 전송 안내 후 사용자가 직접 코드 인증과 저장을 완료했다. **공개 전화 항목의 ‘전화번호 확인됨’과 ‘변경사항이 저장되었습니다’를 실제 확인했다.** 전화값과 OTP는 증거 이미지/Git에 넣지 않는다.

전화 저장 후에도 동일한 한국 개발자 추가 정보 차단이 남았었다([당시 화면](play-release20-after-phone.jpg)). Console이 연결한 [Google 공식 안내](https://support.google.com/googleplay/android-developer/answer/6223646#Korea)의 **2023-08-31 이후 생성 계정** 설명을 펼쳐 읽었다. 한국의 유료 앱/인앱 결제 앱 개발자에게 사업자등록번호·통신판매업 신고번호·신고기관을 요구하며, 개인 계정도 공개 전화 인증 외의 판매 관련 요건에서 자동 면제된다고 쓰여 있지 않다. 이전 문서에서 이 요건을 ‘업체’로만 한정했던 설명은 정정한다. 현재 앱은 인앱 이용권 기능을 포함한다. 실제 차단 팝업은 통합 항목명만 보여 주므로 세 필드 중 단 하나가 원인이라고 단정하지 않는다.

사용자는 기존 사업자등록증과 통신판매 신고 정보의 Google Play 등록·공개를 승인했다. 기존 사업자등록증에서 사업자번호를 확인했고, 이후 사용자가 제공한 통신판매 신고 화면의 사업자번호·대표자와 일치함을 확인했다. 화면에 표시된 신고번호·신고기관을 입력하고 **추가 정보 전체 저장 완료 안내를 실제 확인했다.** 기관 전화번호를 기관명에 추가하거나 번호를 추정하지 않았다. 이전 빈 기관 필드의 오류 화면은 [과거 보완 근거](play-korea-licence-required.jpg)로 남긴다. 저장 후 게시 개요를 새로고침하니 차단이 해제돼 검토 제출을 마칠 수 있었다.

전화 인증의 입력값·OTP·비공개 전화번호·사업자번호·통신판매 신고번호·원본 증명서/제공 화면은 이 문서/Git/증거 이미지에 넣지 않는다. 현재는 실제 웹 참여 안내를 브라우저에 열어 두었다.

## 참여 링크

Console이 표시한 주소: <https://play.google.com/apps/testing/com.moa.babylanguage>

**현재 Alpha 테스터 탭의 Android·웹 참여 링크 복사 버튼이 활성화됐으며 실제 웹 참여 안내까지 확인했다.** 선택된 이메일 목록 `아가톡 비공개 테스트`의 사용자 수는 **1명**이다. 링크만 전달받은 미등록 계정은 참여할 수 없으므로 모집한 Google 계정을 먼저 이 목록에 추가해야 한다. 직전 게시 전 대시보드의 참여 선택 실측은0명이었고, 이번 확인에서는 현재 참여 수를 다시 측정하지 않았다. 등록된 운영자 계정에서도 ‘Become a tester’ 상태여서 해당 계정의 참여 완료로 계산하지 않는다. [활성 링크 화면](play-release20-opt-in-links.png) / [실제 참여 안내](play-release20-opt-in-ready.png). 이전의 [게시 전 링크 대기 화면](play-release20-tester-link-pending.jpg)은 과거 증거로 보존한다.

이제 외부 테스터 모집·목록 추가 → 각 계정의 참여·Play 설치 → 최소12명·연속14일 요건 확인 순서다. 참여/설치 및 기간 충족을 링크 활성화만으로 대신할 수 없고 프로덕션 액세스 신청·공개 출시는 별도다.

## 경고와 한계

- 출시 미리보기는 오류 없이 경고 2개: 가독화 파일 없음, 네이티브 디버그 기호 없음. 현재 `build.gradle.kts`의 release는 `isMinifyEnabled = false`다. 네이티브 기호 미제공은 관련 충돌/ANR 원인 분석의 한계로 남는다. [Console 경고 화면](play-validation-warnings.jpg).
- 현 검토본은 무료60초 촬영/10초 분석, 전체120초 촬영/20초 분석이다. **유료20초/30초는 사용자 최종 결정 전**이다. 현재 검증본으로 비공개 테스트를 준비하며 최종 상용 정책 확정으로 해석하지 않는다.
- 상품 미등록으로 Play 이용권 구매는 불가능하다. release의 실제 권한 검사를 유지한다. 전체 기능 개인 테스트는 다운로드 폴더의 sideload preview로 제공한다.
- 최신 QA는 로컬 계측246통과/0실패/1명시제외다. 서명 UI의 결과 저장 앞부분과 이후 기록 중심 통과를 함께 보존했다. [보고서](../../qa/gallery-0.5.6/README.md). 이번 업로드가 실기기·아기 의도 정확도·실제 구매 검증을 대신하지 않는다.
- 게시 개요 알림 센터에서 ‘결제 계정에 주의가 필요한 긴급한 문제가 있습니다’ 알림도 새로 확인했다. 이 확인에서는 지급/결제 설정의 원인을 조사하거나 금융 정보를 변경하지 않았다. Alpha 활성과 실제 참여 페이지는 별도로 확인됐으며 상품·실제 거래는 기존 보류 범위다. 수익화 전에는 이 알림의 원인을 실제 지급 설정에서 확인한다.

## 다음 실행

1. 사용자가 제공하는 외부 테스터 Google 계정을 기존 이메일 목록에 추가한다. 현재 허용 목록1명을12명 충족으로 보고하지 않는다. 이미 게시한release20을 취소하거나 같은 버전으로 재업로드하지 않는다.
2. 등록한 테스터에게 위 참여 링크를 전달하고 각 계정의 참여 선택·Play 설치를 확인한다. 에이전트가 이를 대신한 것으로 보고하지 않는다.
3. Console의 최소12명·연속14일 조건과 실제 참여 수를 확인한다. 조건 충족 후 프로덕션 액세스 신청은 별도 단계다.
4. 상품/실제 거래 보류를 해제하기 전에 지급 계정 알림 원인과 실제 Play 거래 경로를 검증한다.
