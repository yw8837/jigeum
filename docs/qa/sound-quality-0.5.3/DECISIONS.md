# 판정 변경 가설과 동결 기준

## baseline

`probe.py baseline` 실제 YAMNet→EvidenceInterpreter 실패(앱 코드 0.5.2 그대로):

- 기존 웃음47370: 첫 프레임 infant laughter .668/general laughter .984, 다음 프레임 generic crying .332. 전체 peak 혼합 때문에 출력 보류.
- 기존 울음211528: 울음 대사 정상.
- 신규139046: 배포자 제목은 Babbling Happy2, 모델은 마지막 프레임 baby laughter .5/general laughter .8. 옹알이 대사 미출력. 제목은 독립 청취 정답이 아니지만 과제 불일치로 남긴다.
- 15초는16개 결과,2.48초는3개 결과. 공식 Keras의0.48초 hop을 이 MediaPipe 호출에 가정하지 않는다.

## 반증 가능한 가설 순위

1. 전체 최고점의 혼합 때문에 시간별로 분리된 약한 경쟁 소리가 전 구간을 막는다. 같은 창에서의 상대 우세를 보면 기존 웃음 보류가 해소되어야 한다.
2. 울음 선택에만 반대 웃음 검사가 빠진 비대칭이 반대 대사를 허용한다. 대칭 검사 후 혼합 점수 회귀는 울음 단독을 반환하면 안 된다.
3. 짧은 한 번의 infant 오검출이 전체 문장을 결정한다. 지속된 두 창 또는 강한 한 창을 요구하면 비아기 음성의 오출력이 줄어야 한다(독립 음원으로 확인).
4. 모델 자체가 옹알이/웃음 경계를 잘 못 구분한다. 집계 수정만으로139046이 옹알이가 되지 않으면 해결했다고 보고하지 않는다.

## 추가 음원 실행 전 정한 정책

YAMNet 재학습/클립별 하드코딩 없음. 수치는 측정된 확률이 아닌 보수적 제품 규칙이다.

- 아기 후보 최소 .35 유지. 같은 창에서 아기 소리와 일반 parent 클래스 지지는 합산하지 않고 max.
- 서로 다른 사건의 점수가 .30 이상이며 약한 쪽이 강한 쪽의60% 이상이면 그 창은 충돌. 웃음/울음 양방향 동일.
- 비명은 기쁨에도 가능하므로 울음으로 승격하지 않는다. 강한 비명이 선택 사건보다 우세하면 해석을 보류.
- 판정 가능한 창2개 이상 또는 infant .60 이상+사건 .70 이상의 강한 단일 창이 필요.1초짜리 입력도 강한 단서일 때 지원.
- 서로 다른 사건이 지속되어 잡히면 중립적인 혼합 대사. 울음이 포함되면 놀이 권유 없음. 시간 순서는 창 시작 시각을 보존해 근거에 표시.
- 동시 충돌이 우세하면 특정 감정 대사 대신 구간을 좁히도록 안내. 부모/얼굴만으로 신원·배고픔·졸림을 만들지 않는다.
- 음원 미식별·옹알이 실패는 별도 기록. 보류를 정답으로 치환하지 않는다.

추가 확인용 음원(575331/58308/410741/324783/50762/505990/33658)은 이 정책 작성 시 아직 실행하지 않았다. 각 첫15초 이하. 최초 실행 결과와 후속 변경이 생기면 구분해 기록한다.

## 최초 추가 확인 후 두 번째 수정

첫 실행에서410741 울음 파일의12~13번째 창을 모델이 아기 웃음으로 분류했고,471061의7개월 발성을 Child speech로만 잡았다. 따라서 다음 수정은 **해당 최초 holdout을 본 뒤의 개발 변경**이다. 이후 동일 파일의 결과를 독립 holdout 성능으로 부르지 않는다.

- 혼합 대사에서 `응애… 헤헤`를 제거했다. 모델의 혼합 후보를 실제 발성 전사처럼 반복하지 않고 감정 중립적인 곁에 있기/들어주기 대사만 낸다. 후보 순서는 근거에만 표시한다.
- 정확한 `Child speech, kid speaking` 클래스가 .35 이상인 창3개에서 유지될 때 어린 말소리의 중립 문장을 허용한다. 일반 Speech만으로는 허용하지 않는다. 어린이 클래스는 아기의 신원·연령 인증이 아니다. 초기 두 소리 사건만의 contract에서 범위를 확장했으므로 별도 회귀와 대화 음성 대조군을 검사한다.
- 강한 반대 일반 웃음/울음이 다른 창에 나타났는데 아기 신원이 불명확해도 단일 사건 대사로 지워 버리지 않는다.
- 사용자의 추가 요청으로 DC 제거+80Hz2차 Butterworth high-pass를 분석 PCM에만 적용한다. 노이즈 게이트·자동 볼륨 증폭·화자 분리는 추가하지 않는다. 원음 재생·선택 시간은 그대로다. 필터 전후 실음원 사건 출력과40Hz/DC 합성 교란,250~4000Hz의 작은 신호 보존을 비교한다.

QA 전처리 정정: FFmpeg float 디코드는 압축 overshoot로[-1,1] 밖 값이 있었고, 실제 Android decoder는 clamp한다. 이후 corpus도 같은 clamp로 맞췄다. 울음211528의 baseline unclamped PCM과 이후 PCM은 바이트가 다르며, 이를 동일 파형 성능 개선으로 비교하지 않는다. 웃음47370은 clamp 표본0개로 baseline과 동일하다.
