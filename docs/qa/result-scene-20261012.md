# 결과 장면·저장 날짜·뒤로가기 수정 — 로컬 검증 통과 / Alpha39 검토 요청 완료

**2026-10-13 00:05 KST:** 게시 개요 수동 재확인에서도 정확39는 검토 중이다.
[현재 화면 근거](result-scene-20261012/delivery/play-review-20261013.png). 별도 게시 버튼·반려/오류 없음.
이후 인식 진단 도구 작업은 과거 계측 재집계이며 이 배포 패키지의 모델/인식 변경을 뜻하지 않는다.

## 범위와 재현

- 사용자가 Play38의 갤러리 입력 결과에서 장면이 안 보이고 저장 뒤 페이지를 벗어난다고 보고했다. 프로세스 충돌은 아니라고 정정했다.
- 실제 폰 로그에서 플랫폼 `MediaMetadataRetriever.getScaledFrameAtTime`이 null을 반환했다. 기존 UI는 예외를 삼키고 문장만 표시했다.
- 조사한 원본의 장면 기록은 만들어졌고, 기록에서 앨범 MP4 내보내기도 성공 안내를 확인했다. 해당 경로를 저장/코덱 실패로 기록하지 않는다.
- 수정 연구앱에서 사용자는 장면 표시가 정상이라고 답했다. 후속 요청은 새 저장본의 날짜와 결과/구간 선택 사이 뒤로가기 반복 두 가지다. 인식률 개선은 이번 범위에 추가하지 않았다.
- 폰의 앱 소유 새 앨범 행에서 `date_added`와 `datetaken`의 큰 차이를 확인했다. 원본 영상·기록·촬영 날짜는 외부나 Git에 남기지 않았다.

## 변경

- 결과 포스터는 같은 버전 Media3 FrameExtractor의 SDR 프레임을 사용한다. 추출 실패/재시도 상태를 보이며 게시한 bitmap은 Compose가 참조하는 동안 강제로 recycle하지 않는다.
- 장면/문장 기록 저장 성공 뒤 결과 화면을 유지하고 저장 위치와 완료 상태, 저장한 장면 열기를 표시한다.
- 새로운 자막/무자막 MP4의 생성·수정 timestamp를 저장 시점으로 기록한다. 같은 기본 InAppMp4Muxer의 metadata provider를 사용하며 원본에는 쓰지 않는다.
- 새 앨범 행의 DATE_TAKEN도 저장 시점으로 설정한다. 과거에 이미 저장한 앨범 항목을 일괄 수정하지 않는다.
- 결과의 시스템 뒤로가기와 상단 닫기는 종료 확인으로 이어진다. 명시적인 다른 구간 분석→결과로 돌아가기 이후에도 닫을 수 있다.
- 실폰 회귀 검사에서 선택 구간을 두 번째 재생할 때 새 Surface가 디코더를 0초로 되돌리는 문제도 재현했다. Surface 연결 뒤 선택 구간으로 seek하고 완료 콜백에서 재생한다.
- 모델·인식 임계값·분석 구간·구매 정책 변경 없음.
