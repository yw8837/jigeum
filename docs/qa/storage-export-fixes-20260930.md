## Changes

- Timestamp collision no longer treats another same-day observation with identical content as proof of duplication. Each relocated source receives a SHA-256 identity over its original timestamp plus length-framed UTF-8 fields. The existing SQLite `meta` table records that identity and destination ID in the same transaction as import.
- Preview uses snapshot provenance; committing an old preview re-reads current provenance and records inside the transaction. Deleted destination rows lose associated provenance; deleting all records clears all import provenance. No schema version or exported JSON version changes.
- Existing installations without provenance are safe to open. A previously relocated pre-fix import cannot be conclusively identified: reimporting its old source can create one additional preserved copy. The fix prefers preserving an ambiguous memory over silently discarding a distinct one. Local provenance is not transmitted in JSON/CSV; reimport idempotence across a fresh install cannot reconstruct old collision origins from format v1.
- PNG/PDF work captures an export generation before dispatch. Deletion invalidates synchronously, and rendering checks before and after work. Chooser launch checks generation/file existence and is serialized against cache clearing. This covers deletion before chooser launch. A chooser launched before a later deletion can still lose its cache file before the receiving app reads it; receiver/handoff lifecycle tracking is not implemented. Already-shared third-party copies cannot be recalled. PDF entitlement expiry alone does not invalidate work that began with access.
- Required callers: capture `currentGeneration()` before launching PNG/PDF coroutine; pass it to generation and `share`; call `invalidatePendingExports()` before starting deletion; reject new PNG starts while root mutation is busy. These MainActivity/LibraryScreens edits are owned by the access-policy change.

## Billing risks intentionally left separate

1. **High before paid rollout: lost purchase callback.** Start fake Play purchase returning OK; do not send `onPurchasesUpdated`; call `refresh()` and `restore()`. Both skip purchase queries while PURCHASING, so explicit recovery remains blocked. Existing cancellation test supplies USER_CANCELED and does not cover this failure. A bounded lifecycle recovery design and real manager tests are needed.
2. **Medium UI reliability / high operational acknowledgement dependency:** an immediate failed acknowledge callback writes a delay message, then `verifyPurchases` writes final PREMIUM state with `message=null`. Reproduction: configure FakePlay.acknowledge to invoke callback with SERVICE_UNAVAILABLE synchronously, complete signed verification, inspect final message. Asynchronous failure may retain the message; either way acknowledgment remains client-only and retried only upon later verification. No retry/server behavior was changed.
3. **Interim tester scope:** leave actual billing configuration disabled until lifecycle and operational setup are verified. Controlled instrumented entitlement doubles are separate from real purchase verification; never ship a hidden premium bypass. This scope does not assert readiness for a paid pilot.
