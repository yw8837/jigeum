사용자는 작업에 꼭 필요한 것 외에 사용이 끝난 생성물을 전부 정리하도록 다시 요청했다.
진행 중인 서명 QA와 최신/직전 배포본, 원본·제품 모델·키·검증 근거는 보존한다.

- 기존 `tools/cleanup_research_artifacts.ps1`의 preview를 통과한 종료 APK/AAB **31개**를 삭제했다.

  다른 작업의 이후 공간 변화까지 삭제 효과로 더하지 않는다.
- 최신 후보38과 직전 게시37의 final 최상위 파일을 전후 SHA256·크기로 대조해 보존했다.
- Git 추적 부재, 절대경로 경계, 재분석 지점 부재, 역사적0.2.1/0.3.0 보호 조건을 검사했다.
- 출처·해시·QA 결과는 그대로이며 과거 패키지의 당시 해시를 새 재빌드 해시로 간주하지 않는다.

작은 결과 사본: [cleanup-packages.json](vocal-kind-20261010/cleanup-packages.json).

## 자동 정책으로 남은 범위

새 일괄 정리 스크립트를 생성하고 preview하려던 명령은 자동 승인 정책이 실행 자체를 거부했다.
그후 기존 정리 도구가 허용하는 위31개 범위로 줄여 실제 정리를 마쳤다.

원래 체크아웃의 **구버전 APK/AAB80개 / 약4.599GiB**는 별도 더 좁은 명령도 자동 정책이 거부했다.
그 명령은 실행되지 않았고 대상80개가 모두 남아 있음을 재확인했다.
사용자의 삭제 요청이 없는 것이 아니라 실행 환경의 정책 차단이며, 반환된 상세 이유는
`blocked by policy`뿐이다. 다른 수단으로 같은 삭제를 우회하지 않는다.
계획: ignored `cleanup-primary-apk-only-plan.json`. QA 근거 ZIP 및0.2.1/0.3.0 기준본은 이 계획에서도 제외했다.

이전 세 build 삭제 차단(app/build·recovery-build·interval build)은 원래 기록을 유지한다.
진행 중인 현재 서명 QA가 끝나기 전 필요한 빌드·기기는 제거하지 않는다.
전체 불필요 생성물 정리가 끝났다고 보고하지 않는다.

추가로 제품에 미탑재·실험이 끝난 TalkNet 가중치 두 파일의 SHA256/크기를 확인했다.
`work/talknet-checkpoint-audit/pretrain_TalkSet.model`(63,227,827B),
`work/talknet-face/sfd_face.pth`(89,844,381B), 합계153,072,208B/약146MiB다.
이 두 파일만 지우는 별도 명령도 실행 전 자동 정책이 `blocked by policy`로 거부했다.
계획은 ignored `work/vocal-kind-20261010/retired-talknet-weights-plan.json`에 남기며
다른 도구로 같은 삭제를 재시도하지 않는다. 코드·관찰·출처·실험 로그는 삭제 대상이 아니다.

## 다음 작업에서 유지할 정리 기준

- 현재/직전 최종 배포 패키지, 실제 제품 모델, 재현에 필요한 작은 입력·원천 기록은 유지한다.
- 실험 종료 뒤 중복 APK/AAB·다운로드한 미채택 가중치·임시 기기 미디어를 정리 대상으로 표시한다.
- 과거0.2.1/0.3.0 기준본·사용자 원본·키·개인 기록은 보존한다.
- 로그·측정표·소스가 남아 있어도 삭제한 바이너리를 현재 로컬에서 재검증했다고 보고하지 않는다.
- 현재 필요한 파일은 경로와 이유를 남기고, 실험이 끝났을 때 다시 분류한다.
- 자동 정책 차단은 사용자 동의 부족과 구분하고 같은 대상을 다른 삭제 방법으로 우회하지 않는다.

작업 중 Windows 가상메모리 파일은 약46.45GiB로 관찰됐다. 운영체제 관리 파일이므로
앱 생성물 정리에 포함하지 않았다. 당시 여유 RAM은 약0.47GiB였으며, 이 관찰만으로
서명38의 최초45초 timeout 원인을 확정하지 않는다. 드라이브 여유공간의 전체 변화를
우리 삭제 효과로 환산하지 않는다.
