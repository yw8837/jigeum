# Gemma 탑재 전 성능 준비 상태

2026-10-04. 소스 `4012d42` 기준 실행 경로 검토에 같은 날 S25 연구 실행 결과를 보완했다.
실측 원문은 [S25 QA](S25-GEMMA-20261004.md)다. 제품 Gemma 통합 완료 보고가 아니다.

## 사용자 요구

Gemma 4 E2B를 온디바이스에 탑재하더라도 촬영·저장·화면 조작이 멈추거나 실사용이 어려워져서는 안 된다. 약2.59GB 다운로드를 수용한 결정은 실행 RAM·대기 시간·발열을 수용하거나 검증했다는 뜻이 아니다. 원본·음성·프레임·프롬프트 외부 AI 전송 및 클라우드 대체는 금지한다.

사용자 기기는 **Galaxy S25 Ultra**다. 다른 테스터 기종은 모른다고 했으며 **기종별 사용 제한을 두지 말라**고 추가 요구했다. 기종명 허용 목록을 만들거나 고급기 한 대 통과로 지원 범위 전체를 승인하지 않는다. S25 Ultra는 첫 시험 대상이며 최소 사양 기준으로 확정하지 않는다. 제조사/기종에 따른 기능 잠금 없이 기존 지원 범위에서 핵심 분석을 제공하려는 목표다. 모든 하드웨어의 동일 속도·실행 성공을 이미 보장한 것으로 해석하지 않는다.

## 현재 소스와 실제 증거

| 항목 | 확인한 구현/증거 | 확인하지 못한 범위 |
|---|---|---|
| 분석 대기 제한 | `CaptureFlow.kt`의 `analyzeSelected()`가 `withTimeout(45_000)` 사용. 취소/시간초과 안내와 generation 번호로 늦은 결과 표시 차단 | Gemma native 연산의 즉시 중지·메모리 반환 |
| UI 실행 분리 | `DeviceClipAnalyzer.analyze()`가 `Dispatchers.Default` 사용. UI 직접 실행을 피함 | 큰 native 연산이 CPU/GPU/메모리를 점유할 때 실제 UI 지연 |
| 현재 소리 모델 | `SoundAnalyzer`의 Mutex, 취소 전파 | 새 Gemma 세션과의 동시 점유·반복 로드 |
| 현재 영상 디코더 | 순차 디코딩, 구간 내2fps 표본,15초 진행 없음 제한, 취소 검사 및 bitmap/codec 해제 | Gemma에 다중 이미지 전달 후 복사·인코더·KV 메모리 |
| 기존 취소 회귀 | `CaptureAccessLimitsTest`, `VideoAudioTest`, `VideoTimelineTest`의 늦은 결과/디코더 재사용 검사 및 이전 QA 실행 근거 | Gemma runtime을 사용한 취소와 다음 분석 복구 |
| Gemma 호스트 실행 | 실제 AV10초 단회 추론94.951–95.587초. 일부 GPU 경로는 메모리 오류. [기존 실측](../../research/20261003-ondevice-av-probe.md) | Android ARM 속도, p95, peak RAM, 발열, 배터리 |

PC 실행 시간을 Android에 그대로 적용하지 않는다. 동시에 기존45초 제한에 새 모델을 그대로 연결하고 성능 검증 완료로 볼 수도 없다. timeout 시간을 늘리는 것은 속도 개선이 아니다. 일반 coroutine 취소만으로 동기 native 추론이 즉시 중지된다고 가정하지 않는다.

## 탑재 후보가 품질을 통과한 뒤 필요한 실제 시험

1. 사용자 기종/OS/RAM과 지원할 최저 기기를 고정한다. ARM 실기기를 쓰고 첫 로드·캐시 준비 후 반복 분석을 구분한다.
2. 선택10초/20초 각각 디코딩·미디어 인코딩·첫 토큰·완료 시간을 따로 기록한다. 기존 설계의30초/60초 p95는 잠정 목표이며 현45초 UI 제한과 충돌한다. 실측 전에 이것을 충족했다고 표시하거나 시간 제한만 늘려 통과시키지 않는다.
3. 연속 실행의 최고 메모리와 유휴 복귀 후 메모리를 측정하고, 분석 중 화면 조작·뒤로가기·취소 반응을 측정한다. native 취소 완료 전 다음 분석이 겹치지 않는지 확인한다.
4. 촬영·저장 도중 모델 로드가 경합하지 않는지, 백그라운드 이동·앱 재생성·기기 저메모리에서 기존 미디어가 보존되는지 검증한다.
5. 취소·시간초과·메모리 부족 뒤 정상 입력 재분석, 모델 손상/불완전 설치/저장공간 부족을 검사한다. 실행 불가를 성공 결과로 표시하지 않는다.
6. 모델 설치 후 네트워크 차단 상태로 실제 분석·생성·저장한다. 모델 다운로드와 구매 검증 통신은 아기 자료 전송과 구분한다.

## 현재 판단

Gemma는 배포 후보에 포함되어 있지 않다. 별도 연구 APK로 S25에서 실제 추론했지만 품질·성능 양쪽이 미통과다.
GPU AV10초14.82초/AV20초30.93초 추론, runner 전체32.79초/43.29초,
20초 뒤 thermal3, 취소 terminal6.63초 지연을 확인했다. 이 시간에 앱 MP4 디코딩은 포함하지 않는다.
단회/순차 실행이므로 p95·다른 기기·배터리 영향으로 일반화하지 않는다.
현재 코드24의 서명/보존/동작 QA를 Gemma에 재사용하지 않는다.

공식 LiteRT-LM 고정commit `5e58e9a0aef7abf7091207a8b1d1063a1c800f08`의 [Kotlin 안내](https://github.com/google-ai-edge/LiteRT-LM/blob/5e58e9a0aef7abf7091207a8b1d1063a1c800f08/docs/api/kotlin/getting_started.md)를 읽어 CPU/GPU backend와 GPU용 선택적 native-library 선언을 확인했다.
후속 실제0.17.1 AAR 검사에서 minSdk24, arm64-v8a/x86_64만 확인했다.
기존 beta24 APK는 armeabi-v7a/x86도 포함하므로 SDK를 그대로 전면 대체하면 기존32비트 지원을 잃는다.
현재 제품 앱의 `minSdk=26`·ABI·의존성을 변경하지 않았다. 기종명을 제한하지 않고 지원 범위를 유지하려는 요구는 아직 미해결이다.
