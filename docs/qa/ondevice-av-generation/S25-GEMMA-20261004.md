# UltraQA Report — S25 Ultra Gemma 후보 실측

2026-10-04 · 연구 패키지 `com.agattok.gemmaprobe` · 제품 앱/Play 배포와 별도.

## 목표·시험 범위

사용자가 연결하고 USB 디버깅을 허용한 Galaxy S25 Ultra(SM-S938N, Android API36,
arm64-v8a, 총 RAM 약10.85GiB)에서 고정 Gemma4 E2B의 실제 실행·취소·자원 사용을 확인한다.
기존 아가톡 `com.moa.babylanguage` code23/0.5.9-beta는 업데이트·삭제·데이터 변경하지 않는다.
기종명 허용 목록은 추가하지 않는다. 사용자 원본은 이번 시험에서 사용하지 않았다.

인터넷·카메라·마이크 권한이 없는 별도 debug APK, 공개 모델, 합성 tone/색상 입력만 사용했다.
AV10초는10장, AV20초는20장의 시간순 이미지와 같은 구간의16kHz mono PCM16 WAV다.
이는 native video 모델이나 앱의 촬영/화면 반응성 시험이 아니다. SDK의 capabilities는
text/vision/audio=true, video=false다. 후보의 관찰 품질은 여전히 미통과다.

멈춤 기준은 실행별90–240초 timeout과 연구 프로세스 종료 확인, thermal 상태 악화 시 연속 추론 중단이다.
20초 실행 뒤 thermal3(SEVERE)를 관찰하여 추론을 멈췄고, 입력 실패 시험을 하는 동안1(LIGHT)로 내려온 것을 확인한 뒤 취소 시험을 진행했다.

runner 전체에는 입력 검증·모델 해시·capabilities·초기화·미디어 구성·해제가 포함되며,
호스트의 APK 설치/전송 시간은 제외한다. 실제 앱의 MP4 디코딩/결과 표시 시간도 포함하지 않는다.

첫 콜백은 개별 첫 토큰 측정이 아니다. 초기화 밖의 지연 준비 작업도 있어0.45초를 전체 모델 준비 시간으로 읽지 않는다.
PSS는250ms 간격 Debug.MemoryInfo 표본으로, 정확한 전체 RAM/GPU 최고점이나 다른 앱 영향을 의미하지 않는다.
CPU AV10의 표본 RSS는3.92GiB, GPU AV10은1.27GiB였으며 PSS와 같은 지표가 아니다.
전원·주변온도·다른 앱·열 누적을 통제한 벤치마크가 아니며 p95·전 기종 성능으로 일반화하지 않는다.

## 취소

GPU AV10에서 추론 시작1,000.47ms에 cancel 요청, API 호출은0.19ms에 반환했다.
그러나 CancellationException terminal까지 **요청 이후6,629.91ms**가 걸렸다.
native 종료 확인 후 cleanup은670.85ms, 이후 PSS 표본은294MiB였다.
호스트가 force-stop 후 PID 부재를 확인했다. API가 반환했다는 것만으로 연산 즉시 중지라고 보고하지 않는다.
제품 UI의 취소·같은 프로세스/엔진 재사용 검증은 별도다.

취소 뒤 **새 프로세스·새 엔진**의 동일 AV10 입력을 다시 실행해14.72초 추론 완료·native해제·PID부재를 확인했다.
이것은 같은 세션의 취소/재사용 성공이 아니다. 재실행의 의미 출력도 이전 GPU10과 동일하게 실패했다.

## 관찰 품질

- CPU와 GPU의10초 응답 모두 색상 변화를 음성 요약에 섞고 audible sound 없음이라고 기술했다.
  실제 합성 WAV는 RMS2893.04(PCM16),16kHz·160000 samples였고 기기에 전달된 WAV SHA가 호스트와 일치했다.
- GPU20초는 tone을 언급했지만 실제 시각 순서를 여러 차례 반복된 red/blue로 잘못 기술했고 JSON이 깨졌다.
  GPU10도 timestamp 오기·trailing comma가 있었다. nonempty 응답 완료는 구조/의미 통과가 아니다.
- 추가 Astra/high 읽기 전용 검토: Java AudioFile→AAR JSON content→JNI→native audio 전처리 규약에
  오디오가 빠지는 코드 결함을 찾지 못했다. 모델의 “음성이 없다”는 생성문은 transport 진단이 아니다.
  native 전처리의 실제 sample/RMS·tensor 값은 계측하지 않아 silent corruption을 완전히 배제하지 않는다.
  이 근거만으로 AudioBytes 교체나 프롬프트 반복이 해결책이라고 결론내리지 않는다.

근거: [고정 SDK multimodal helper](https://github.com/google-ai-edge/LiteRT-LM/blob/5e58e9a0aef7abf7091207a8b1d1063a1c800f08/runtime/conversation/model_data_processor/multimodal_processor_helper.cc),
[MiniAudio](https://github.com/google-ai-edge/LiteRT-LM/blob/5e58e9a0aef7abf7091207a8b1d1063a1c800f08/support/preprocessor/audio_preprocessor_miniaudio.cc).
앞선 [마음 추측 구분](../../research/20261004-grounded-intent-recheck.md)은 유지한다. 이번 tone 검사는 욕구 문장 자체의 금지를 뜻하지 않는다.

## 발견·수정·검토

1. 코드 검토에서 응답 SHA 누락, cancel timestamp 경쟁, 설치/전송 단계 cleanup 누락,
   terminal-only 첫 콜백 누락, symlink 경유 쓰기, force-stop 성공만 확인하던 문제를 수정했다.
   두 축 재검토에서 기존7건(spec4/standards3, 일부 중복)이 해소됐다.
2. Windows ADB exec-in의 대용량 regular-file stdin 전송이 잘렸다.1MB/128MB byte pipe는 일치했다.
   공개 모델만 UUID 이름으로 ADB push→private copy→크기검사하고 shell staging을 제거하도록 수정했다.
   미디어는 작은 byte pipe로 private에 직접 전송·크기확인한다. native 모델 SHA 검사도 유지한다.
   copy실패 cleanup/잘린복사 거부2개 회귀와 standards 추가 검토를 통과했다.
3. 첫 headless 에뮬레이터가 부팅 중 응답하지 않아 해당 작업이 띄운 두 process만 종료했다.
   AVD/기존 데이터는 삭제하지 않았다. ADB 서버 재시작 후 실제 S25 연결로 검증을 이어갔다.

## 판정·남은 작업

**실기기 실행 가능은 확인, 제품 탑재·품질·범용 기기 지원·배포 승인은 미통과.**
GPU 개선은 확인했지만20초의 전체 시간은 앱의45초 제한에 매우 가깝고 앱 디코딩 시간은 아직 빠져 있다.
발열3,6.63초 취소 지연, 잘못된 음성/시각 관찰·깨진 구조 출력,32비트 ABI 부재가 남는다.
기존 beta24/기존322회귀를 Gemma 승인 증거로 합산하지 않는다. Play 업로드·기존 앱 변경 없음.

로컬 증거는 `work/gemma-android/{run_id}/summary.json`, `result-private.json`, `response-private.txt`,
`qa-01/{negative-results.json,release-rejection.log,build-04.log}`에 있다.
원본·모델·APK·native응답·기기 식별자는 커밋하지 않는다. 공유 문서는 합성 시험의 익명 수치만 담는다.

## 정리

마지막 추론의 native cleanup·PID부재 확인은 통과했지만, 이어 연구 패키지 uninstall을 시도할 때
ADB가 `device not found`를 반환했다. 이 삭제 시도는 실행되지 않았으며 설치된 연구 모델/캐시 정리는 아직 미완료다.
제품 앱/데이터에 쓰는 명령은 실행하지 않았다. 연결 복구 후 연구 패키지 제거와 제품 버전 재확인이 필요하다.
로컬 private 시험 증거는 Git 제외 경로에 보존한다. 제품 품질/성능 목표는 미통과라 UltraQA 완료로 선언하지 않는다.
