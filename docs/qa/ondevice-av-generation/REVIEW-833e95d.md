# 시간순 관찰 체크포인트 검토

2026-10-04. 고정 비교: `72fe00aaeb75b5a036eb7a101bf281f60c6ade22...833e95d2558964712d36f1f6cc51e3408c2487ad`.
두 Sol 검토자가 서로 독립적으로 읽었다. 당시 후속 AST 파일은 대상에서 제외했다. 아래는 수정 전 발견 사항이며 최종 배포 승인과 다르다.

## Standards

1. **P2 — 관찰 응답의 스키마와 검증기가 다르다.** `ondevice_av_probe.py`의 perception 스키마는 관찰 1~3개를 요구하지만 generation 검증기를 재사용해 0개와 4개 합성 입력이 모두 `observed`로 통과했다. 허용 필드·limitations 제한도 일치시켜야 한다.
2. **P2 — WAV 헤더만 확인한다.** 1초 WAV를 100바이트로 잘라도 헤더의 16,000 frame만 믿어 입력 검증을 통과했다. 실제 PCM은 28 frame이었다. 모델 로드 전 실제 데이터 길이를 검증해야 한다.
3. **P2 — 영상 색상 범위/표준을 무시한다.** YUV→RGB는 항상 limited BT.601이었다. full BT.709의 `(18,128,128)`은 RGB `(18,18,18)`이어야 하지만 식은 `(2,2,2)`가 됐다. 이때 증거는 호스트 수치 재현이며 Android decoder 출력의 실제 범위나 얼굴 인식 영향 실측은 아니었다.

## Spec

1. **P2 — 점진적인 입 개폐를 놓친다.** `.04→.12→.24→.12→.04`를 포함한 연속 유효 관찰에서 인접 두 값이 임계 구간을 한 번에 건너야만 변화로 셌다. 명확한 점진 개폐를 0회로 안내하고 시각 표현의 근거에서도 제외했다. 유효 관찰 동안 확정 상태를 유지하고 얼굴 누락·여럿·시간 공백에서 초기화해야 한다.
2. **P2 — 관찰 스키마 위반을 통과시킨다.** Standards와 별도로 같은 0개/4개 합성 재현을 확인했다. 관찰 형식 검사라는 설계 요구를 충족하지 못한다. `quality_validated=False`는 유지돼 이 형식 결함이 의미 정확도 검증으로 보고되지는 않았다.

요약: Standards 3건, Spec 2건, 양 축의 최고 심각도 P2. 중복된 스키마 발견을 서로 독립적인 두 제품 결함으로 더하지 않는다.

## 후속 조치

- Android 입 움직임·색 변환·시간 표시 수정: `sol_perception_spec`.
- Python 스키마·손상 WAV 수정 및 합성 회귀: `sol_perception_standards`.
- 부모 담당: 실제 변경 확인, 단일 Gradle/ADB 통합, 전체 QA와 서명 패키징, 비공개 트랙 업데이트.
- 최종 통과 수와 실행 증거는 [PERCEPTION-QA](PERCEPTION-QA.md)에 기록한다. 원래 98개 Android/26개 연구 테스트는 이 새 결함을 모두 검사했던 수치가 아니다.
