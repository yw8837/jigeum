# 결과 카드 → 갤러리 — 0.5.6/code20

사용자는 결과 카드 디자인 그대로 사진/영상으로 내려받아 휴대전화 앨범에 저장하길 요청했고, 보완된 연락처 이후 Play 비공개 테스트 진행을 승인했다.

- 결과의 카드와 이미지/영상 출력은 같은 로컬 카드 렌더러를 사용한다. 선택 장면/원음/최종 편집 문장을 담고 버튼·근거 펼침·결제 안내는 출력에 넣지 않는다.
- 결과에서 ‘카드 이미지 앨범에 저장’, ‘영상 카드 앨범에 저장’을 제공한다. 녹음도 실제 소리가 있는 카드 동영상으로 만들 수 있다. 앱 기록 보관과 갤러리 저장은 각각 명확히 표시한다.
- 기록의 보관 영상에서도 카드 이미지/영상 앨범 저장을 제공한다. 기존 파일 위치 선택/공유 경로는 유지한다. 이미 생성된 결과의 보관/내보내기는 무료다.
- Android29+는 MediaStore pending 삽입→완전 쓰기→게시, 실패/취소→생성 항목 삭제. Android26–28은 쓰기 권한을 사용자가 눌렀을 때만 요청한다. 아기 원본 자동 업로드/외부 DB는 추가하지 않는다.
- 앨범에 사용자가 저장한 사본은 앱 기록 삭제로 지워지지 않는다. 사진 앱의 클라우드 백업 설정은 그 앱에서 관리한다. 새 권한/갤러리 노출을 정책에 반영한다.
- 표정 단독 욕구 번역은 기존 조사 결과를 따른다. 이번 저장 UX 작업에서 추가하지 않는다.
- 무료60초/10초/100MB, 전체120초/20초/200MB 검토본 유지. Play에는 release만 업로드한다. 새 서명preview/code20의 자동 업데이트 전환은 후속 더 높은 versionCode가 필요하다.

## 앱 기록과 앨범 저장의 동작

결과를 보는 것만으로 앱 기록을 자동 생성하지 않는다. ‘영상·소리 함께 보관’ 체크는 저장할 내용을 정하는 옵션이고, 실제 보관은 아래 저장 버튼을 눌렀을 때 시작한다.

| 사용자 동작 | 남는 데이터와 위치 | 이후 동작 |
|---|---|---|
| 촬영·분석 후 저장 없이 화면 닫기 | 촬영 원본은 앱의 임시 캐시. 결과는 기록 DB에 넣지 않음 | 화면 닫기·재촬영 시 원본 삭제. 비정상 종료로 남은 캐시는 다음 앱 실행에서 정리 |
| ‘이 문장 저장하기’ | 문장·날짜·관찰 요약·메모를 기기 내부 SQLite에 보관 | 기록을 다시 볼 수 있음. 영상·음성을 보관하지 않았으므로 장면 재생은 불가 |
| ‘장면과 함께 저장하기’ | 위 문장 기록과 선택 구간의 영상·원음·자막 MP4를 앱 비공개 `files/record-media`에 보관 | 기록에서 앱 내부 MP4를 재생하고 앨범·선택 위치로 복사하거나 공유 가능 |
| 결과에서 ‘카드 이미지/영상 카드 앨범에 저장’ | 휴대전화 사진·동영상 앱의 ‘아가톡’ 앨범에 PNG/MP4 사본 생성 | 이 버튼만으로 앱 기록은 생성하지 않음. 앱 기록을 지워도 앨범 사본은 남음 |

예를 들어60초를 촬영해10초 구간을 저장하면 앱 기록에는 그10초 MP4만 남고 전체60초 촬영 원본은 정리한다. 소리만 녹음한 경우에는 선택 구간의 실제 소리와 문장 카드가 담긴 MP4를 보관한다. 가져온 기존 영상은 앱 소유 파일이 아니므로 원본을 삭제하지 않는다.

앱 기록 삭제는 해당 내부 MP4도 삭제하며 실패한 미디어 삭제는 다음 저장소 접근/앱 실행에서 재시도한다. 앱 제거·앱 데이터 삭제 시 내부 기록과 MP4는 사라지지만 별도로 만든 앨범·내려받기·공유 사본은 해당 위치에서 관리한다. manifest와 Android12+ 추출 규칙은 앱 내부 DB·파일·설정을 자동 백업/기기 전송에서 제외하도록 설정했다. 사진 앱의 클라우드 백업은 그 앱의 설정에 따른다. 아기 기록·소리·영상은 서버로 자동 전송하지 않는다.

코드 근거: `CaptureFlow.kt:419`의 저장 클릭, `MainActivity.kt:285`의 별도 앨범 출력과 `:307`의 기록 보관, `ObservationStore.kt:67`의 SQLite 저장/미디어 연결, `TranslatedMedia.kt:218`의 내부 MP4, `RecordMediaViewer.kt:86`의 내부 파일 재생/앨범 복사.
