# 독립 검증 범위와 재현 방법

대상: `f42238c341ff890449154562052be15dc7f9b2e7`의 PlayVerifier + 이 변경의 `test/edge-cases.test.js`.

## 실행 범위

- Node v24.19.0, Linux x86_64
- 명령: `cd outputs/PlayVerifier && npm test`
- 기존 시험16개와 추가18개, 총34개. 실행 시각/최종 결과는 [최종 로그](node-tests.log)를 기준으로 한다.
- 서버 소스와 기존 시험은 수정하지 않았다. 추가 파일은 상대 import를 사용하며 외부 의존성을 추가하지 않는다.
- 실제 임시 포트의 localhost HTTP 요청을 보내지만 Google OAuth/Play 응답은 모두 대역이다. 서명키는 시험 안에서만 생성한다.
- 실제 결제·생산 환경 통신·운영 부하/수용량·계정/비밀값을 사용하지 않는다.

## 추가18개가 확인하는 경계

토큰 길이·설치 UUID·만료 경계, 구독 line item 선택,24시간 서명상한·변조 거절, 공유 lookup에서 설치별 서명분리, 손상/초대형/stream Google JSON과 회복, OAuth 오류와401 갱신,32개 동시 lookup 상한,공유요청 취소 격리,HTTP 경로/메서드/content-type,16KiB 본문상한,쿼터 윈도 경계.

이러한 시험의 성공은 검사한 조건에 대한 결과다. 모든 입력·기기·운영 설정이 안전하다는 보증이 아니다. 추가 시험은 운영 로직을 고친 버그 수정이 아니라 회귀 방어를 보강한 것이다.

## Android와 실제 결제는 미실행

이 환경에는 컴파일용 JDK/Android SDK/ADB/에뮬레이터가 없다. Android의 기존40개+신규9개를 여기서 실행하지 않았다. 현재 저장소의 체크포인트 빌드 성공은 기존 담당자가 남긴 로그이며 독립 빌드 결과로 집계하지 않는다. 신규9개는 컴파일 후ADB 단계에서 중단된 상태다.

현재 커밋 대응 APK·SHA256·실기기 설치/스모크 결과도 이 검토에서 확보하지 못했다. 이 변경의 머지는 Android49개 통과,0.4유료게이트완료,실제Play구매성공,앱전체QA완료,출시승인을 뜻하지 않는다.

## 재현과 통합

1. 이 변경을 포함한 최신 소스를 가져온다.
2. Node20이상으로 `outputs/PlayVerifier`에서 `npm test`를 실행한다.
3. 종료코드·통과·실패·skip·실행시간과 소스SHA를 보관한다.
4. Android/실기기 시험은 [검토 인수인계](README.md)와 원래 [RUNBOOK](../../RUNBOOK.md)의 별도 체크리스트로 수행한다.

추가 파일에서 실제 네트워크로 대체하거나 실제 토큰/개인키를 넣어 시험하지 않는다. 실제Play환경 시험은 계정·상품·권한·테스터 준비가 된 별도 단계다.
