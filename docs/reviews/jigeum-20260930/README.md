# 이번 주 테스트 공개를 위한 검토·인수인계

검토일 2026-09-30. 기준 소스 `f42238c341ff890449154562052be15dc7f9b2e7`.

## 목표와 변경 범위

PM이 정한 목표는 **이번 주에 테스트 참여자가 설치해서 사용할 수 있게 만드는 것**이다. 일반 공개 Play 출시나 유료 판매 완료를 이번 검토의 필수 조건으로 확대하지 않는다.

이 검토 변경은 조사·UI/UX 검수·코드/보안 리뷰·인수인계와 로컬 서버 회귀 시험 보강이다. Android 운영 코드·기존 접근 정책·가격·브랜딩·스토어·계정·배포 설정을 변경하지 않는다. 앱 전체 구현 완료나 출시 승인 문서가 아니다.

## 읽을 문서

- [BM·레퍼런스 재검토](business-model.md): 공식 출처와 최신 무료/전체 이용권 방향, 검증할 가설
- [UI/UX 검수](uiux.md): 실제로 본 저장소 화면 3장과 아직 실행하지 못한 항목
- [코드·보안 리뷰](code-security.md): 확정된 코드 경로, 미재현 후보와 유료 활성화 전 조건
- [실행 증거](verification.md): 정확한 소스와 실행한 시험/미실행 범위
- 원래 기준: [HANDOFF](../../HANDOFF.md), [NEXT](../../NEXT.md), [접근 정책](../../../outputs/Jigeum-Access-Policy.md)

## 현재 사실

- f42238c는 0.3.0/code6이며 카메라·저장 영상이 무료인 현재 구현을 포함한다. 0.4 전체 이용권의 미디어 잠금은 아직 구현 전이다.
- 과거 기준본의 Android 계측40개 성공과 이번 추가9개의 컴파일 성공은 별개다. 추가9개는 ADB 환경 문제로 실행 대기이며 현재49개 전체 실행 성공으로 쓰지 않는다.
- 서버 Google 응답은 대역이며 localhost HTTP를 사용한 독립 시험이다. 실제 Play 구매/복원/환불을 검증한 것이 아니다.
- 이 검토 환경에는 Android SDK·컴파일용 JDK·ADB·에뮬레이터가 없어 Android 빌드/설치를 독립 실행하지 못했다. 기존 개발자의 빌드 로그는 읽었지만 우리 실행으로 집계하지 않는다.
- 실제 영아 의도 정확도·개인화 학습·사진/원음 보존은 현재 구현의 성능이나 혜택으로 약속하지 않는다.

## 기존 Codex 담당자에게 전달할 실행 작업

### 1. 테스트할 빌드를 고정

현재0.3 계열의 기능 시험인지, 0.4 전체 이용권 경계를 구현한 다음 시험인지 PM과 맞춘다. 새 빌드의 커밋·버전코드·APK SHA256·서명 종류를 기록하고 기존 기준APK를 덮어쓰지 않는다. 미구현 카메라/영상 잠금을 이미 동작한다고 보고하지 않는다.

### 2. Android 실행 증거 확보

`docs/RUNBOOK.md`에 있는 로컬 SDK/AVD 경로를 확인하고 전용 에뮬레이터 복구 후 전체 계측을 실행한다. 현재는 기존40+신규9의 실행/실패/건너뜀을 구분한다. 0.4가 추가되면 해당 UI·미디어 경계 시험도 함께 갱신한다. 한 담당자만 빌드와 ADB를 사용한다.

실제 ARM 단말에서는 설치 → 권한 거절/수동 입력 → 10초 소리 → 후보 수정/저장 → 종료/재접속 → JSON 백업/복원 → PNG/CSV 공유를 먼저 확인한다. 카메라·저장영상·잘못된 입력·프로세스 복원·큰 글씨는 별도 기록한다. 진짜 아기 데이터 없이 합성 fixture로 시작한다.

### 3. 재현할 코드 경계

1. 같은 날짜 같은 내용의 서로 다른 기록과 timestamp 충돌이 겹치는 JSON 가져오기에서 기록 누락 여부
2. PNG/PDF 생성과 전체 삭제가 경합할 때 삭제한 데이터의 재생성 또는 없는 파일 URI 공유 여부
3. 구매 콜백 자체가 오지 않을 때 PURCHASING 상태에서 재조회/복원이 가능한지
4. acknowledge 실패·앱 종료 후 승인 재시도와 복구 여부. 이 항목은 유료 거래 활성화 전 조건이다.

각 항목은 현재 미재현 후보를 포함한다. 재현 전 ‘확정 버그’로 표시하거나 근거 없이 큰 구조를 바꾸지 않는다.

### 4. 전이 의존성 확인

`releaseRuntimeClasspath`의 `protobuf-javalite`에 대해 Gradle dependencyInsight를 저장한다. MediaPipe 전이 의존성의 공급자 보안공지와 실제 패키징 버전을 대조한다. 버전이 포함된 것과 앱에서 공격 입력이 도달하는 것은 별도 판단이다. 호환성 확인 없이 protobuf 종류를 바꾸거나 기존에 실패했던 R8 축소를 다시 켜지 않는다.

### 5. 무료 테스트 공개와 유료 운영을 분리

무료 제한 테스트는 운영 결제 서버·실구매가 없어도 검증할 수 있다. 테스트 배포 경로와 대상은 PM이 정한다. 배포 자체는 이 리뷰에서 실행하지 않는다. 실제 결제 테스트에는 Play 앱/상품/테스터·검증 HTTPS/서명·승인 처리·환불·계정 전환 검증이 추가로 필요하다. 스토어 신원 확인과 테스트 요건은 해당 배포 경로의 조건으로 관리한다.

## UI/UX·BM 우선 결론

- 무료의 완결성을 유지한다: 소리/수동 → 수정 → 저장 → 다시 보기 → 기본 공유/백업.
- 유료는 같은 문장 품질에서 입력 편의와 제작 기능을 확장한다. 더 정확한 아기 마음 판독처럼 설명하지 않는다.
- 실제 PDF 본문을 보여 주고 ‘다음 달에도 만들 이유’를 보호자에게 확인한다. 월4,900/3개월12,900은 실행 가격 제안이며 지불 의사 검증 결과가 아니다.
- 첫 파일럿에서는 설명 없이 완주하는지, 결과를 실제 의도로 오해하는지, 수정/저장을 발견하는지, 다시 보고 싶은지를 관찰한다. 모집 수치나 매출 목표를 시장 사실로 꾸미지 않는다.

## 통합 시 주의

이 브랜치의 추가 문서·서버 시험은 Android 구현 담당자의 파일과 분리한다. 통합 전 main 변경을 확인하고 타인의 소스 변경을 덮어쓰지 않는다. 머지 후 기존 작업자는 main을 동기화하고 새 APK·검증 결과를 별도 커밋으로 남긴다. 이 문서를 최신 앱 실행 결과로 대체하지 않는다.
