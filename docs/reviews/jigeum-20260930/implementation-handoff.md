# 0.4 기록과 공유 안전성 보강 인수인계

기준 커밋: `f83887c74a243dd3e535bd7e932265d612a7a511`. 기존 Codex의 0.4.0/code 7 구현과 검증 자료를 보존하고, 남아 있는 기록·공유·카메라 비동기 경계만 보강한다. **이 추가 변경은 Android 빌드 검증 전이며 초안 PR로 유지한다.**

## 역할과 합치는 원칙

PM은 콘솔 승인이 완료되면 바로 등록할 수 있는 수준을 목표로 정했다. Codex의 최신 앱 구현을 기준으로 삼고, 이 변경의 검증 결과를 별도로 남긴다. ddot은 분석 정확도 근거와 평가 방법, 시장·BM 세부기획을 추가 조사한다. 계정 정산 사례 검토는 개발보다 후순위다.

이전 PR 초안의 별도 접근 정책 구현은 겹치므로 제거했다. 최신 main의 AccessPolicy·시간 검증·화면·약관·버전은 되돌리지 않는다. 이전의 별도 정책 호스트 5개 통과는 삭제한 구현에 대한 결과이며 현재 코드에 합산하지 않는다.

## 이 PR에 남긴 수정

- 같은 시각에 충돌한 서로 다른 기록을 보존하고, 출처를 SQLite 기존 meta에 함께 저장해 재가져오기 중복을 방지
- 삭제 전에 시작했거나 대기 중이던 PNG/PDF 결과를 선택기로 보내지 않도록 작업 세대를 확인. DB 변경 중 새 PNG/PDF 시작 제한
- 비동기로 카메라 provider가 준비된 후 실제 센서를 연결하기 직전에 현재 이용권을 다시 확인
- 기록·공유 계측 8개 추가, 실제 Kotlin 병합 테스트, 부모 파일럿과 베타 체크리스트

**최신 main에서 전달받아 확인한 실행 로그:** debug/test/release/lint 빌드 성공, Android 계측 `OK (72 tests)`, lint 오류 0·경고 22·힌트 2. 무료 UI 7유형 중 최종 clipping 변경 뒤에는 3유형과 72계측을 재실행했다. 모든 화면이 최종 APK에서 다시 시험된 것은 아니다. APK SHA는 `3a60112e49198c6013c0630bbf688716c8be61f3ceb514b6e9a681d5c6283795`다. [기존 0.4 보고서](../../../outputs/Jigeum-QA-0.4.0.md)

**이번 추가 변경에서 직접 실행:** 최신 main의 실제 RecordTransfer.kt를 Kotlin으로 컴파일해 기록 누락을 재현했다. 수정본은 동일 사례와 전체 호스트 병합 11개를 통과했다. 이 시험은 Android 저장소를 테스트 계약으로 대체하므로 SQLite 트랜잭션·JSON 파서 검증은 아니다. 기존 서버는 이 작업에서 34개 통과, 실패·건너뜀 0이며 Google 응답은 대역이다.

**이번 추가 변경의 미실행:** Android/Compose 전체 컴파일, 신규 계측 8개, 기존 72개에 대한 회귀, PNG/PDF 렌더·선택기 경쟁, 실제 카메라 비동기 provider 시험. 기존 72 통과를 수정된 새 APK의 결과로 사용하지 않는다.

## Codex 통합 검증 순서

1. 작업 중인 로컬 변경을 보존하고 별도 브랜치에서 이 PR을 검토한다. 강제 reset이나 파일 덮어쓰기를 하지 않는다.
2. [RUNBOOK](../../RUNBOOK.md)대로 debug 앱·androidTest·release bundle·lint를 실행한다. 발견한 컴파일 오류부터 해결한다.
3. 전용 합성 데이터 설치에서 전체 계측을 실행한다. 기존 72개와 신규 8개가 모두 발견되는지 확인하고 실제 실행 수·실패·ignored를 기록한다.
4. 타임스탬프 충돌·재가져오기·삭제 후 복원·오래된 preview·트랜잭션 실패 시 원본 보존을 확인한다. 기존 앱에 업데이트 설치해 기록이 유지되는지도 확인한다.
5. PNG/PDF 생성 중 삭제 및 선택기를 열기 전 삭제를 실제 화면에서 확인한다. 공유 화면을 먼저 연 후 삭제하는 경우의 잔여 한계는 아래와 같이 구분한다.
6. 카메라 provider가 늦게 완료되는 동안 이용권이 만료되는 상황을 실제 경로에서 시험한다. 기존 FakeMedia 내비게이션 시험으로 센서 연결을 검증했다고 보고하지 않는다.
7. 새 APK SHA, 실행 환경·명령·로그를 PR에 남긴다. 실제 통합 빌드·회귀가 통과한 뒤 병합한다.

## 등록 준비까지 남은 것

- 실제 resolved dependency graph에서 protobuf-javalite 버전과 영향 확인, 필요 시 호환 업그레이드·회귀
- 구매 콜백 누락 시 PURCHASING 복구, 동기 acknowledge 실패 안내와 재시도 설계
- 실제 Play 상품·가격·구매·복원·환불·승인 시험 및 검증 서버 운영 연결
- ARM 실물 기기에서 모델·마이크·카메라·영상·발열·오프라인·파일 선택·16KB 환경 확인
- 업로드 서명, 정책·약관 URL과 시행일, 스토어 고지·스크린샷 정합성
- [베타 체크리스트](beta-release-checklist.md)와 [부모 파일럿](beta-pilot.md)의 실제 실행 결과

공유 선택기를 이미 띄운 뒤 기록을 삭제하면 수신 앱이 읽기 전에 캐시 파일이 없어질 수 있다. 이번 수정은 선택기 이전의 오래된 작업 차단이며 이 이후 전달 수명주기까지 해결했다고 주장하지 않는다. 수정 전 가져오기에는 출처가 없어 옛 백업을 다시 가져오면 보존용 복제 1건이 생길 수 있다.

운영 키·계정·배포·정산 설정은 이 PR에서 수행하지 않는다. 실제 결제 설정은 해당 검증 전까지 비활성 상태를 유지한다. 등록 가능 완료 판정은 위 실행 증거가 확보된 뒤 한다.
