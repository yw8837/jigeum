# 0.4 구현 후보 인수인계

기준 커밋: `cc8403508dfb311e57c12d4b5d9f1226618ad851`. 이 변경은 **Android 빌드 검증 전의 구현 후보**다. 버전 이름과 코드는 기존 0.3.0/code 6을 유지하며, 검증 후 통합자가 새 배포 버전을 정한다. main의 과거 문서에서 “미구현”으로 남은 항목을 이 후보의 실제 완료 증거 없이 일괄 완료 처리하지 않는다.

## 포함한 변경

- 카메라·저장영상·PDF 중앙 접근 정책과 실행 시점 권한 확인
- 만료·화면 종료 뒤 늦은 콜백 거부, 원래 화면으로 복귀, 기존 초안의 편집·후보 보존
- 같은 시각에 충돌한 서로 다른 기록의 누락 방지와 로컬 SQLite 가져오기 출처 보관
- 삭제 전에 시작했거나 대기 중이던 PNG/PDF의 오래된 결과 공유 방지
- 무료·유료 안내와 읽기 전용 미시행 약관 초안
- 호스트 회귀 테스트, Android 계측 테스트 추가, 부모 파일럿 절차와 베타 체크리스트

## 실제 실행과 미실행

- 서버 기존 34개 테스트: 2026-09-30 이번 작업에서도 34 통과, 0 실패, 0 건너뜀. 실제 HTTP, Google 응답은 대역이다.
- 실제 `RecordTransfer.kt`: 기존 코드의 누락 오류를 Kotlin으로 재현. 수정본 병합 로직 11개 통과. Android 저장소는 테스트 계약으로 대체하므로 SQLite 트랜잭션·JSON 파서 검증은 아니다.
- 실제 `AccessPolicy.kt`: 호스트 5개 통과. 권한 우회 및 종료된 세션 재활성화의 고의 변형 2개를 테스트가 거부했다.
- 새 Android 계측 13개 작성: 접근 정책 5개와 기록/내보내기 8개. **실행하지 않았다.** 기존 테스트 수와 합쳐 통과 수로 표현하지 않는다.
- Android/Compose 전체 컴파일, APK/AAB, lint, 계측, 화면, ARM, 실제 구매: 아직 미실행.

## 통합자가 이어서 할 순서

1. 기존 로컬 작업을 보존한 별도 브랜치에서 이 PR의 변경을 검토한다. 작업 중인 파일을 강제로 덮어쓰거나 reset하지 않는다.
2. [RUNBOOK](../../RUNBOOK.md)대로 debug 앱·androidTest·release bundle·lint를 실행한다. 컴파일 오류를 먼저 해결한다.
3. 전용 합성 데이터 설치에서 전체 계측을 실행한다. `AccessPolicyTest`, `RecordTransferTests`, `MemoryArtifactsTests` 신규 사례를 누락하지 않는다.
4. [베타 체크리스트](beta-release-checklist.md)의 무료 완주, 잠금, 권한 요청·선택기·분석 중 만료, 수정 초안 보존, 프로세스 재생성, 삭제/공유 경쟁, 업데이트 보존을 실제 화면에서 확인한다.
5. MediaPipe 의존성은 실제 dependency graph에서 protobuf-javalite 버전을 확인하고, 필요 시 호환 업그레이드 및 재검증한다. upstream POM만으로 설치 APK의 취약성을 확정하지 않는다.
6. 실제 기기에서 마이크·카메라·영상·모델·발열·오프라인을 확인하고, 버전과 APK SHA를 기록한다. 그 뒤 PM이 테스트 전달 범위를 정한다.
7. 빌드와 회귀가 통과하면 병합하고, 관련 HANDOFF/NEXT/검증 기록을 실제 결과에 맞춰 갱신한다. 미실행 체크박스는 남긴다.

## 아직 해결하지 않은 항목

- 구매 콜백 누락 시 PURCHASING 상태에서 복원/새로고침이 막히는 복구 흐름
- 동기 acknowledge 실패 메시지 덮어쓰기와 실제 구매 승인 재시도/운영 설계
- 공유 선택기를 이미 띄운 다음 삭제하면 수신 앱이 읽기 전에 파일이 없어질 수 있는 문제. 이번 수정은 선택기 이전의 오래된 작업 차단 범위다.
- 수정 전 충돌 가져오기에는 출처가 없어 옛 백업 재가져오기 시 보존용 복제 1건이 생길 수 있다. 서로 다른 기록을 조용히 잃는 것보다 보존을 택했다.
- 실제 Play 정산·계정·운영 키·검증 서버 설정은 이 변경에서 수행하지 않았다. PM은 개발을 우선하고 해당 검토는 후속으로 두기로 했다.

실결제 설정은 검증 전까지 비활성 상태를 유지한다. 호스트 테스트 통과가 유료 서비스 출시 승인이나 부모 사용성 검증을 대신하지 않는다. 실제 부모 시험은 [파일럿 절차](beta-pilot.md)에 따라 별도로 진행한다.
