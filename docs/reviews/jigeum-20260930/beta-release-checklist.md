# 지금 0.4 베타 검증 체크리스트

작성일: 2026-09-30. 아래 항목은 모두 미실행 상태에서 시작한다. 이전 버전의 통과 기록을 새 빌드의 결과로 복사하지 않는다.

## 빌드 식별과 실행 환경

- 커밋 / 브랜치 / 작업 트리 변경 여부:
- versionName / versionCode / APK SHA-256 / 서명:
- JDK / Gradle / SDK / 기기 모델 / Android 버전 / ABI:
- 실제 실행 명령 / 시작·종료 시각 / 로그 위치:
- 통과 / 실패 / 건너뜀 / 미실행 수:

전용 합성 시험 설치만 사용한다. ADB 담당자는 한 명으로 고정한다. 빌드·설치·계측 명령은 저장소 [RUNBOOK](../../RUNBOOK.md)과 [QA 도구 설명](../../../outputs/QA/README.md)을 따른다. 0.3 전용 camera/video 시나리오를 무료 0.4에 그대로 적용하지 않는다.

## 새 코드 검증

- [ ] assembleDebug와 assembleDebugAndroidTest 성공
- [ ] bundleRelease와 lintRelease 실행 및 결과 확인. unsigned AAB를 배포용으로 소개하지 않음
- [ ] 현재 코드의 전체 Android 계측 실행. 과거 49개에 새 테스트가 추가되면 실제 실행 수로 기록
- [ ] 서버 npm test 실행. Google 대역 시험과 실제 Play 거래 구분
- [ ] 실제 resolved dependency graph에서 protobuf-javalite 버전 확인. upstream POM만으로 APK 포함 버전을 단정하지 않음
- [ ] 실제 APK/AAB 패키지 검사. R8 비활성 유지, 네이티브 정렬 확인과 ARM 실행을 구분

## 무료와 이용권 경계

- [ ] 녹음·직접입력 → 표현 선택·수정 → 저장 → 조회 → PNG 및 JSON/CSV가 결제 없이 완료
- [ ] 카메라·영상 선택 시 센서 권한과 파일 선택기보다 이용권 설명이 먼저 표시
- [ ] 잠긴 화면 복원·뒤로가기·연속 탭으로 카메라나 디코더가 시작되지 않음
- [ ] 권한 요청 중, 파일 선택 중, 분석 중 만료하면 자원을 정리하고 늦은 결과를 폐기
- [ ] 카메라·영상에서 이미 생성한 문장과 편집 내용은 만료 후에도 수정·저장 가능
- [ ] PDF 시작 전에 권한 확인. 유효 권한으로 시작한 생성은 완료되고 기존 결과물 보존
- [ ] 구매·복원 성공 후 명시적 계속하기로 이동하며 자동 촬영하지 않음
- [ ] 취소·닫기·정책 페이지 왕복 후 원래 화면·편집·앨범 선택 유지
- [ ] 구매 보류·취소·콜백 누락·검증 실패·이전 세대 응답에서 잘못 열린 권한이나 영구 대기 없음

## 기록과 파일

- [ ] 서로 다른 기록의 타임스탬프 충돌을 가져와도 기존/신규 기록 모두 보존
- [ ] 같은 백업 재가져오기는 중복을 만들지 않음. 충돌 후 재시도와 앱 재시작도 포함
- [ ] 가져오기 실패 시 일부 데이터만 저장되거나 기존 데이터가 사라지지 않음
- [ ] 내보내기 중 삭제·화면 이동·취소를 반복해 유효하지 않은 파일 공유나 오래된 결과 재생성 여부 확인
- [ ] 새 버전 업데이트 설치 뒤 기존 합성 기록·백업 복원과 메타데이터 호환 확인

## 실제 화면과 기기

- [ ] 작은 화면·가로 화면·200% 글꼴에서 버튼 접근과 잘림을 직접 확인
- [ ] TalkBack 순서·버튼 이름·터치 영역 확인
- [ ] ARM 실기기에서 녹음·전후면 카메라·모델·저장영상·오프라인·발열·메모리 확인
- [ ] 마이크·카메라 권한 거절 후 무료 대체 경로와 재시도 확인
- [ ] 16KB ARM 기기 실행 여부를 별도 표시. 패키지 정렬만으로 실행 통과 처리하지 않음

## 배포 판단

무료 베타: 포함 기능의 실제 빌드·기록 보존·핵심 흐름 검증 후, PM이 설치 파일과 알려진 한계 및 전달 대상 확정. 이 문서 작성은 배포 완료가 아니다.

실결제: 운영 프로젝트, 검증 HTTPS, 키/서비스 계정, Play 상품과 실제 가격, 라이선스 테스터 구매·복원·환불·승인 검증이 별도로 필요하다. 테스트 대역으로 통과했다고 실결제를 활성화하지 않는다.

부모 파일럿: [진행 절차](beta-pilot.md)를 사용하되 실제 피드백을 받은 뒤 결과를 기록한다. 준비 문서를 사용자 검증 완료로 보고하지 않는다.
