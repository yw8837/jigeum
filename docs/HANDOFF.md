### 최신 실측 — S25 Ultra Gemma 연구 실행

사용자가 연결한 S25 Ultra(API36)에서 별도 연구 APK로 Gemma를 실제 실행했다.
**제품 앱에는 아직 탑재하지 않았다.** 합성 AV10초의 GPU 추론14.82초/runner전체32.79초,
AV20초30.93초/43.29초이며20초 뒤 thermal3(SEVERE)를 보고했다. GPU PSS 표본은 약3.5–3.6GiB다.
취소는 native terminal까지 요청 후6.63초 지연했고 새 프로세스의 재실행은 완료했다.
소리 누락·영상 내용을 음성으로 기술·잘못된 순서/JSON 때문에 의미 품질은 미통과다.
SDK 배선 재검토에서 AudioFile 누락 결함은 찾지 못했으나 native tensor 값은 미계측이다.
[실측·실패·QA](qa/ondevice-av-generation/S25-GEMMA-20261004.md).

연구 실행기14 host회귀·실기기 입력오류6개·release차단을 확인했고 Windows ADB 대용량 전송 잘림을 수정했다.
AAR 실제 ABI는64비트뿐이라 기존 앱의32비트 지원까지 충족한 것이 아니다. 기종명 제한은 추가하지 않았다.
마지막 실행 이후 연결이 끊겼으나 사용자가 USB 디버깅을 다시 켠 뒤 연구 패키지 uninstall을 완료했다.
연구 패키지·PID·공개 모델 staging의 부재를 확인했고 내부 모델/캐시는 uninstall로 제거됐다.
기존 제품 앱·원본은 수정하지 않았으며 code23/0.5.9-beta와 lastUpdateTime이 전후 동일하다.
Play 업로드는 없으며 code24의 제품 QA를 Gemma 통과로 재해석하지 않는다.

후속 [공식 런타임 결함 조사](research/20261004-gemma-runtime-triage.md)에서 같은 파일 SHA·최신0.17.1을 확인했다.
알려진 JSON/GPU 결함은 있지만 현재 S25의 의미 실패에 적용되는 수정 근거는 확보하지 못했다.
[대안 후보 조사](research/20261004-compact-av-candidates.md)는 MiniCPM-o·Mini-Omni2·Qwen2.5-Omni3B/Qwen3-Omni·SmolVLM2의
실제 모달리티·파일 크기·라이선스·Android/한국어 근거를 대조했다. 이 범위에서 바로 검증할 모바일 대체 후보를 선정하지 못했다.
이는 모든 모델의 불가능성이나 사용자 목표 축소 승인이 아니다. 새 모델 다운로드·제품 변경·배포는 수행하지 않았다.

추가 [보관 PCM 비교](research/20261004-retained-pcm-ast-check.md)에서 과거 기준 PCM 5개를 검증하고,
이미 평가한 원본의 2구간을 제외했다. 다른 보류 원본의 2구간은 고정 AST/v2에서도 후보 조건을 충족하지 못했다.
별도 울음 1구간은 기존 판정을 유지하며 AST 실행 대상에서 제외됐다. 필터 상세 타임라인이 없어 현재 Android 전체 경로 검증은 아니다.
독립 정답·일반 정확도 근거로 세지 않으며, AST 비활성과 기존 임계값을 유지했다.
이번에도 새 모델을 제품에 탑재하지 않았다. 실측 결과를 알리고 Gemma 없는 검증된 code24 영상 개선본의 선배포 여부를 질문했다.

새 [SpeechMaturity 저자 artifact 조사](research/20261004-speech-maturity-artifacts.md)에서 기존에 미확인으로 남았던
5-way 학습 분류 head와 encoder 가중치를 확인했다. 옹알이 두 종류·웃음·울음·기타의 **음성 분류 후보**이며
영상·욕구·문장 생성 모델은 아니다. 약0.576초 학습 입력과 복수 encoder, 공식 recipe의 학습/평가 의존성이 있어
10/20초를 단일 입력으로 넣거나 공개 파일 존재만으로 바로 Android에 탑재하지 않는다.
고정 소스의 [실행 구조 검토](research/20261004-speech-maturity-runtime-review.md)에 따라 최소 가중치·키/shape부터 검증한다.
상용 모델 포함·재배포 조건은 미확정이다. 이번 source 조사에서 가중치 다운로드·추론·제품 활성화는 하지 않았다.

### 최신 대화 보완 — 배포 범위와 Gemma 기대 차이

사용자는 `최종검토후 배포`를 지시한 직후 **Gemma 4 E2B 온디바이스 탑재 시 속도 저하·문제가 없어야 한다**고 강조했고, 배고픔·밥 요청 표현이 한 번도 나오지 않는 점을 지적했다. 현재 code24는 Gemma 미탑재이며 시간순 영상 관찰 개선 후보라는 사실을 다시 설명했다. 업로드 전 현재 후보를 먼저 배포할지 Gemma 품질·성능 통과 후 배포할지 질문한 상태다. 공개 출시 승인으로 확대하지 않는다.

현재 `EvidenceInterpreter`에는 배고픔·졸림의 추론 경로와 해당 문장 풀이 없다. 울음·리듬 등의 입력만으로 욕구 문장이 나오지 않음을 검사하는 테스트도 있다. 따라서 욕구 표현이 안 나오는 이유를 사용자 영상이나 수음 실패로만 설명하지 않는다. **장면에 어울리는 감정·욕구 추측을 제공하려는 제품 목표는 유지한다.** 장면에 없는 사실을 추가하는 실패와 감정·욕구 표현 자체를 혼동하지 않는다. 기존 무근거 울음 테스트를 삭제하거나 단순 문장 풀 추가만으로 이 목표를 완료하지 않는다.

Gemma 호스트의 실제 AV10초 단회 추론은 약95초였고 일부 GPU 실행은 메모리 오류였다. 이후 S25 ARM 연구 APK에서 지연·메모리·발열을 위 실측 요약과 연결 문서처럼 측정했다. 호스트 수치를 휴대폰 성능으로 옮기지 않으며, S25 연구 실행도 제품의 촬영·저장·화면 응답 보존이나 모든 기기의 지원을 입증하지 않는다. 제품 통합 성능 검증은 남았다.

현재 분석의45초 제한·취소·UI 분리와 신규 runtime의 검증 경계는 [성능 준비 검토](qa/ondevice-av-generation/PERFORMANCE-READINESS.md)를 따른다. 사용자 기기는 **Galaxy S25 Ultra**이며 다른 테스터 기종은 미확인이다. 이어 사용자는 **기종별 사용 제한을 두지 말라**고 요구했다. 기종명 허용 목록·고급기 한 대의 성공으로 일반 지원을 주장하지 않는다. 최신 S25 연구 실행은 위 실측 문서를 따르며 제품 UI·같은 프로세스 취소·일반 기기 검증과 구분한다.

Astra/high의 [마음 추측 재검토](research/20261004-grounded-intent-recheck.md)는 소리 라벨뿐인 합성검사의 욕구 금지를 제품 전체로 확대하지 않도록 바로잡았다. 자연스러운 가상 청유와 실제 없던 사물·행동 관찰을 구분한다. 기존 tone 오인·사건 누락·실행 부담은 그대로 실패이며, 재실행할 새 호출 버그 근거는 찾지 못했다. 새 모델 추론·Android QA를 수행한 결과가 아니다.

## 최신 사용자 요구 — 온디바이스 생성 구조 개편

사용자가 **선택한 최대20초의 소리·영상 흐름을 함께 해석하고 아기말을 새로 생성하는 구조**로 변경을 요청했다. 이어서 **무조건 온디바이스, 외부 전송 없이**를 재확정했다. 단순 문장 풀 확대만으로 이 요구를 완료 처리하지 않는다. [설계](superpowers/specs/2026-10-03-ondevice-av-generation-design.md)에 따라 Gemma4 E2B를 실제 다운로드·해시 확인하고 로컬 소리+이미지10/20초를 실행했다. **초기 관찰 품질은 미통과이며 앱 모델 교체·Android 통합·신규 배포는 미완료**다. [실측/실패와 한계](research/20261003-ondevice-av-probe.md)를 먼저 읽는다. 아래0.5.9는 계속 배포 기준본이다.

2026-10-04 최신 요청: **문장 표현보다 소리·영상을 제대로 읽는지 우선 개선**한다. 약국 영상은 또렷한 옹알이인데 현재 앱10초/20초 모두 미확정으로 보류한다고 사용자가 확인했다. 잡음이 더 크다는 가정을 하지 않는다. `응앵25초`는 이전 앱 결과 영상이며 새 원본의 인식 평가 분모에서 제외한다. 핵심 분석·수정은 사용자가 지정한 **Astra/high**, 이후 후속 조사·QA·배포는Luna/Sol로 진행한다. [실행 계획](superpowers/plans/2026-10-04-perception-recovery.md). 작업은 `codex/ondevice-av-probe` worktree에서 이어간다.

동일 원본의 현재/float YAMNet × raw/filter ×10/20초8조합에서 누락을 재현했다. AST 후보는 해당 영상의 Babbling0.419를 포착하지만 공개 옹알이·혼합 사건 한계가 남아 일괄 교체하지 않는다. 클래스 점수를 음량/정확도로 해석하지 않는다. Android에서는 순차 디코딩·실제PTS·2fps VIDEO 추적·초중후/입 변화 방향 보존을 구현했고 관련98개 계측을 통과했다. 연구 호스트26개도 통과했다. 후속 Sol 검토·보조 모델 통합·문장 생성·전체 QA·배포는 남았다. [실측](research/20261003-ondevice-av-probe.md) / [진행 중 QA](qa/ondevice-av-generation/PERCEPTION-QA.md). 새 연구 결과를 배포 앱의 인식 개선 완료로 보고하지 않는다.

### 2026-10-04 후속 통합 검증

- 연구 도구 **43개 통과**, 수정 후 전체 앱 회귀 **322통과/0실패/명시제외2**다. 이후 정책v2와 빌드 분리를 변경한 기본 APK 관련 **116개**, 연구 APK 관련 **27개**도 모두 통과했다. 이 묶음은 중복이 있고 같은 소스 시점의 전체 검사로 합산하지 않는다. AST INT8 91MB 후보의 Android ORT1.24.3 이식, 합성 logits 비교, native 취소·복구·10/20초 창 보존을 검증했다. [Android QA](qa/ondevice-av-generation/ANDROID-AST-QA.md).
- 평가용 opt-in에서 제공 원본의10초/20초가 실제 Android 디코더·두 음성 모델·시각 관찰을 거쳐 옹알이 후보로 회복됐다. 영상은20/40개 표본의 실제PTS를 보존했다. **배포 경로는 여전히 비활성이며 이것은 독립 정확도·새 문장 생성·기본 앱의 회복 증거가 아니다.** 추가 대상 연령 공개 자료에서도 누락이 남았다.
- 두 축 코드 검토의 P2 두 건(감정 하위 클래스6개 충돌 누락, 비활성 모델의 일반 빌드 포함)을 수정·재검증했다. 기본 APK/AAB에는 AST·ORT가 없으며 연구 모델 누락/손상/금지 배포 변형의 Gradle6게이트를 통과했다. beta/release lint 각각 오류0/경고19다. [검토](qa/ondevice-av-generation/REVIEW-AST-20261004.md).

- Gemma/Qwen 생성 실험은 없는 감정·욕구를 추가하거나 부자연스러운 문장을 출력했다. 호출 형식 대조에서도 실패가 남아 채택하지 않았다. [원인 검토](research/20261004-generation-failure-review.md).

- 사용자에게 검증된 영상 개선을 먼저 배포할지, 인식·생성이 준비될 때까지 함께 보류할지 범위를 확인 중이다. 확인 없이 전체 요구를 영상 개선만으로 축소해 완료 처리하지 않는다.

### 이번 변경과 남은 인식 한계

- `상상한` 대신 `예상한 아기말`을 표시한다. 실제 근거를 AUDIO/AUDIO_VISUAL/CAREGIVER/LEGACY로 저장하고 화면·PNG·새 MP4·기록·백업에 유지한다. 영상 파일/유료 권한만으로 시각 근거를 붙이지 않는다.
- 음성이 보류돼도 요청한 시각 관찰을 실행한다. 무음·작은 소리·발성 미확정·배경 우세·모델 오류 안내를 구분하고, 조건에 맞으면 현재 선택 중 소리가 집중된5초를 제안한다. 자동 재분석/저장은 없다.
- 기존 음성 판정이 통과하고 유효 단일 얼굴 표본이2개 이상일 때 입 모양에 맞춘 답을 청하는 문구를 추가한다. 얼굴 주인·실제 프레임PTS·립싱크·감정·욕구를 확인하는 기능은 아니다. 얼굴만으로 한마디를 만들지 않는다.
- **제공된 두 영상의 아기 발성 누락은 미해결.** 공식 float 모델 비교에서도 회복하지 못하고 공개 웃음/울음 일부가 회귀해 기존 모델·음성 임계값을 유지했다. 공개22개 기존판정과 변화0이며 strict 선언라벨4불일치는 여전히 실패다. [실측 진단](research/20261002-private-video-diagnosis.md) / [모델 비교](research/20261002-model-059-comparison.md).
- 결과 카드의 초기/최종 높이를 맞춰 로딩 중 버튼 위치가 밀리는 결함을 수정했다. 이 변경을 수음 개선·아기 의도 정확도 향상으로 소개하지 않는다.
