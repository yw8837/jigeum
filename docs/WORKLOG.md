# 작업 과정과 검증 이력

대화와 저장된 문서·소스에 근거한 단계별 요약이다. 개별 대화의 시각은 복원하지 않았으며, 명시한 버전의 실행 근거를 함께 링크했다.

1. **자료·기획:** 사용자가 제공한 GitHub 5개와 첨부 자료 3개를 바탕으로 영아 부모를 위한 첫 한마디 흐름을 정의했다. 냥톡·멍톡과 유사한 제품, 영아 앱, 육아 기록 앱, 연구·모델의 권리와 적용 범위를 조사하고 PRD·시장/BM 문서를 작성했다.
2. **Android 기능:** Kotlin Compose·CameraX·MediaPipe/YAMNet으로 10초 녹음·카메라·영상 단서 → 보호자 확인 → 표현·수정·기록 흐름을 만들었다. ‘모아’라는 작업명에서 최종 표시 이름으로 변경했으며 기술 패키지 ID는 유지했다.
3. **디자인·홍보:** UI 위계와 흐름, 큰 텍스트, 귀여운 가족 콘셉트를 정했다. 부모 캐릭터를 여러 안으로 비교한 뒤 단순한 가족 B안을 선택했다. 아기 얼굴은 유지하고 옷을 수정했으며 자막 배경과 MVP 문구를 제거했다. 확정 영상 외의 시안을 정리하고 합성 응애·칭얼거림·웃음 효과음을 음악과 믹싱했다.
4. **입력 회귀·0.2.x:** 영상 오디오 추출, 오디오 트랙 없음·무음·손상·길이/크기 초과 처리, 권한·백그라운드·회전·프로세스 복구를 점검했다. CameraX 업데이트로 ELF 16KB 정렬을 확인했다. R8에서 MediaPipe protobuf/JNI가 깨지는 문제를 확인한 뒤 축소를 비활성화했다.
5. **BM·프라이버시:** 외부 아기 DB와 앱 로그인을 제외했다. 기본 기록·PNG 공유·JSON 보존과 앨범 PDF 구독을 중심으로 0.3을 설계했다. 과도한 하드 페이월, 부모 불안 조장과 출석 압박은 제외했다. 월 4,900원·3개월 12,900원은 가설로 표시했다.
6. **0.3 통합:** SQLite의 IO·Mutex·트랜잭션·legacy 이전, JSON 48MiB·10,000건·문자 토큰 제한과 충돌·중복 처리, CSV 수식 무력화를 구현했다. 무료 PNG와 월별 PDF의 세 표지, 300개 기록·300쪽 한도, 긴 한글·이모지의 페이지 나눔을 처리했다. Play Billing, 서명 캐시, 무상태 Node 검증기를 구현했다.
7. **0.3 결함 수정:** 후보 문장의 시작말 반복, 미래 시각의 import가 새 timestamp를 오염하는 문제, SAF 이용 중 프로세스 종료, 앨범 선택 유실·메모 터치·넓은 화면의 안전 여백을 수정했다. 서명 만료 시간·늦은 검증 응답·상품 조회 경합도 점검했다. 서버에는 본문·시간·동시성·중복 조회 제한을 적용했다.
8. **0.3 최종 QA:** Android 40/40, Node 16/16, UI 12유형, lint 오류 0·경고 24·힌트 2를 기록했다. 서명·ZIP·ELF·백업 제외 설정을 확인하고 앱 기록·공유 캐시·fixture·테스트 패키지·전용 emulator를 정리했다. [최종 보고](../outputs/Jigeum-QA-0.3.0.md)와 [Git에 보존한 계측 결과](qa/baseline-0.3.0/instrumentation-result.json)를 참고한다. 실제 Play 거래와 ARM 기기는 미검증 상태다.
9. **Git 기준:** 사용자 요청으로 비공개 `yw8837/jigeum`을 생성하고 `a693b98`을 커밋·푸시했다. APK/AAB/ZIP은 제외하고 모델·소스·선택한 홍보물·문서를 보존했으며 원격 SHA 일치를 확인했다.
10. **출시 가능 여부 명시:** 즉시 공개할 수 있다고 안내하지 않았다. 운영 연결·실구매·ARM·계정 인증·정책 URL·서명이 남아 있음을 설명했다. 사용자는 일부 무료 범위를 확정하고 전체 기능을 유료 이용권으로 완성해 달라고 요청했다.
11. **0.4 정책·검토:** 음성·수동 입력, 기록, 기본 공유와 백업은 무료로 두고 카메라·영상·PDF는 하나의 전체 이용권으로 묶는 정책을 정했다. 정책 문서·약관 초안을 갱신하고 복원·만료·화면 복원·콜백 경계를 검토했다. 이 정책 검토 시점에는 중앙 미디어 접근 제어와 UI를 아직 구현하지 않았으며 이후 13단계에서 진행했다.
12. **이번 협업 체크포인트:** 운영자명을 최용우로 확정했다. Play 계정의 신원 확인 대기와 앱 생성 잠금 상태를 다시 확인했다. gcloud 로그인은 돼 있지만 선택한 프로젝트는 없다. 결제의 현재 권한 확인 메서드와 내부 테스트 경계를 추가하고 계측 테스트 9개를 보강했다. 원본 참고 문서·마케팅 편집 입력·QA 결과를 Git에 옮겨 문서를 정리했다. 결과는 [체크포인트 QA](qa/handoff-checkpoint.md)에 있다.

13. **0.4 구현과 통합:** `f42238c` 협업 자료를 먼저 푸시한 뒤 사용자 요청대로 구현을 계속했다. 카메라·영상·PDF의 전체 이용권, 실제 실행 시 권한 재검사, 세션별 늦은 응답 차단, 초안·앨범 선택 보존, 기능별 이용권 안내와 약관을 반영했다. 기기 시계 되돌림으로 캐시 기한이 늘어나는 문제는 단조시간·부팅 횟수 검사로 보완했다. 0.4 빌드·Android 72계측·서버 16시험을 통과했으며 UI/정리의 최종 결과와 제한은 [0.4 QA](../outputs/Jigeum-QA-0.4.0.md)를 따른다. 원본 참고문서의 CRLF가 Git에서 정규화되는 문제도 `.gitattributes`로 고쳐 23개 manifest SHA를 Git 바이트와 일치시켰다.

## 다시 겪지 말아야 할 환경·하네스 실수

- 기본 Unicode AVD 경로에서 부팅이 멈췄다. 해당 환경에서는 영문 AVD 경로를 사용한다.
- DocumentsUI에서 가려진 배경의 Downloads를 클릭한 적이 있다. 열린 drawer에서 실제로 보이는 노드를 선택한다.
- `Save`와 실제 문구 `SAVE`, Compose의 `checked`와 `selected`를 구분한다.
- 보존된 스크롤 위치 때문에 화면 밖에 있는 제목을 기다리면서 UI 고장으로 오인하지 않는다.
- 이름이 같은 Python 모듈의 import 문제와 PowerShell 인용부호·UTF-8 문제는 별도로 진단한다.
- OMX clear의 성공 필드는 `cleared`이며, read에서 값이 없으면 `exists:false`다. 모든 명령을 일반적인 `success` 필드로 검사하지 않는다.
- 테스트 실패를 로그에서 지우지 않는다. 원인·수정·재실행 기록을 남긴다. 단순 빌드 성공이나 모의 거래로 출시 완료를 주장하지 않는다.

14. **0.4 최종 검증·압축 영상:** 중앙 viewport의 상태바 침범을 수정한 APK에서 72계측을 재통과했다. 서버 16개, 무료 UI 7유형과 패키지를 확인하고 합성 기록·fixture·테스트 패키지를 정리했다. 미니 영상은 다운로드 폴더의 사용자 지정 이름으로 저장했다. 실행별 범위·실패/수정·운영 미검증 사항은 [0.4 최종 보고서](../outputs/Jigeum-QA-0.4.0.md)에 보존한다.
