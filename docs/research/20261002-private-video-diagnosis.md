# 실사용 영상 인식 누락 — 진단과 개선안

2026-10-02 · 기준 소스 `70e1328` / 모델·판정 로직은 0.5.8과 동일.

## 요청과 이번 작업의 범위

사용자가 제공한 로컬 영상 3개로, 영상 가져오기에서 아기말이 생성되지 않는 현상을 재현하고 개선 방법을 조사했다. 결과 화면·저장 기능은 사용자가 정상 동작을 확인했다. `상상한 아기말`을 `예상한 아기말`로 바꾸고, 무료는 소리, 전체 이용권은 소리와 영상 근거를 사용하는 방향을 요청했다.

**이번 작업은 원인 조사·비교 실험·설계다. 모델 교체, 앱 문구 변경, 새 APK 배포 또는 Play 업데이트를 완료한 것이 아니다.** 시험을 실행하는 하네스의 통과와 아기 발성 인식 성공을 구분한다. 제공 영상만으로 독립적인 정확도·재현율을 계산하지 않는다.

원본·추출 프레임·PCM·개별 기록·해시는 Git에 넣지 않는다. 공개 서비스에 원본을 전송하지 않았다. 상세 실측과 임시 진단 소스는 Git 제외 `work/infant-feedback-20261002/`에 보관한다. 기존 Play beta22 산출물은 바꾸지 않았다.

## 재현 결과

- 3개 파일 모두 AAC 음성 트랙이 있다. 두 파일은 44.1 kHz stereo, 하나는 48 kHz stereo다.
- 기존 Android `SoundAnalyzer`와 `EvidenceInterpreter`에 5개 구간을 입력했다. 문제가 보고된 2개 영상의 앞/뒤 4구간은 모두 보류됐고, 울음이 담긴 비교 영상의 1구간은 울음 표현을 생성했다. 동일 입력 재실행에서도 같은 결과였다.
- `--strict`로 아기말 생성을 기대한 진단은 실패했다. 이 실패를 수정 완료로 바꾸거나 통계에서 제외하지 않는다. 기대 라벨은 사용자 보고에 따른 재현 가설이며 독립 청취로 확정한 정답이 아니다.
- 필터를 적용하지 않은 모델 출력도 같은 보류 결과였다. 현재 DC/80 Hz 필터만을 원인으로 지목할 수 없다.
- 2/4/8배 증폭(peak 0.98 상한으로 실제 gain 제한)과 250/500 ms 시작점 이동을 한 25개 변형에서도 실패 영상의 생성은 회복되지 않았다. 비교 영상은 울음 표현을 유지했다. 출력 성공은 감정·욕구의 정답이라는 뜻이 아니다.
- FFmpeg 기본 stereo→mono가 앱의 산술평균 downmix보다 약 3 dB 크게 나오는 것을 확인했다. `pan=mono|c0=0.5*c0+0.5*c1`로 맞춘 5개 기준과 25개 변형을 별도로 재실행했다. 실패 영상의 20개 변형은 모두 보류, 비교 영상의 5개 변형은 모두 울음이었다. FFmpeg 기본 결과를 Android와 완전히 같은 입력이라고 부르지 않는다.
- 별도 임시 Android 계측으로 MP4 → `VideoAudioDecoder` → 실제 모델 → `DeviceClipAnalyzer`를 실행했다. 최대 20초, 총 4개 선택 구간으로 첫 영상 전체를 겹쳐 살폈다. 첫 2개 영상은 여기에서도 보류됐고, 비교 영상은 울음을 생성했다. 첫 2개 영상의 PCM 길이·RMS는 같은 downmix의 독립 추출과 일치하거나 근접했다.
- 비교 영상은 오디오 PTS가 영상보다 14 ms 늦게 시작했다. 최초 진단의 임의 10 ms 길이 허용 assertion이 여기서 실패했다. 원문 실패를 보존하고 하네스를 길이·요청 sample 수를 기록하는 방식으로 바꿨다. 디코더를 수정하지 않았고 이 측정 완료를 모든 타임스탬프 경계의 검증으로 보고하지 않는다.

### 관찰과 아직 확정하지 않은 것

첫 실패 영상은 현재 모델에서 음악·일반 말소리 쪽 점수가 상대적으로 높았고, 아기 울음·웃음·옹알이 단서는 매우 낮았다. 다른 실패 영상은 소리 크기와 활동량이 작았고, 볼륨을 올려도 충분한 아기 후보가 나오지 않았다. 이는 **현재 모델의 발성 범위·해당 녹음 조건에 대한 약점이 주요 조사 대상**임을 보여 준다. 실제 발성의 화자·종류는 보호자의 시간 구간 확인과 독립 라벨링이 필요하다. 얼굴이 보인다는 사실만으로 그 구간의 소리가 아기의 소리임을 확정하지 않는다.

이번 결과로 확인한 개선 제한:

1. 단순 볼륨 증가로 이 두 영상이 해결된다는 가설은 지지되지 않았다.
2. 임계값을 조금 낮추면 해결된다는 근거도 없다. 아기 후보가 거의 없는 구간에서 낮추면 주변 말소리를 아기말로 만드는 위험을 평가해야 한다.
3. 시작점 250/500 ms 이동은 회복 효과가 없었다. 모든 중첩창·모든 짧은 발성에 효과가 없다는 일반화는 하지 않는다.
4. 영상이 읽히지 않는 현상과 소리를 아기 발성으로 분류하지 못하는 현상은 구분된다. 이번 실패 사례는 정상 PCM을 읽은 뒤에도 재현됐다.

## 유료 영상 분석의 실제 구현

`DeviceClipAnalyzer`는 소리 판정을 먼저 실행한다. 소리 판정이 보류되면 `inspectVideoEvidence` 호출 전에 반환한다.

소리가 승인되면 같은 구간의 최대 5장면에서 얼굴·입 열림을 관찰한다. `EvidenceInterpreter`에서 이 영상 결과는 근거 설명·관찰 상태에 추가되며, 문장 후보 선택에는 사용되지 않는다. 임시 계측에서 영상 관찰을 별도로 강제 실행하면 4개 구간 모두 얼굴을 찾았지만, 영상 근거를 전달해도 소리만 사용한 경우와 문장/보류 결과가 같았다.

따라서 현재 상태를 **‘영상으로 아기말의 의미를 보완하는 기능이 완성됐다’**고 소개하면 안 된다. 유료 화면의 시각 관찰 옵션과 실제 복합 해석을 구분해야 한다.

## 문구 계약 제안

`예상`은 현재 장면에 대한 가능성 표현으로 사용하고, 미래를 예측한다는 인상을 줄 수 있는 `예측`보다 우선한다.

| 실제 사용한 근거 | 결과·PNG·MP4 공통 문구 |
|---|---|
| 소리만 사용 | 소리를 바탕으로 예상한 아기말 |
| 소리와 영상 특징이 문장 결정에 실제로 사용됨 | 소리와 표정을 바탕으로 예상한 아기말 |
| 영상은 부가 관찰만 수행하는 현 구현 | 소리를 바탕으로 예상한 아기말 · 영상 관찰 포함 |
| 얼굴 없음·가려짐·시각 분석 실패 | 소리를 바탕으로 예상한 아기말 + 해당 관찰 제한 안내 |

결제 여부나 영상 파일의 존재만으로 문구를 선택하지 않는다. 실제 사용한 입력·분석 결과를 저장하고 카드와 공유 미디어에서도 같은 근거를 표시해야 한다. 사용자가 수정한 문장은 보호자 수정임을 구분할 필요가 있다. 기존 저장 미디어의 문구가 업데이트와 함께 자동 변경된다고 안내하지 않는다.

## 실행 가능한 개선 순서

### 1. 실패 원인 안내와 짧은 발성 탐색

- ‘아기 소리를 못 찾았어요’ 하나로 끝내지 않고 무음, 작은 소리, 주변 소리 우세, 발성 종류 불확실을 구분한다. 이를 위해 `SoundAnalysis`/`ClipAnalysisResult`에 구조화된 관찰 이유를 추가한다.
- 소리가 있는 후보 구간을 파형에서 추천하되, 일반 음성 활동 검출을 아기 신원 판정으로 사용하지 않는다. 보호자가 기존 양끝/통째 이동 편집을 유지할 수 있게 한다.
- 분석용 크기 보정은 clipping·잡음 증폭을 제한하며 원음 재생/저장에는 적용하지 않는다. 이번 2개 실패를 해결한 수단으로 소개하지 않는다.
- 결과 한마디를 만들 수 없어도 선택 장면을 보관하는 흐름을 검토한다. 무음 영상에 욕구 대사를 붙여 보류율을 낮추지 않는다.

### 2. 아기 발성 분류 개선 — 핵심 우선순위

1. 현재 YAMNet classification과 원본 YAMNet 표현을 같은 PCM·시간 구간에서 비교한다. 현재 asset은 FLOAT32 입출력/내부 INT8 변형이며 공식 `float32/latest`를 다시 받는 것은 새로운 모델 교체가 아니다. [기존 모델 내부 조사](20261002-sound-appropriateness.md)를 따른다.
2. 웃음·울음 외에 비정형 옹알이, 작은 발성, 끙끙거림, 높은 발성을 다루는 아기 발성 분류기를 비교한다. 발성 검출과 유형 분류를 나누고, 일반 말소리·음악·생활 소리·무음을 명시적 대조군으로 둔다.
3. 첫 경량 후보는 YAMNet 1,024차원 임베딩 + 작은 분류 head다. 현재 521개 최종 score를 다시 이름 붙이는 것은 추가 학습이 아니다. embedding을 출력하는 모델/변환 경로가 별도로 필요하다.
4. 아기 발성에 맞춘 wav2vec2/SpeechMaturity 계열을 오프라인 비교 후보로 둔다. 데이터·체크포인트 상용 허가와 접근 조건을 확인한 뒤 사용할 수 있다. 해당 모델을 지금 앱에 탑재하거나 실행한 것은 아니다.
5. 아기·가정·녹음 세션 단위로 학습/검증/최종평가를 분리한다. 이번 파일의 재인코딩·증폭·잘라내기는 독립 표본이 아니다. 증강 버전은 원본과 같은 split에 둔다.

무료도 같은 개선된 음성 분류를 사용한다. 유료 가치는 긴 구간과 실제 영상 보완으로 제공하며, 무료의 음성 인식 품질을 인위적으로 낮추지 않는다.

### 3. 실제 음성+영상 결합

- 소리 보류를 이유로 영상 관찰 자체를 건너뛰는 현재 순서를 재검토한다. 유료의 영상 관찰 결과를 얻은 뒤, 음성 단서를 보완할 수 있는지를 판정한다.
- 고정 5장면 대신 발성 전후의 짧은 시간대를 추가 관찰하는 실험을 먼저 한다. 얼굴 추적·입 움직임과 음성 활동의 시간 관계를 확인한다. 다중 인물·TV·부모 말소리·화면 밖 발성도 대조한다.
- 눈 감김, 입 열림, 입꼬리 변화 등 측정 가능한 특징과 실패 상태를 구조화한다. 표정 계수 하나를 곧바로 행복/슬픔/배고픔의 정답으로 쓰지 않는다. 영아 얼굴·각도·가림에서 별도 검증이 필요하다.
- 소리와 시각이 일치하면 해당 관찰을 반영한 문장군을 선택한다. 서로 충돌하면 어느 감정을 확정하지 않는 표현이나 관찰 제한을 낸다. 얼굴 검출만으로 소리의 주인을 확정하거나 음성 근거가 없는 한마디를 만들지 않는다.
- `ClipInterpretation`, 상태 복원, `Observation` 보관/가져오기, `ResultMomentCard`, `TranslatedMedia`에서 근거 출처를 끝까지 전달한다. 무료·유료·영상 실패·오프라인·기존 기록까지 같은 계약으로 QA한다.

## 새로 확인한 1차 자료

- [TensorFlow YAMNet transfer learning 공식 튜토리얼](https://www.tensorflow.org/tutorials/audio/transfer_learning_audio): 일반 사건 521종, 원본 0.96초 창/0.48초 간격, 1,024차원 임베딩을 이용한 작은 분류기의 학습·평가·내보내기 경로를 설명한다. 이 튜토리얼 자체는 아기 발성 성능 검증이 아니다.
- [YAMNet 공식 README](https://github.com/tensorflow/models/blob/master/research/audioset/yamnet/README.md): AudioSet 기반 모델·입력 처리·사건 분류 범위. 현재 Android 변형의 0.975초 관측 간격과 원본의 0.48초 간격을 혼용하지 않는다.
- [Employing self-supervised learning models for cross-linguistic child speech maturity classification, 2025](https://arxiv.org/html/2506.08999v1): 울음·웃음·canonical/non-canonical 발성·other 분류 연구.
