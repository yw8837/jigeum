# 발성 존재와 종류 불확실성 — 검증 계약

기준 e16f448 / beta37. 사용자 요청은 아기 발성이 들려도 전체 분석이 막히는 현상 개선이다.
정확한 종류를 정하지 못한 경우와 아기 발성 단서 자체가 없는 경우를 구분한다.

## 재현과 가설

- 보관 Android `mayra_context` 첫20초는 MIXED_VOCAL로 보류된다. 세 AST창의 두 presence head는
  모두 .99 이상이고 실제 YAMNet 울음 후보는 7800/15600ms에 .5/.668, RMS .00846/.00545다.
- 현재 AST Crying .307/.375, Baby cry .388의 종류 단서가 존재 보완까지 전역 차단한다.
- 가설: 같은 창에 영아 사건 후보가 있는데 상위 울음/웃음 종류 점수를 부재 근거로 사용하는
  정책 때문에 중립 발성 결과가 누락된다. 원문상 multilabel 점수는 배타적 확률이 아니다.
- 공개 파일 설명은 영아/아이 맥락이며 월령/사건 정답 미확정이다. 회복을 정답 증가로 세지 않는다.

## 허용하는 변경

1. 기존 성공 및 기존 unopposed 경로를 유지한다. 바뀌는 것은 audible YAMNet 후보가 있는
   `shouldCorroborate` 경로뿐이다. .35 후보/.80 양쪽head/.003 RMS/완전 AST창 검사를 유지한다.
2. AST 종류 충돌이 없는 **각 창**에서 두 presence head와 음량을 충족하고,
   같은 창 안의 실제 YAMNet 영아 후보도 기존 기준을 만족할 때만 그 넓은 창을 보존한다.
   다른 시간창의 근거·큰 음량을 빌리지 않는다. 충돌창의 종류 점수를 영아 근거로 쓰지 않는다.
3. 선택 전체의 Television/Screaming 차단은 유지한다. 다른 종류 충돌창은 결과에서 제외하고
   전체 보류 대신 **부분 관찰**로 명시한다. AST창은 겹칠 수 있어 남긴 범위가 깨끗하거나
   아기가 계속 발성했다는 뜻이 아니다. 정확한 시작/반복/다른화자·입술동기를 주장하지 않는다.
4. 모든 YAMNet 후보를 supported창이 감싸지 못할 때도 부분 관찰로 표시한다. 결측/NaN/역순/
   누락창/모델오류는 기존 처리 유지. 새 결과에 whole-scene 리듬·긴표현·시각추론을 붙이지 않는다.
   기존 전체 승인 경로의 결과는 유지한다. 출력은 kindUncertain 아기 발성이고 종류/욕구 미확정이다.
5. 모델·음성 필터·인식 임계값·외부전송·접근정책·추론횟수 변경 없음. 타이밍/속도 개선 주장 없음.

## 검증·출하 조건

- 실제 보관 실패를 현재 소스에서 먼저 red로 재현. 기존84정책 재생 결과와53실제 엔진 조건을 비교.
- 동일창/다른종류/무음/성인/배경/TV/비명·고점수 조작/취소/오류를 반례로 검사.
- 기존38개 정책 출력 및 실제28개 출력 보존, 성인·배경 대조 신규출력0. 추가출력은 개별 기록.
- 두 독립 Spec/Standards 검토, 서명판에서 실제 실패→결과/저장 경로, 업데이트 기록 보존.
- 통과할 때만 기존 Alpha 상위 버전 제출. 일반 인식률·욕구 정확도·S25 속도는 별도 미입증이다.
