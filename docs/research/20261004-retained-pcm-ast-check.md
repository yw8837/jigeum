# 보존 PCM의 고정 AST INT8·v2 추가 비교

작성: 2026-10-04 · 로컬 연구 결과 · 제품 변경 없음

## 판단

**기존 owner2와 다른 누락 원본의 보존 2구간에서는 AST 옹알이 보완이 0/2였다.** 두 구간 모두 고정 양성 조건에 미달했다. v2의 웃음·울음 충돌 가드를 완화해도 이번 실패가 해결되는 구조가 아니다. 같은 원본의 겹치는 두 구간이므로 독립 표본은 **1원본**이다.

`BabbleSupportPolicy.ENABLED=false`를 유지한다. 임계값·창·라벨을 바꾸거나 제품을 활성화할 근거가 추가되지 않았다. 새 영상이나 독립 라벨은 평가의 불확실성을 줄일 수 있지만, 현재 모델의 양성 조건 미달을 해결하는 구현은 아니다.

## 입력 범위와 중복 제외

[10월 2일 진단](20261002-private-video-diagnosis.md)에서 보관한 `matched-corpus`를 사용했다. 이 경로는 Android의 산술 평균 downmix와 맞춘 `pan=mono|c0=0.5*c0+0.5*c1` 기준이다. 기본 FFmpeg downmix를 사용했던 별도 `corpus`와 gain/shift 변형은 추론하지 않았다.

| 분류 | 원본 수 | 보존 기준 구간 | 처리 |
|---|---:|---:|---|
| 기존 owner2와 동일 | 1 | 2 | 원본 SHA256 일치로 제외, 새 추론 없음 |
| owner1/2/3와 다른 누락 원본 | 1 | 2 | 고정 INT8 신규 추론 2회 |
| 별도 기존 울음 비교 원본 | 1 | 1 | YAMNet 유지 정책 재생, AST 호출 제외 |
| 합계 | 3 | 5 | 신규 AST 대상은 1원본·2구간 |

- 5개 모두 manifest의 `applied_gain=1`, `shift_ms=0`, 저장 PCM SHA256과 결과 로그에 기록된 PCM SHA256의 일치, 바이트 정렬, 표본 수, 유한 float32, 진폭 범위를 확인했다.
- 16kHz·mono·little-endian float32는 당시 추출 계약에 따른다. 헤더 없는 `.f32` 바이트만으로 원래 샘플레이트나 MP4 대응을 새로 입증한 것은 아니다. 사라진 원본 MP4를 다시 해시하지 않았다.
- 신규 누락 원본은 시작 10초와 끝 10초의 기존 선택 그대로다. 두 구간은 약 2.83초 겹친다. 연결해 새 20초 선택을 만들지 않았다.
- owner2 제외는 **원본 단위 중복 제외**다. 끝부분의 기존 선택과 이전 AST 0–20초 창이 완전히 일치한다는 뜻은 아니다. 원본·창을 바꾼 반복을 독립 성공으로 세지 않기 위해 전체 원본을 제외했다.
- 남은 두 원본은 owner 입력 manifest 및 기존 AST 사례 목록과 대조했다. 이전 owner2의 FP32/INT8/Android 결과는 [고정 정책 결정](20261004-babble-fusion-decision.md)의 개발 회귀 결과로 남으며 이번 추가 성과에 합산하지 않는다.

## 실행과 실제 정책 적용

기존 로컬 ONNX Runtime **1.24.4**, CPU 4스레드, 고정 INT8 모델을 사용했다. 모델 SHA256은 `3dff0cc2b374977ae1460258261608e33428f4767a6959cb8bc910b09433f71e`이며 label config의 고정 SHA도 확인했다. 기존 `ondevice_ast_features.py`의 전처리를 그대로 사용했다. AST에는 gain·cleanup·정규화 변경 없이 원시 보존 PCM을 넣었다.

Python 네트워크 연결을 차단했다. 다운로드·설치·ADB·Gradle 실행·새 YAMNet 추론은 없었다. PCM/영상/이미지를 표시하거나 재생하지 않았고 외부 AI로 전송하지 않았다.

정책을 별도 Python 임계값 코드로 대체하지 않았다. 현재 `BabbleSupportPolicy.kt`, `SoundTimeline.kt`, `AudioCleanup.kt`를 그대로 복사하고, `SoundAnalyzer.kt`의 데이터 형식과 `cueLabel` 함수를 추출해 기존 로컬 Kotlin compiler JAR로 실행했다. Gradle을 호출하지 않았다. 소스 해시와 컴파일/실행 로그는 비공개 산출물에 남겼다.

적용 순서는 현재 소스와 같다.

1. PCM 형식 및 현재 cleanup 후 무음 기준을 확인한다.
2. 기존 YAMNet 결과로 현재 `SoundTimeline`의 수용/보류 및 `shouldAnalyze`를 재생한다.
3. 수용된 울음과 복합 발성·입력 오류·무음 등은 보완 대상에서 제외한다.
4. 대상에만 고정 INT8를 실행하고 전체 선택의 울음/웃음 계열·TV 차단과 창별 충돌 가드, 양성 기준을 실제 `attachCandidate`로 적용한다.

양성 기준은 Babbling ≥ .30, 또는 Babbling ≥ .10과 Child speech ≥ .30의 동시 충족이다. v2의 추가 웃음·울음 하위 라벨도 현재 소스대로 포함했다. 추론된 광범위 창을 실제 발성 시작·반복 횟수·연속 발성으로 해석하지 않았다.

## 결과 집계

| 항목 | 결과 |
|---|---:|
| 보존 baseline PCM 무결성 통과 | 5/5 |
| 신규 누락 구간 AST 실행 완료 | 2/2 |
| AST 양성 기준 충족 | 0/2 |
| AST 전체 선택 충돌 차단 해당 | 0/2 |
| AST 창별 감정 충돌 해당 | 0/2 |
| 실제 v2 부착된 보완 창 | 0/2 |
| 기존 울음 비교군 수용 유지 | 1/1 |
| 기존 울음 비교군 AST 실행 | 0회 |

신규 누락 구간은 두 재생 방식 모두 `INFANT_UNCONFIRMED`를 유지했다. 원시 YAMNet 타임라인 재생과 보존 필터 집계의 fallback 재생이 같은 결과를 보였다. 기존 울음은 양쪽 모두 `CRY` 수용을 유지했다. 이 숫자는 **정답률·민감도·특이도·새 사용자 성공률이 아니다**.

## 이전 결과와 현재 정책의 차이 및 한계

10월 2일 저장된 결과는 당시 0.5.8의 출력이다. 그때의 일반적인 보류 문구를 오늘의 `AnalysisIssue`로 직접 치환하지 않았다. 현재 소스에서 해당 이슈를 새로 계산했다.

보존 `sound-results.json`의 `frames`는 **비필터 PCM의 YAMNet 상세 프레임**이다. `cues`와 최종 결과는 당시 앱 필터 경로의 집계이며, 그 상세 프레임은 저장돼 있지 않다. 특히 신규 누락 두 구간의 필터 집계 cues는 비어 있다. 현재의 전체 분류 점수 보존·타임라인 정책을 이 빈 집계에서 복원할 수 없다. 따라서 필터 집계 재생은 결과 일관성 대조일 뿐 현재 앱 필터 경로와 동등하다는 증거가 아니다.

원시 프레임에 현재 cue 매핑을 적용한 재생은 현재 타임라인 규칙을 검사하지만, 현재 Android 디코더·필터·YAMNet까지 실행한 결과는 아니다. 이번 AST 창의 양성 미달 자체는 이 타임라인 복원 제한과 별개로 직접 측정됐다. 그러나 이를 현재 제품의 end-to-end 보류율로 확장하지 않는다.

독립 청취 정답은 없다. 옛 `user_reports_baby_vocalization` 표기는 재현 가설이며 실제 옹알이·발성 주인·욕구·감정의 정답이 아니다. 이번에는 새 원본 2개를 찾았지만, AST 보완을 검사한 누락 자료는 **1원본**뿐이다. 기존 울음 보존은 새 옹알이 회복 성과가 아니다.

## 제품에 적용할 결론과 다음 판단

- **현 후보를 활성화하지 않는다.** owner2 한 원본의 회복을 전체 누락 해결로 일반화할 수 없고, 이번 다른 원본은 같은 고정 후보로 회복되지 않았다.
- **충돌 가드 제거·threshold 완화·선택 구간 재탐색을 하지 않는다.** 두 구간 모두 양성 조건 미달이며 독립 정답도 없어, 이 자료를 보고 조건을 바꾸면 개발 자료에 맞춘 조정이 된다.
- **이 결과만으로 core 수정안을 제안할 근거는 없다.** 소리 종류 보조 모델은 장면에 맞는 감정·욕구 생성의 해결책까지 제공하지 않는다. 이 비교로 사용자 목표를 달성했다고 보고하지 않는다.
- 현재 후보의 no-go 판단에는 추가 영상이 필요하지 않다. 새 영상 요청을 해결 경로로 제시하지 않는다. 새로운 실행은 고정된 대체 후보나 재현된 구현 결함 등, 기존 실패를 바꿀 구체적인 근거가 생겼을 때만 의미가 있다.
- 향후 **다른 후보의 효과를 판단**하려면 출처가 분리된 사례의 청취 기반 소리 종류/시간 구간 정답과 아기·성인/TV 등 발성 주인 정보, 오류를 겨냥한 고정 비교 계획이 필요하다. 이는 평가 근거이며 모델 개선 자체가 아니다. 표본 수와 채택 기준은 별도 설계가 필요하다.
- 향후 **현재 Android 경로의 결과만 확인**하려면 같은 baseline PCM에 대한 현재 필터 YAMNet 전체 프레임 또는 원본을 통한 현재 디코더 실행 로그가 필요하다. 단순 재실행으로 이번 AST 양성 미달이 해결된다고 기대할 근거는 없다. 이번 작업에서는 요청하거나 실행하지 않았다.

## 비공개 재현 산출물

`work/retained-pcm-ast-check/`는 Git ignore 대상이다.

- `run.py`: 한 번 완료된 결과가 있으면 중복 추론을 막는 실행 스크립트.
- `input-audit-private.json`: 원본·PCM 해시, 선택 범위, 기준 조건, 중복 대응.
- `results-private.json`: 모델/정책 소스 해시, 현재 정책 전후 결과, 로컬 추론 실행 정보.
- `*-scores-private.npz`, `*-scores.tsv`: 개별 AST 점수. 공개 문서에 복사하지 않는다.
- `before-private.tsv`, `after-private.tsv`, `compile.log`, 복사된 Kotlin 및 JVM classes: 실제 정책 실행 근거.

제품 코드·기존 PCM·옛 결과·모델을 수정하지 않았다. 본 문서와 ignored 연구 산출물만 추가했다.
