# AST 보조 인식의 제한적 채택 기준 재검토

2026-10-04 · Astra/high 읽기 검토와 실제 기록 변화 감사에 따른 판단 보완.
새 모델 추론·제품 활성화·Play 배포를 완료했다는 문서가 아니다.

## 확인된 개선과 남은 실패

[변화 감사](20261004-ast-delta-audit.md)에서 약국 원본 한 개의 10초·20초 선택 모두
실제 Android 후보 경로의 `INFANT_UNCONFIRMED → BABBLE` 전환을 확인했다.
사용자가 알려 준 옹알이 개발 사례의 회복이며, 두 개의 독립 성공이나 일반 정확도가 아니다.
다른 보존 원본의 겹친 두 구간은 계속 보류됐다. 기존 울음 승인 한 구간은 유지됐다.

공개 11원본·30창은 AST 점수만 있고 같은 입력의 YAMNet baseline과 결합 판정이 없다.
따라서 새 오인 0건, 추가 승인 0건, 독립 회복 0건으로 계산할 수 없다. 변화는 미확인이다.
v1 점수 sweep과 v2의 실제 전후 판정도 합치지 않는다.

## 채택 판단 보완

신규 독립 양성에서 회복이 아직 입증되지 않았다는 이유만으로 알려진 약국 회복까지 무효화하지 않는다.
기존 승인·입력오류를 유지하는 제한적 보조 경로의 핵심 검토 대상은 **새로 승인하는 구간의 오인**과
**추가 처리 비용**이다. 다른 사례에서 계속된 보류는 개선 범위의 한계로 남긴다.

다음 검증은 고정 v2·동일 입력의 baseline/candidate 쌍을 확보하여 아래를 비교한다.

1. 추가 승인 구간에서 실제 아기 발성이 있는지, 성인 대화·TV·음악·무음·tone을 잘못 승인하는지 확인한다.
   모델 점수·파일 제목만으로 정답을 만들지 않고 정답이 불명확한 사례는 unknown으로 남긴다.
2. 이미 승인된 울음·웃음·혼합과 무음/디코딩 오류 처리가 유지되는지 확인한다.
3. ARM의 실제 실행 지연·메모리·취소/복구를 측정하고, 제품 통합 시 전체 처리 시간과 화면 반응을 검증한다.
   분리된 합성 측정과 에뮬레이터 결과만으로 모든 휴대폰의 성능을 보장하지 않는다.
4. 모델을 포함할 경우 배포 용량·ABI·업데이트 보존을 새 최종 패키지에서 확인한다.

위 검증을 통과하면 **검증된 범위의 옹알이 누락 완화**로 제한해 채택을 판단할 수 있다.
일반적인 아기 의도 정확도나 새로운 AV 문장 생성 기능을 완성했다는 주장으로 확대하지 않는다.
기존 결과에 맞춰 임계값·시작점·음량을 반복 조정하는 계획은 아니다.

## 현재 상태

제품의 `BabbleSupportPolicy.ENABLED=false`와 기본 패키지의 AST/ORT 제외는 유지한다.
평가 준비를 이어 갈 수 있으므로 독립 정답 부족을 전체 개발 중단 사유로 사용하지 않는다.
Gemma의 의미 품질·발열 실패와 소리/영상의 새 문장 생성 요구는 별도 미완료 과제다.
장면에 어울리는 감정·욕구 추측 목표를 일괄 금지하거나 단순 문장 풀 확대로 대체하지 않는다.

## 실제 paired 평가 후속

[Android33입력 비교](../qa/ondevice-av-generation/AST-PUBLIC-PAIRED-QA.md)에서 과거 AST-only11개를 포함한
같은 입력의 실제 baseline/candidate를 확보했다. 승인12/보류21 유지, 추가승인/손실0이며
합성 비아기5개·설명기반 공개 대조7개에서도 출력이 없었다. 정답12개나 일반 정확도를 뜻하지 않는다.
Astra/high 재검토는 이 위험 회귀 근거와 별도 약국 회복으로 제한적 채택 후보를 유지하는 것이 타당하다고 판단했다.
추가 양성 성공을 절대 기준으로 요구하지 않으며, 같은33개 재실행·임계값 변경을 권고하지 않는다.

현재 남은 구현은 기본 빌드의 noAst 대역을 실제 런타임으로 연결할 **명시적 통합 후보 패키징**과
실제 DeviceClipAnalyzer/제품 UI의20초·취소/복구·저장보존 검증이다. 연구모델 파일을 포함하지 않은 빌드에서
ENABLED만 켜는 변경은 회복을 만들지 못한다. ARM비용과 이 통합 결과를 함께 확인하고 제품 채택을 결정한다.
