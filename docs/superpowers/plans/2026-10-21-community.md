# 우리 아이 자랑 Implementation Plan

**Goal:** 익명 글/댓글·비밀번호 관리·좋아요·영상카드 게시판을 구현하고 Android와 연결한다.
**Architecture:** 전용 웹/서버, D1/R2 저장소, Android 명시적 카드 전달. 개인 기록은 기기에 유지한다.
**Spec:** ../specs/2026-10-21-community-design.md

## 작업과 검증

- [x] 서버/API: `outputs/Community`에 스키마·비밀번호 검증·형식/용량 제한·작성/조회/수정/삭제·좋아요·신고·차단·운영자 API. 잘못된 비밀번호, 중복 요청, 삭제 후 미디어와 익명 경계의 실제 DB 검사를 먼저 작성한다.
- [x] 웹: 단일 피드, 작성 미리보기, 댓글과 좋아요, 수정/삭제/신고/차단, 접근성·실패/재시도·정책 안내. 합성 미디어로 브라우저 검증한다.
- [x] 앱 개발판: `CommunityActivity.kt`와 URL/파일 경계, 홈 및 결과의 명시적 연결. 기존 저장과 분석 경로는 재사용하고 입력·결과 상태를 보존한다. 빌드/전용 기기 검증.
- [ ] 배포: 새 웹 전용 호스팅을 배포하고 운영자 권한/실제HTTPS/영속저장 확인, 앱 URL 설정. 공개 UGC 안내·Play 영향 확인 후 beta 패키지 준비. 실제 검토/제공 상태와 구현 완료를 구분한다.
- [ ] 문서/정리: HANDOFF/NEXT/QA 갱신, 합성 테스트 게시물과 소유 임시물 정리, 커밋·푸시 후 SHA와 clean 확인.

## 검토 초점

1. 공개 버튼 전 아기 자료가 네트워크로 전송되지 않는가.
2. 카드 렌더 실패/파일 선택 취소에도 기존 결과가 남는가.
3. 비밀번호와 토큰이 피드/로그/브라우저 공유 URL에 노출되지 않는가.
4. 다른 글·댓글에 대한 무권한 수정/삭제, 익명 요청의 운영자 사칭이 거부되는가.
5. 삭제/차단/운영자 숨김 뒤에도 오래된 미디어 URL로 계속 읽을 수 있는가.

- 2026-10-22: 서버/API·웹 익명 MVP와 품질 보완을 Sites버전3으로 baby.yeolmaeapps.kr에 제공.
  Node24, TypeScript, production build, 실제 도메인 JPEG/MP4 흐름 통과.
- Android 홈/결과 연결과 정확한 origin/명시적 카드 전달을 구현. debug 빌드 및 API35 4/4 통과.
  새 서명 beta·Play 제공과 소셜로그인·마이페이지는 미완료다.
- Google/Kakao·마이페이지는 이후 사용자 요청으로 추가된 목표다. 익명 사용은 계속 보존한다.
- 프로덕션 액세스 신청 접수와 웹 게시 완료는 별개다. 자세한 증거/남은 조건은
  [QA](../../qa/community-20261021/README.md), [NEXT](../../NEXT.md)를 따른다.

- 기존 Alpha39 제공 확인과 미배포 문구 확장을 보존한다. 기존 worktree 대신 원래 checkout/codex 브랜치 사용.
- 최신 사용자 ‘익명, 비번설정’으로 이메일 인증 제안 철회. 다른 서비스 Supabase 프로젝트는 변경하지 않는다.
