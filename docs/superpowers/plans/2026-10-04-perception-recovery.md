# 소리·영상 구간 인식 개선 — 2026-10-04

## 사용자 우선순위

- 핵심 분석·검토·개선·수정은 Astra/high. 그 이후 후속 조사·검증·배포는 Luna/Sol.
- 약국 옹알이 영상은 아기 소리가 주변 잡음보다 또렷하다. 현재 앱10초/20초 모두 아기 발성 미확정으로 보류한다. 잡음 원인을 미리 정하지 않는다.
- 선택한 구간의 연속 소리와 시간순 영상 변화를 함께 처리한다. 소수의 독립 정지 화면 판정으로 완료하지 않는다.
- 원본과 파생 자료는 로컬에서만 처리한다. 큰 모델 허용은 품질 조건부다. 원본 저장 기록, 접근 정책, 현재 베타는 유지한다.
- 사용자 추가 완료 기준: 검수·검토·분석·수정·QA 후 **기존 비공개 테스트 트랙 업데이트 배포와 실제 테스터 제공 상태 확인**까지 수행한다. APK 생성이나 검토 제출만으로 작업을 완료 처리하지 않는다. 공개 프로덕션·상품/실거래 보류는 유지한다.

## 작업과 소유권

1. **Astra/high — 핵심 코드 및 실제 로컬 실험:** tools/research 및 필요시 Android perception core. 기존 실험·고정 출력·독립 검토 수정19tests를 출발점으로 한다. 무의미한 문장 확대나 단일 영상에 맞춘 임계값 조정으로 완료하지 않는다.
2. **주 담당 — 증거/문서 조정:** 실패와 통과, PC/Android, 개발 사례/독립 평가를 구분한다. 다른 작업자의 코드를 덮어쓰지 않는다.
3. **Sol — 변경 후 검증/통합:** Astra의 실제 수정에 맞춘 재현·회귀·코드 검토. Gradle/ADB는 한 담당자만 사용한다.
4. **Luna — 필요시 범위가 좁은 읽기 전용 조사:** 자료 조회와 설정 확인. 미실행 모델을 완료 엔진으로 기록하지 않는다.

## 승인 기준

- [ ] 원음·PTS·채널·구간 길이의 입력 계약을 검증하고 실제 입력 누락과 모델 누락을 분리한다.
- [ ] 프레임별 나열을 강요하는 형식과 전체 구간 요약을 비교한다. 순서 반전·후반 변화·무음·tone·성인 말소리 대조를 포함한다.
- [ ] 뚜렷한 옹알이 누락을 재현하고 타당한 수정으로 회복하는지 확인한다. 이미 알려진 약국 사례는 개발용이며 독립 정확도 분모로 쓰지 않는다.
- [ ] 기존 앱 결과 영상은 자막/결과 재인식 진단으로만 사용한다.
- [ ] 원음과 필요시 잡음 처리본을 비교하여 약한 옹알이 제거·웃음/울음 뒤바뀜이 늘지 않는지 확인한다.
- [ ] 실행/관찰 품질/Android 지연·메모리·취소·오프라인 상태를 각각 판정한다. 부족하면 배포를 통과시키지 않는다.
- [ ] 검증된 수정본의 서명·업데이트·패키지 검사를 마친 뒤 Alpha 업로드·검토 제출·게시/테스터 제공 상태를 확인한다. [배포 준비와 현재 Console](../../release/20261004/PLAY-PREP.md).
- [ ] 소스·공개 증거 커밋/푸시 후 원격 SHA와 로컬 상태를 확인한다. 원본·모델·캐시·키는 커밋하지 않는다.
