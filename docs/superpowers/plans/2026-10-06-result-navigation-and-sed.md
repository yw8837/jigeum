# 결과 재분석 UX와 소형 인식 후보 적용 계획

기준: `363ea7c` / 사용자 annotation의 조사 적용·개발 우선순위·결과 후 다른 장면으로 이동 개선 요청.

## 완료 기준과 공통 제약

- 결과 화면에서 같은 영상의 다른 구간, 다른 파일, 새 촬영으로 가는 경로가 눈에 보이고 구별된다.
- 같은 영상의 다른 구간은 원본과 구간을 유지한 채 편집기로 돌아간다. 외부 picker 취소 때 기존 결과가 사라지지 않는다.
- 저장/앨범 내보내기 중 원본 삭제나 화면 이동 경쟁이 없다. 새 분석에서 이전 결과/메모가 섞이지 않는다.
- 무료/정식 이용권/beta 전체 접근, 무료 기존 기록·미디어 저장과 온디바이스 경계를 유지한다.
- 경쟁사 리뷰의 반복/입력 거절/탐색/결제 마찰을 현재 앱과 대조한다. 근거 없는 욕구나 임의 문장 변경을 추가하지 않는다.
- EfficientSED는 연구 경로에서 공식 mel·출력 일치와 Android 실행을 검증한다. 자료상 이득 없는 모델을 제품에 자동 편입하지 않는다.
- 무단 원본 업로드, 외부 아기 DB, 로그인, Elice 사용 금지. 사용자폰/기존 AVD/이전 삭제 거부 폴더를 변경하지 않는다.
- 메인만 Gradle/ADB 실행. 다른 작업자의 변경을 되돌리지 않는다. 새 변경 QA·두 축 리뷰·commit/push 후 승인된 비공개 beta 업데이트를 진행한다.

## Task 1 — 결과에서 다음 분석으로 이동

담당 파일: CaptureFlow.kt, 관련 새 Android UI 테스트. 필요 시 MainActivity.kt의 콜백만 협의.
명확한 다음 분석 영역을 결과 카드 가까이 두고 다른 구간/다른 파일/새 촬영을 제공한다.
Back, 긴 글자/작은 화면, 선택 취소, 저장 중, 미저장 문구 편집, 원본 수명·권한을 다룬다.
사용자가 이미 저장한 자료는 지우지 않는다. 회귀 테스트의 실제 결과·탐색 상태를 확인한다.

## Task 2 — EfficientSED Android 전처리 이식·비교

담당 파일: 연구용 순수 Kotlin frontend/harness, tools/research의 새 parity runner, 관련 연구 문서.
공식 preprocess.py/eval 연산을 재현: 16k mono, conv preemphasis [-.97,1], FFT512/win400/hop160,
nonperiodic Hann, center reflect, Kaldi128mel fmin0/fmax7000, log clamp1e-7, (x+4.5)/5, mel-major1000.
원본 mel 및 기존20.3MB ONNX출력을 무음/음/잡음/경계impulse/DC/작은음량/다중주파수에서 비교한다.
AST frontend를 바꾸지 않는다. 제품 sourceSets/weights/thresholds는 변경하지 않는다.
호스트 일치 후 메인에게 Android용 실행 경로·필요 파일을 인계한다.

## Task 3 — 통합 검증·배포

메인 담당: 버전·문서·QA 매트릭스, Gradle/ADB, 패키지/서명·업데이트 보존, Play 상태/제출.
구현별 검토 후 전체 diff를 Standards/Spec로 독립 검토한다. 수정에는 회귀 검증을 붙인다.
새 엔진 채택 근거가 부족하면 그 이유/실제 비교를 기록하고 검증된 UX를 beta로 배포한다.
게시·검토 제출·테스터 설치는 실제 확인한 상태로 구분해 보고한다.
