# 아가톡 — 최대 20초 온디바이스 소리·영상 해석과 문장 생성 설계안

작성일: 2026-10-03 (KST). 상태: **설계 검토안. 제품 코드·모델 교체·실행 성능 검증·새 배포 미완료.** 현재 기준본은 0.5.9-beta/code23이다.

## 1. 사용자가 확정한 목표

- 최대 20초의 소리와 영상에서 시간에 따른 변화를 함께 살펴보고, 해당 장면에 어울리는 아기말을 새로 생성한다.
- 미리 작성한 문장 후보를 늘리는 것만으로 이 요구를 완료 처리하지 않는다.
- **분석·문장 생성은 반드시 온디바이스.** 원본, 추출 음성·이미지, 임베딩, 분석 프롬프트를 외부 AI 서버에 보내지 않는다. 클라우드 자동 대체도 없다.
- 사용자 데이터와 기록은 로컬. 기존 로그인 없는 사용, 결제 검증, 저장한 결과의 무료 내보내기는 유지한다.
- 현재 무료 60초 촬영/10초 분석, 전체 120초 촬영/20초 분석을 유지한다. 무료는 음성, 전체는 소리와 영상. 베타는 전체 접근을 제공한다.
- 배고픔·졸림 등을 예측하려는 연구가 존재하지만, 일반 멀티모달 모델 채택을 아기 욕구 정확도 입증으로 표현하지 않는다.

## 2. 현재 문제와 성공 조건

현재 YAMNet은 일반 소리를 분류하고, 영상은 최대 5개 독립 IMAGE 표본으로 처리한다. 음성 보류는 문장 생성을 먼저 막는다. 문장은 소리·활동 패턴에 대응한 유한 후보 풀에서 선택한다. 제공된 일부 영상의 발성 누락은 아직 남아 있다.

새 경로는 **원음과 시간순 영상 표본을 같은 모델 문맥에서 처리**한다. 기존 YAMNet 결과는 보조 단서이며, 저점수 하나만으로 새 경로 실행을 차단하지 않는다. 결과는 관찰 근거, 시간 흐름, 장면에 맞춘 생성 문장으로 분리한다.

성공은 문장 종류 증가가 아니라 다음으로 판단한다.

1. 기존 실패 구간에서 실제 들리고 보이는 내용을 더 잘 반영한다.
2. 웃음→울음과 울음→웃음 등 순서를 바꾸면 관찰 순서와 표현도 그 차이를 반영한다.
3. 소리와 영상이 어긋나면 같은 아기의 같은 행동이라고 무조건 합치지 않는다.
4. 무음·성인만 등장·TV 대조군에서 근거 없는 아기 욕구를 만들지 않는다.
5. 10초와 20초의 실제 ARM 기기 지연·메모리·발열·취소 가능성이 사용 가능한 수준이다.
6. 네트워크를 끈 상태에서 모델 로드 후 분석·생성·저장·다시 보기가 동작한다.

## 3. 비교한 접근과 추천

| 접근 | 적합성 | 결정 |
|---|---|---|
| 기존 분류 + 작은 텍스트 전용 생성기 | 기존 분류가 놓친 소리·표정을 생성기가 직접 볼 수 없다. 반복 표현 개선은 가능하다. | 이번 핵심 요구의 완료 경로로 쓰지 않는다. |
| 모바일 소리·영상 입력 모델 + 앱 내부 근거 검사 | 원음과 시간순 이미지를 한 문맥에서 처리하고 한국어 문장을 생성할 수 있다. 모델 크기와 기기 성능 확인 필요. | **Gemma 4 E2B + LiteRT-LM을 첫 비교 후보로 추천.** |
| 더 큰 로컬 멀티모달 모델 | 품질 비교에는 유용할 수 있으나 모든 휴대폰의 실행 경로가 아니다. | E2B 결과가 부족할 때 E4B를 별도 비교. PC 실행만으로 Android 성공이라고 보고하지 않는다. |

외부 AI API는 사용자 확정 조건에 따라 제외한다. 더 작은 텍스트 모델로 기존 판정만 다시 말하게 만들고 ‘영상 흐름 이해’로 소개하지 않는다.

## 4. 확인한 모델·런타임

### 첫 후보

- 모델 저장소: `litert-community/gemma-4-E2B-it-litert-lm`
- 조회 revision: `b3ca0d2f076785a8f4b2219ddbd2bdb99954eae1`
- 파일: `gemma-4-E2B-it.litertlm`
- Hub 메타데이터 파일 크기: **2,588,147,712 bytes** (약 2.59 GB / 2.41 GiB). 다운로드·메모리 사용량을 혼동하지 않는다.
- Hub 선언 SHA-256: `181938105e0eefd105961417e8da75903eacda102c4fce9ce90f50b97139a63c`
- 공식 모델 카드와 Hub 표기: Apache-2.0, nongated. 파일을 내려받아 해시를 검사한 결과는 아직 아니다.
- 런타임: LiteRT-LM Android **0.17.1**, Git tag commit `5e58e9a0aef7abf7091207a8b1d1063a1c800f08`. Google Maven에서 버전 존재를 확인했다.

### 문서에서 확인한 범위

- Gemma 4 E2B/E4B는 이미지·소리 입력과 텍스트 출력을 지원한다. 공식 모델 카드는 소리 최대 30초, 영상은 1fps 기준 최대 60초를 설명한다.
- Kotlin API는 한 Contents 안에 ImageFile/ImageBytes와 AudioFile/AudioBytes를 넣는 예를 제공한다. maxNumImages, maxNumTokens, seed 설정과 cancelProcess가 있다.
- 모델 배포 카드의 지원 문맥은 최대 32K로 안내한다. 상위 모델 소개의 128K를 이 파일의 실행 설정에 그대로 사용하지 않는다.
- 공개 속도 표는 **텍스트 1,024 입력 토큰/256 출력 토큰, 문맥 2,048, 캐시 준비 상태**이며 로드 시간을 제외한다. 이 수치를 20초 아기 영상의 속도·메모리로 소개하지 않는다.
- 영상은 프레임 시퀀스로 처리한다. ‘통째로 이해’라는 제품 요구를 ‘모든 30fps 프레임을 처리’나 ‘연속 움직임을 완벽히 인식’했다는 뜻으로 바꾸지 않는다.
- Kotlin 예제가 있다는 것만으로 실제 모델 파일의 소리+다중 이미지 결합, 비언어 아기 발성 이해, 한국어 표현 품질이 검증된 것은 아니다.

## 5. 입력과 분석 흐름

1. 기존 구간 편집기로 고른 구간과 실제 이용권 상한을 실행 직전 확인한다.
2. 선택한 구간의 연속 원음을 로컬에서 16kHz mono로 디코딩한다. 선택 밖 정보는 모델에 넣지 않는다. 잡음 필터는 원음 대비 개선을 비교한 뒤 적용하며 작은 아기 소리를 없애는 전처리를 기본값으로 넣지 않는다.
3. 같은 구간에서 시간순 장면을 추출한다. 시작·중간·끝을 포함하고 실제 디코더 PTS를 기준으로 음성과 시점을 맞춘다. 초기 비교안은 1fps와 2fps이다. 20초의 2fps라면 약 40장으로, 실제 메모리·인식 차이를 측정한 뒤 고정한다.
4. 하나의 모델 요청에 원음, 시간표시가 있는 이미지 시퀀스, 한국어 출력 규칙을 넣는다. 몇 장의 요약문만 만든 뒤 텍스트 생성기에 넘기는 방식은 이 경로로 간주하지 않는다.
5. 먼저 관찰 사건과 순서, 불확실한 점을 구조화한다. 이어서 그 관찰에 맞는 1인칭 아기말을 생성한다. 한 번의 응답 안에 둘을 포함하는 방식부터 비교하여 불필요한 두 차례 추론 비용을 줄인다.
6. 앱에서 시간 범위·출처·형식·근거 없는 욕구 단정·반대 감정·텍스트 주입을 검사한다. 모델 출력의 자기확신 숫자를 정확도로 표시하지 않는다.
7. 결과 카드/PNG/MP4/기록에는 실제 생성 경로와 관찰 근거를 유지한다. 저장하지 않은 결과의 원음·영상 파생물은 작업 종료 시 정리한다.

### 표현 원칙

- 준비된 후보 중 선택하지 않고, 실제 관찰된 변화와 상호작용에 맞춰 한국어를 생성한다.
- 유료 20초는 발성·행동 변화가 충분할 때 그 흐름을 담는다. 침묵이 길다는 이유로 내용을 지어내지 않는다.
- 배고픔·졸림 표현은 울음 라벨만으로 붙이지 않는다. 영상·행동 맥락으로 추정하더라도 사실 관찰과 추정을 구분하고 정답처럼 확정하지 않는다. 약하게 단서를 붙인 표현이 실제 장면에 도움이 되는지도 별도 평가한다.
- 같은 모델·입력·설정은 고정 seed와 설정으로 의미를 안정시킨다. 다른 기기/가속기에서 글자 단위 동일성을 보장한다고 쓰지 않는다. 저장한 문장은 다시 생성하지 않고 그대로 재생한다.
- 결과가 안 나오거나 모델이 실행되지 않으면 명확하게 안내한다. 기존 템플릿을 새 모델 결과인 것처럼 자동 반환하지 않는다.

## 6. 온디바이스 경계와 설치 UX

- 최초 공개 모델 다운로드만 허용한다. 아기 자료 업로드나 원격 추론은 구현하지 않는다. 모델 다운로드와 기존 결제 확인 통신은 목적·코드 경로를 분리한다.
- 앱 첫 설치 시 2.59GB를 몰래 내려받지 않는다. 기기 지원/남은 용량 확인 후 크기와 Wi-Fi 권장을 안내하고 사용자가 다운로드를 시작한다.
- 고정 revision/크기/SHA를 검증한다. 중단된 파일은 완성 모델로 실행하지 않으며, 다운로드 재개·취소·저장공간 부족·손상 복구를 제공한다.
- 분석 프로세스에는 네트워크 요청 기능·외부 도구 호출을 제공하지 않는다. 모델 출력에 URL/도구 호출이 포함되어도 실행하지 않는다.
- SDK native ABI와 minSdk, GPU/CPU 지원은 AAR/실행 결과로 확정한다. 현 단계에서 모든 기존 Android 26+ 기기가 새 모델을 실행한다고 약속하지 않는다.
- 미지원 기기는 촬영·기존 기록·무료 내보내기를 보존하고 새 생성 기능의 미지원 상태를 표시한다. 이 경로에 대한 판매 설명은 지원 범위 확정 후 반영한다.
- 기존 서버·외부 DB·클라우드 정책을 새로 추가하지 않는다. 모델 다운로드에 관한 개인정보 안내와 저장공간 안내만 실제 구현에 맞춘다.

## 7. 구현 경계

| 구성 | 책임 |
|---|---|
| ModelStore | 고정 모델 manifest·다운로드·검증·설치·삭제, 사용자 미디어를 인자로 받지 않음 |
| DeviceCapability / LocalModelRuntime | 지원 여부·모델 로드·직렬 추론·메모리 회수·취소·시간 제한 |
| TemporalClipInput | 구간 내 연속 음성/실제 PTS 이미지/시간표시, 외부 I/O 없음 |
| OnDeviceClipInterpreter | 소리·영상 결합 요청, 구조화 응답·생성 문장, 모델·프롬프트 버전 |
| GroundedResultValidator | 형식·시간·출처·근거 일치 검사, 보류 이유와 실패 구분 |
| CaptureFlow / ResultMomentCard | 다운로드/분석/취소/결과 상태, 기존 UX·저장 연결 |
| ObservationStore / RecordTransfer | 기존 기록 보존, 새 생성 출처/버전 보존, 내보내기 호환성 |

저장 스키마는 새 provenance를 보존하도록 명시적으로 버전 이전한다. 기존 LEGACY/AUDIO/AUDIO_VISUAL/CAREGIVER 기록을 새 모델로 만든 결과라고 다시 표시하지 않는다. 새 네이티브 런타임과 기존 MediaPipe의 의존성/JNI 충돌은 통합 빌드에서 확인한다.

## 8. 검증 순서와 배포 차단 조건

### A. 실행 가능성 — 앱 기본 경로 교체 전

공개 모델을 로컬에서 내려받아 해시 확인 → 합성 음성/이미지 결합 입력 → 허용된 공개 샘플 → 사용자 제공 실패 구간의 로컬 비교 순서다. PC는 사전 비교 환경이고 최종 판단은 Android ARM에서 한다.

현재 호스트는 RAM 약 15.7GiB, Intel Iris Xe + RTX3050 Laptop 약 4GB다. 휴대폰 기종은 사용자에게 질문한 상태이며 실기기 성능은 아직 측정하지 않았다.

### B. 장면 적합성 — 정답을 출력문에서 역으로 만들지 않음

- 웃음/울음/옹알이/높은 발성/혼합/무음/성인/TV를 포함한다.
- 제공 원본 3개는 기존 실패 회복 사례로 사용하고 전체 정확도 평가 분모로 삼지 않는다.
- 같은 구간의 음성만/영상만/둘 다를 비교한다. 영상 순서 반전, 소리·영상 시차, 무관한 소리 교체로 양쪽 입력과 순서가 실제 결과에 영향을 주는지 검사한다.
- 반대 감정·없는 행동·근거 없는 욕구를 만드는 사례와 정상 입력을 전부 보류하는 사례 모두 실패다.
- 부모가 원본을 보고 장면 적합성을 평가한다. 기존 문장보다 다양한지와 실제로 더 어울리는지는 따로 기록한다. 현재 정확도 목표 숫자를 만들어 결과로 제시하지 않는다.

### C. 서비스 품질

- 10/20초, 초기/반복 로드, 연속 사용, 저메모리, 백그라운드 이동, 취소, 손상 입력, 앱 재시작을 확인한다.
- 지연·최대 메모리·발열·배터리는 실측한다. 잠정 UX 목표는 로드 완료 상태에서 10초 p95 30초 이내/20초 p95 60초 이내이며, **아직 성능 결과가 아니다.** 실제 지원 기기와 측정 표본을 명시해야 한다.
- 모델 설치 후 네트워크 차단 상태의 실제 생성과 통신 관찰을 확인한다. 결제 통신 여부와 아기 자료 유출 여부를 구분한다.
- 베타 전체 개방/정식 권한/기록 이전/PNG·MP4/PDF/내보내기 회귀를 다시 실행한다.
- 평가 전 Play에 기본 경로를 교체해 배포하지 않는다. 새 beta는 code24 이상을 사용하며 새 모델의 실기기 실행·장면 평가가 끝난 후에 준비한다.

## 9. 단계 상태

- 완료: 사용자 요구와 외부 전송 금지 확정, 현재 소스 분석, 공식 모델/SDK/API/배포 메타데이터 조사.
- 미완료: 설계안 검토, 모델 실다운로드와 실행, Android 통합, 영상 품질 비교, 실기기 QA, 새 패키징·배포.
- 이 문서는 새 분석이 구현됐거나 배고픔·졸림을 알아맞히게 됐다는 완료 보고가 아니다.
