# KOTA 공개 페이지·콘텐츠 1차 점검표

작성일: 2026-09-18  
대상: `https://ko-ta.co.kr/ko/`  
목적: 디자인 재제작보다 먼저 해결할 데이터·문구·탐색 품질 문제를 식별하고, 개발자가 재현·검증할 작업으로 분리한다.

## 1. 확인 범위와 한계

- 확인 자료: 홈페이지 열람 결과, 검색에 수집된 한국어·일본어 상세페이지 및 먹거리 목록, 사용자가 이번 대화에 올린 제주 목록 스크린샷.
- 수집 시점: 홈페이지와 일부 상세페이지는 당일 수집본, 다른 페이지는 2~6일 전 수집본이다. 검색 자료는 현재 배포 상태와 다를 수 있다.
- 상세 링크의 직접 열람에서 `Cache miss`가 반복되었다. 컨테이너는 대상 사이트뿐 아니라 일반 도메인도 DNS 해석이 되지 않았다. 이를 사이트 장애나 404로 판정하지 않았다.
- 실제 원격 브라우저에서 모바일 렌더링, 터치, 검색 입력, 필터 클릭, 로그인, 지도 권한, 리뷰 제출을 실행하지 못했다.
- 사이트 소스코드, 데이터베이스, 배포 설정, 원본 응답 헤더를 확인하지 않았다. 구현 원인은 가설과 검증 지시로만 제시한다.
- 사이트 수정, 데이터 삭제, 배포, 계정 생성, 리뷰 게시, 로그인 메일 발송은 하지 않았다.

상태 구분:

| 표시 | 의미 |
|---|---|
| 자료에서 확인 | 제공 화면 또는 수집된 본문·검색 제목에 해당 현상이 있다. 현재 배포본 재확인이 필요할 수 있다. |
| 중복 유력 | 서로 같은 행사로 보이지만 원천 ID·일정·장소·회차를 대조해야 확정할 수 있다. |
| 개선 제안 | 현재의 표시를 더 유용하게 만드는 제품·UX 제안이다. 런타임 오류로 판정한 것이 아니다. |
| 실기 미검증 | 아래 재현 테스트를 아직 실행하지 않았다. |

## 2. 유지할 강점

홈페이지의 주말·위치·테마·지역 진입점, 상세페이지의 요금·공식 채널·먹거리 메뉴와 가격은 유지할 가치가 있다. 산청 일본어 상세페이지에는 과거 먹거리 정보임을 밝히는 안내도 있다. 이미 있는 기능을 없다고 가정해 다시 만들지 않는다. 출처: S01, S03, S06.

## 3. 우선순위별 이슈

### KOTA-01 — 같은 행사의 중복 카드 후보

우선순위: P1 / 상태: 중복 유력

관찰: 제주 캡처 마지막 줄에 새연교 주말 문화공연의 이름이 약간 다른 카드 두 개가 나란히 있다. 하나는 대표 이미지가 없고, 다른 하나는 포스터가 있다. 먹거리 수집본에도 ‘영주 풍기인삼축제’와 ‘경북영주 풍기인삼축제’가 같은 10월 3~11일 일정으로 노출된다. 출처: S02, S10.

영향: 서로 다른 행사로 오인할 수 있고, 목록 수·추천·리뷰가 분리될 수 있다.

원인 확인: 원천 ID, 축제 연도/회차, 주최, 장소/좌표, 실제 운영일을 비교한다. 데이터 소스가 여러 개여서 생긴 현상인지, 같은 프로그램의 별도 회차인지 확인한다.

수정 방향: 내부 대표 행사 ID와 원천 레코드 ID를 분리한다. 표기 변형은 별칭으로 관리한다. 확실한 동일 행사만 병합하며 원천 정보는 보존한다. 제목이 유사하다는 이유만으로 자동 삭제하지 않는다. 기존 공개 URL이 있다면 대표 페이지로 연결하는 정책을 결정한다.

완료 기준: 동일 회차가 목록에 한 번 표시되고, 다른 연도·별도 회차는 유지되며, 포스터·리뷰·통계가 대표 행사에 정확히 연결된다.

### KOTA-02 — 실시간 인기처럼 읽히는 제목과 과거 데이터의 혼용

우선순위: P1 / 상태: 자료에서 확인 + 개선 제안

관찰: 홈 인기 섹션 제목은 현재의 관심도를 암시하지만, 카드에 제시된 근거는 이전 회차 개최지 방문객의 배수다. 상세페이지에서는 이전 회차 방문객 순위를 강조한다. 출처: S01, S03.

영향: 현재 조회수, 행사장 입장객, 개최지 유동인구, 이전 회차 지표가 같은 수치인 것처럼 읽힐 수 있다. 실제 정렬 로직과 배수의 정의는 확인하지 못했다.

수정 방향: 정렬의 실제 근거와 제목을 일치시킨다. 과거 데이터 기반이면 과거임을 제목에서도 명시한다. 현재 조회수 기반이라면 집계 기간과 그 사실을 표시하고 과거 방문객 수치와 분리한다. 배수에는 기준 연도, 비교 대상, 측정 지역, 출처, 산식 설명을 제공한다. 개최지 방문객을 입장객 실측치로 표현하지 않도록 정의를 확인한다.

완료 기준: 제목, 정렬 로직, 카드 지표가 같은 모집단·시간 기준을 설명하며, 사용자가 배수의 분모를 알 수 있다.

### KOTA-03 — 장기 운영 기간과 실제 행사일의 구분

우선순위: P1 / 상태: 표시 확인 + 개선 제안, 날짜 계산 버그는 미확정

관찰: 목포해상W쇼 홈 카드와 제주 캡처의 장기 운영 행사에는 넓은 기간, 진행 상태, 기간 중 일부 날짜라는 안내가 함께 있다. 안내가 이미 존재하므로 ‘예외 안내 없음’으로 보고하면 안 된다. 출처: S01, S10.

영향: 기간이 진행 중이라는 뜻이 오늘 공연/체험을 한다는 뜻으로 받아들여질 수 있다.

수정 방향: 전체 운영 기간, 실제 회차/운영일, 다음 확정 일정, 오늘의 운영 여부를 분리한다. 실제 회차를 모르면 ‘운영 기간 중 · 세부 일정 확인’처럼 불확실성을 유지한다. 오늘/주말 필터와 달력은 가능하면 실제 운영일로 계산한다. 알 수 없는 날짜를 생성해 채우지 않는다.

완료 기준: 실제 휴무일에는 ‘오늘 열림’으로 추천되지 않으며, 회차 미확인 상태가 명확하게 안내된다. 시간 계산은 행사 현지 시간대를 따른다.

### KOTA-04 — 일본어 페이지의 핵심 정보 번역 누락

우선순위: P1 / 상태: 자료에서 확인

관찰: 일본어 산청 상세페이지에 소개 본문이 한국어로 남아 있다. 일본어 부천 상세페이지에서는 요금 설명과 다수 메뉴명이 한국어로 남아 있다. 출처: S04, S06.

영향: 언어를 전환해도 실제 방문 결정을 위한 정보를 이해하기 어렵다.

수정 방향: 요금·예약·운영일·참여 제한 등 행동에 필요한 정보를 우선 번역한다. 행사명·상호·주소는 현지 언어 설명과 한국어 원문을 병기할 수 있다. 한국 지도앱에서 찾기 위한 원문 주소 복사 기능은 유지한다. 번역이 없으면 완료된 번역처럼 보이게 하지 말고 원문 제공 상태를 안내한다.

완료 기준: 일본어 사용자가 한국어를 읽지 않아도 주요 요금·예약·운영 안내를 이해한다. 원문 주소를 복사할 수 있다. 다른 지원 언어도 별도 표본 검사한다.

### KOTA-05 — 검색에 수집된 페이지 제목의 브랜드 중복

우선순위: P2 / 상태: 자료에서 확인

관찰: 부천국제만화축제, 부산국제항만컨퍼런스, 신촌글로벌대학문화축제 등의 수집 제목에서 KOTA가 두 번 반복된다. 출처: S03, S07, S08.

원인 가설: 개별 페이지 제목에 브랜드를 붙인 뒤 공통 메타데이터 템플릿이 다시 붙였을 수 있다. 실제 HTML을 확인하지 않았으므로 확정하지 않는다. 검색 엔진이 제목을 구성했을 가능성도 점검한다.

수정 방향: 브랜드 접미사를 한 곳에서만 붙이도록 원본 title·og:title·페이지 제목 생성 경로를 확인한다. 예: `부천국제만화축제 2026 | 일정·요금·위치 | KOTA`. 화면과 일치하는 정보만 사용한다.

완료 기준: 원본 HTML title의 브랜드는 한 번만 등장하고 언어별 제목이 해당 언어에 맞는다. 수정 후 검색 반영은 재수집을 기다려 확인한다. 참고: S11.

### KOTA-06 — 주변 추천에 여행 날짜 맥락이 부족함

우선순위: P2 / 상태: 자료에서 확인 + 개선 제안

관찰: 일본어 산청 상세의 본 행사 기간은 10월 2~11일이다. 주변 추천에는 10월 24일 시작하는 황매산 행사와 9월 12~13일 함양연암문화제가 함께 있다. 현재 추천 알고리즘을 확인한 것은 아니다. 출처: S06.

영향: 지리적으로 가까워도 같은 여행에 함께 방문할 수 없는 추천이 섞인다. ‘주변’이 공간만 뜻한다면 오류는 아니지만 여행 서비스의 효용은 떨어질 수 있다.

수정 방향: 사용자가 선택한 여행 날짜를 최우선으로, 없으면 본 행사와 겹치는 실제 운영일을 우선한다. 겹치지 않는 행사는 ‘다른 날짜의 주변 행사’로 구분한다. 후보가 없다고 날짜가 맞지 않는 행사를 같은 묶음으로 채우지 않는다.

완료 기준: 같은 여행 날짜의 추천과 다른 시기의 추천이 명확하게 구분된다. 반복 행사에 대해서는 전체 기간 겹침만으로 동시 개최를 판정하지 않는다.

### KOTA-07 — 포스터 미보유 카드의 반복 빈 화면

우선순위: P2 / 상태: 사용자 캡처에서 확인

관찰: 제주 캡처에서 여러 카드의 이미지 영역에 첫 글자와 연한 준비 안내만 표시된다. 출처: S10.

수정 방향: 사용자가 선택한 한국적 무문자 이미지 10종을 적용한다. 큰 한글 제목·홍보 문구는 넣지 않으며, 작은 KOTA 정도만 허용한다. 테마에 맞는 후보를 선택하고 행사 ID에 따라 고정해 새로고침 때마다 이미지가 바뀌지 않게 한다. 현재 회차 공식 이미지가 있으면 이를 우선한다. 과거 포스터는 연도 안내를 유지한다. 대표 이미지를 실제 현장 사진으로 오인하지 않도록 UI 설명 또는 접근 가능한 대체 설명을 마련한다.

에셋 제안: 카드 비율에 맞는 WebP/AVIF 파생본, 적절한 해상도, 명시적 이미지 크기를 준비한다. 원본 손실 없는 파일은 별도로 보존한다. 이미지가 없거나 로딩 실패한 경우 모두 대체 이미지로 안전하게 전환한다. 이 보고서에서는 파일 변환이나 사이트 반영을 하지 않았다.

완료 기준: 이미지 없음·외부 이미지 로딩 실패·대체 파일 실패에서 깨진 아이콘/무한 재시도가 없고 레이아웃이 흔들리지 않는다.

### KOTA-08 — 카드에서 날짜·지역의 가독성 및 정보 우선순위

우선순위: P2 / 상태: 사용자 캡처 기반 디자인 의견

관찰: 제주 캡처의 날짜·예외 설명이 작고 연한 반면, 모든 카드에서 긴 행정구역 표기가 반복된다. 명암 대비의 수치 측정은 하지 않았다. 출처: S10.

수정 방향: 목록에는 짧은 지역명과 읽기 쉬운 날짜를 쓰고, 상세에서 정식 주소를 제공한다. 제목 길이가 다른 카드의 날짜 기준선과 여백을 정리한다. 작게 줄여 넣는 방식보다 중요 정보의 대비와 구조를 우선한다. 변경 전후를 실제 모바일 폭과 글자 확대 환경에서 비교한다.

완료 기준: 긴 행사명과 긴 주소, 작은 모바일 폭에서도 제목·날짜·상태를 무리 없이 구별할 수 있다. 객관적인 접근성 적합 여부는 별도 측정한다. 참고: S12.

### KOTA-09 — 축제와 전문 행사 구분, 홈페이지 미등록 상태 처리

우선순위: P2 / 상태: 자료에서 확인 + 개선 제안

관찰: 부산국제항만컨퍼런스 상세는 축제 방문객 순위 체계에 들어가 있다. 해당 수집본의 공식 홈페이지 섹션에는 전화번호는 있지만 다른 상세에 있는 홈페이지 열기 링크는 보이지 않는다. 본문 추출 누락 여부 및 현재 UI 확인은 필요하다. 출처: S07.

수정 방향: 컨퍼런스·전시·공연·지역 축제 등 행사 유형과 일반 관람 가능 여부를 구분한다. 사전 등록·참가 자격을 확인하지 못했다면 임의로 ‘누구나 무료’로 채우지 않는다. 홈페이지 URL이 없을 때는 ‘주최 측 문의’와 전화 행동을 제공하는 등 제목과 실제 제공 정보를 일치시킨다.

완료 기준: 가족 나들이 검색과 전문 컨퍼런스 검색을 구분할 수 있고, 없는 홈페이지를 열도록 유도하는 UI가 없다.

### KOTA-10 — 방문객 순위보다 방문 결정 정보를 우선하는 상세 요약

우선순위: P2 / 상태: 개선 제안

근거: 부천 상세에는 방문객 순위, 소개, 사진, 먹거리, 위치, 기본 정보가 수집된다. 수집 순서는 실제 CSS 배치와 다를 수 있으므로 요금이 화면 맨 아래라고 단정하지 않는다. 출처: S03.

수정 방향: 첫 화면에 언제·어디서·비용·예약 필요 여부·오늘 운영 여부를 명확히 제시하고, 방문객 통계는 근거를 볼 수 있는 보조 정보로 배치하는 안을 검토한다. 신뢰 가능한 자료가 있을 때만 주차·대중교통·유모차·반려동물·우천 대응 정보를 추가한다. 미확인 값은 미확인으로 유지한다.

완료 기준: 사용자가 긴 소개문을 모두 읽지 않아도 일정과 방문 조건을 알 수 있다.

## 4. 버그로 확정하지 않은 항목

- 응답·검색 수집 시점에 따른 총 축제 수 차이: 최신 배포본과 동일 시점 API 응답을 대조하지 않았다.
- 날짜 배지: 며칠 전 수집본의 D-day/진행 상태를 오늘 날짜와 비교해 오류라고 판정하지 않았다.
- 지도 로딩 문구: 본문 수집 결과의 로딩 문구만으로 실제 지도가 무한 로딩한다고 판정하지 않았다.
- 메뉴/부스 개수: 수집 도구가 일부 항목만 노출했을 수 있으므로 합계 오류라고 판정하지 않았다.
- 직접 링크의 Cache miss: HTTP 404나 사용자 화면 장애가 확인된 것은 아니다.
- 상단 내비게이션 누락: 본문 추출에 없더라도 UI에 없는 것으로 단정하지 않았다.
- API 오류, 로그인 실패, 느린 성능, 취약한 권한, 잘못된 robots/sitemap: 측정하거나 재현하지 않았다.

## 6. 개발 순서 제안

1. 현재 배포본에서 KOTA-01~06을 재확인하고 원천 데이터/템플릿을 확인한다.
2. 중복 후보 병합 정책, 날짜·회차 모델, 인기 지표 정의를 먼저 정한다.
3. 번역 필수 필드와 제목 템플릿을 수정한다.
4. 날짜 맥락을 반영한 주변 추천, 대체 이미지, 카드 가독성을 정리한다.
5. 실기 테스트를 실행하고 재현 경로·전후 화면·측정 결과를 남긴다.

아직 재현하지 않은 런타임 문제는 실제 버그처럼 이슈 제목을 작성하지 않는다. 데이터 병합·삭제와 배포는 별도 검토 후 진행한다.
