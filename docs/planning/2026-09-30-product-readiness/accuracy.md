## 1 결론과 우선순위

정확도를 높일 수 있는 구체적인 작업이 있다. 가장 먼저 할 일은 **입 벌림 좌표 계산 수정, 소리 구간 보존, 화자 혼동 줄이기, 영상과 소리의 시간 맞추기**다. 그다음 한국어 가정환경의 독립 평가셋을 만들고, 같은 셋에서 현재 YAMNet과 영아용 전이학습 모델을 비교해야 한다. 모델 이름을 추가하는 것보다 이 순서가 현재 코드의 병목을 직접 해결한다.

권고 순서는 다음과 같다.

1. **P0 계산과 관찰 단위 수정**: 얼굴 좌표 종횡비, 전체 최대값만 남기는 오디오 집계, 영상·오디오의 서로 다른 분석 구간을 바로잡는다
2. **P1 정답과 시험 체계 확보**: 아이·가족·세션을 분리한 한국어 스마트폰 검증셋으로 현재 성능부터 측정한다
3. **P2 작은 영아 사건 분류기**: YAMNet 임베딩에 작은 분류기를 붙여 울음·웃음·비울음 발성·성인/배경 혼동을 개선한다
4. **P3 연구 모델 비교**: voc2vec와 최신 BabyHuBERT/VTC를 오프라인 비교 후보로 검토한다. 검증·권리·모바일 성능을 통과한 경우에만 경량화·탑재를 결정한다
5. **P4 얼굴 행동과 문장 연결**: 검증한 입 움직임·소리·보호자 맥락만 문장 선택에 반영한다

여기서 P0는 믿을 수 있는 관찰 단서를 만들기 위한 **개발 우선순위**다. 실제 아기 피해나 출시 안전 비상사태가 입증됐다는 뜻은 아니다.

이 문서는 조사 및 설계 결과다. **새 영아 데이터 수집, 모델 다운로드·학습, 실험 모델 실행, 앱 코드 변경은 하지 않았다.** 확인한 실행 증거는 아래 좌표 계산의 합성 수치 검산뿐이다. 따라서 현재 앱의 영아 정확도나 개선 폭을 숫자로 주장하지 않는다.

## 2 정확도를 무엇으로 나눠 측정할 것인가

하나의 ‘아기 분석 정확도’로 합치면 어디가 좋아졌는지 알 수 없다.

| 층 | 정답으로 삼을 것 | 예시 출력 | 별도 지표 |
|---|---|---|---|
| 입력 품질 | 무음·과도한 잡음·클리핑·가림·분석 실패 | 소리가 작음, 입이 가려짐 | 불량 입력 검출률, 정상 입력 과잉 거절률 |
| 소리 사건 | 독립 평가자가 실제 들은 사건과 구간 | 울음, 웃음, 비울음 발성 | 사건별 precision/recall/F1, 오탐/분 |
| 화자 유형 | 구분 가능한 아이·성인·중첩·매체 소리 | 아이 발성 후보, 화자 불명 | 성인→아이 오탐, 중첩 검출, 보류율 |
| 얼굴 관찰 | 화면에서 보이는 위치·입 열림·움직임 | 입이 벌어짐, 입 움직임 | 검출 실패, 좌표 오차, 사건 F1 |
| 보호자 맥락 | 보호자가 입력한 상황 | 놀이 중, 수유 후 | 입력 일치, 질문 부담, 맥락별 효용 |
| 표현 품질 | 확인된 관찰·맥락과 문장의 부합 | 해당 장면의 기록 후보 | 사실 불일치, 수정 시간, 저장 의향 |

‘배가 고프다’, ‘외롭다’, ‘졸리다’는 앞의 관찰 라벨과 다른 가설이다. 보호자가 그렇게 추정했다는 것과 실제 원인이 입증됐다는 것도 다르다. 예를 들어 수유 뒤 울음이 멎어도 수유·안기·시간 경과가 함께 변했다면 원인을 하나로 확정할 수 없다. 이번 개발 목표는 **관찰 사건의 정확도와 기록 도움을 개선하는 것**으로 잡고, 원인·발달·건강 판정은 별도의 연구 질문으로 남긴다.

## 3 최신 코드에서 확인한 개선 지점

### 3.1 입 벌림 비율이 프레임 종횡비의 영향을 받는다

현재 실시간 카메라와 저장영상은 랜드마크 13·14 사이 거리와 61·291 사이 거리의 비율이 0.12를 넘으면 입이 벌어졌다고 본다. 그런데 x와 y를 서로 다른 축의 정규화 좌표 그대로 계산한다. 공식 API에서 x는 영상 너비, y는 영상 높이로 각각 정규화된다. 따라서 같은 얼굴이라도 프레임 가로세로비가 달라지면 비율이 달라질 수 있다. [카메라 계산 L362–381](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/CameraScan.kt#L362-L381), [영상 계산 L350–359](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/VideoImport.kt#L350-L359), [NormalizedLandmark 좌표 정의](https://developers.google.com/edge/api/mediapipe/java/com/google/mediapipe/tasks/components/containers/NormalizedLandmark)

합성 좌표로 직접 검산한 결과는 다음과 같다. 실제 얼굴 추론 시험이 아니라 수학적 회귀 사례다.

| 입력 프레임 | 동일한 입 너비 100px와 높이 10px | 현재 정규화 좌표 비율 | 현재 0.12 판정 | 픽셀 축 보정 후 비율 |
|---|---:|---:|---|---:|
| 1000×1000 | 0.10 | 0.1000 | 닫힘 | 0.10 |
| 1600×900 | 0.10 | 0.1778 | 열림 | 0.10 |
| 900×1600 | 0.10 | 0.0563 | 닫힘 | 0.10 |

**수정 명세**: 거리 계산 전에 x 차이에 실제 추론 입력 너비 W, y 차이에 높이 H를 곱한다. 회전 후 실제 비트맵 크기를 사용하고 카메라·영상에 같은 함수를 적용한다. 이 수정은 원근·고개 회전·가림까지 해결하지는 않는다. 0.12 자체도 영아에서 검증된 문턱이 아니므로 보정 후 개발셋에서 다시 정한다.

정확한 식은 d(i,j) = hypot((x_i−x_j)×W, (y_i−y_j)×H), r = d(13,14) / d(61,291)이다. W·H는 **해당 결과를 만든 MPImage에 실제 전달한 upright/scaled 비트맵**의 크기다. 원본 동영상 metadata, PreviewView 크기, MediaPipe 내부 tensor 크기를 대신 넣지 않는다.

- 카메라: `toUprightBitmap()` 반환 비트맵의 width·height를 결과와 함께 보존한다. 90/270도에서 바뀐 축을 반영한다
- 저장영상: `BitmapImageBuilder(scaled)`에 넘긴 scaled 비트맵의 실제 width·height를 쓴다. 요청 크기 512×512가 실제 반환 크기라고 가정하지 않는다
- 앱이 별도로 균일 축소·letterbox·crop을 했다면 그 좌표계와 변환을 기록한다. 균일 축소와 평행이동·회전·반사는 거리 비율을 보존한다
- 비균일 강제 resize는 피한다. 외부에서 적용했다면 관찰 좌표에 역변환을 적용해 공통 픽셀 좌표계로 되돌린다. 내부 MediaPipe crop/letterbox까지 중복 역보정하지 않는다
- 화면의 미러링과 추론 입력 미러링을 구분한다. 비율 자체는 반사에 불변이어야 한다
- 분모 0·비정상 좌표·가려진 입은 보류한다. 원래 정규화 폭 기준 0.001을 단위 변경 후 그대로 재사용하지 않는다

회귀 시험은 비율 0.10·0.20, 가로/세로/정사각, 0/90/180/270도 회전, 균일 축소, letterbox, crop, 미러링, 0분모·NaN을 포함한다. 이번에는 아래 부록의 8개 기하 불변 사례를 실제 검산했다. Android 이미지 변환·실제 모델·경계값 검증은 아직 하지 않았다.

### 3.2 소리 후보가 시점과 지속시간을 잃는다

SoundAnalyzer는 상위 20개 결과를 받은 뒤 이름에 baby cry/infant cry, laughter/giggle, babbl, speech가 있는 항목만 남긴다. 모든 구간을 평탄화하고 같은 한국어 라벨의 **최대 점수**를 취해 0.20 이상인 상위 3개를 반환한다. 이 과정에서 사건 시점·길이·반복·동시에 난 소리가 사라진다. 일반 laughter와 baby laughter도 하나로 합쳐져 보호자 웃음이 아이 웃음처럼 보일 수 있다. 이는 실제 오탐률 측정이 아니라 코드상 가능한 실패 경로다. [SoundAnalyzer L106–141](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/SoundAnalyzer.kt#L106-L141)

**수정 명세**:

- `timestampMs`, 구간 길이, 원래 class ID/라벨, raw score를 보존한다
- 문자열 부분 일치 대신 모델 버전과 연결된 명시적 클래스 매핑을 둔다
- 전체 521개 점수 또는 목표 사건과 중요한 혼동 클래스가 포함된 고정 집합을 유지한다. ‘아이 후보만’ 남겨 성인·TV·음악이라는 반증을 없애지 않는다
- 최대값, 평균, 연속 지속시간, 상위 구간 평균을 개발셋에서 비교한다. 평균으로 바꾸는 것만 정답으로 취급하지 않는다. 짧은 웃음은 전체 평균에 묻힐 수 있다
- 울음·웃음·발성이 바뀌거나 겹치면 복수 사건을 허용한다. 무조건 1등을 정답처럼 선택하지 않는다

MediaPipe는 구간별 timestamp를 제공하고 결과 수 제한도 조정할 수 있다. YAMNet 일반 모델의 프레임은 0.96초, 이동 간격은 0.48초다. 실제 탑재 TFLite의 출력 경계는 고정 모델의 메타데이터와 회귀 시험으로 확인한다. [AudioClassifier Android 공식 안내](https://developers.google.com/edge/mediapipe/solutions/audio/audio_classifier/android), [YAMNet 전이학습 안내](https://www.tensorflow.org/tutorials/audio/transfer_learning_audio)

### 3.3 영상과 소리가 같은 순간을 가리키지 않을 수 있다

영상 소리는 첫 10초만 분석한다. 얼굴은 전체 영상에서 최대 5개 시점을 골라 가장 가까운 키프레임을 검사하며, 입 열림이 한 프레임이라도 있으면 전체 결과에 반영한다. 예를 들어 30초 영상의 얼굴 요청 시점은 5·10·15·20·25초이고 소리는 0~10초다. 나머지 장면의 입 움직임을 처음 소리와 연결할 근거는 없다. 키프레임 요청은 실제로 서로 다른 프레임을 반환한다는 보장도 따로 검증해야 한다. 현재 문장 엔진은 이들을 학습된 멀티모달 모델로 결합하지 않는다. [VideoAudioDecoder](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/VideoAudioDecoder.kt), [VideoImport L308–359](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/VideoImport.kt#L308-L359)

**수정 명세**: 먼저 현재 첫 10초 정책 안에서 오디오 사건 구간과 영상 샘플 구간을 맞춘다. 최대 5개 프레임의 ‘장면 요약’과 짧은 연속 구간의 ‘입 움직임’을 분리한다. 움직임 기능에는 실제 presentation timestamp를 보존하는 디코더와 연속 프레임이 필요하다. 더 긴 영상 전체 분석이나 구간 선택 UI는 별도 범위로 결정한다. 얼굴 미검출 때문에 화면 밖 아이의 울음까지 버리지는 않는다.

### 3.4 음성 전처리와 품질 기준이 입력 경로마다 다르다

직접 녹음은 16kHz mono PCM이고 1초 미만만 거른다. 저장영상은 16kHz로 직접 선형 보간하며 RMS 0.003 미만을 무음으로 판정한다. 리샘플러에는 명시적인 저역통과 필터가 없다. 고샘플레이트 오디오를 내릴 때의 aliasing, 채널 평균으로 인한 상쇄, 기기별 자동 이득·소음억제 영향은 검증 대상이다. 현재 정보로 실제 저하 폭을 단정할 수는 없다. [캡처·분석](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/SoundAnalyzer.kt), [리샘플러](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/VideoAudioDecoder.kt)

**수정 명세**: 공통 품질 검사와 전처리 계약을 만들고 16/44.1/48kHz, mono/stereo, PCM16/float, 조용한 발성·클리핑·반대 위상 사례를 시험한다. anti-aliasing을 갖춘 표준 변환을 비교한다. 강한 denoise나 성인 음성 VAD는 기본 적용하지 않는다. 영아의 약한 발성·고음이 없어지는지 원본과 짝지어 확인한다.

### 3.5 얼굴을 찾았다는 사실은 아이를 찾았다는 뜻이 아니다

두 경로 모두 `numFaces=1`의 첫 얼굴을 쓴다. 아이·보호자가 같이 있으면 누구를 관찰했는지 검증할 구조가 없다. 실시간 처리는 약 180ms 간격이고 결과를 바로 상태로 바꾸며, 앱 차원의 연속 프레임 확인·히스테리시스는 없다. [CameraScan L319–383](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/CameraScan.kt#L319-L383)

**수정 명세**: ‘얼굴’이라는 현재 표현을 유지하면서 사용자가 관찰 영역을 지정하거나 아이만 화면에 두도록 한다. 여러 얼굴 검출을 도입한다면 타깃 불명 상태를 추가하고 평활화 동작도 재검증한다. 얼굴 인식용 신원 저장은 필요하지 않다. 입 관찰은 크기·가림·고개 각도·추적 안정성을 통과할 때만 내보내고, 미검출·가림·입 닫힘을 서로 다른 상태로 기록한다.

### 3.6 보호자 확인과 모델 출력을 섞지 않아야 개선량이 보인다

직접 녹음에서는 0.50 이상인 울음/웃음만 미리 추천하지만 사용자가 다시 확인해야 한다. 저장영상은 남은 첫 후보를 확인 버튼에 제시한다. PhraseEngine의 실제 후보 함수는 소리·상황·세션 ID를 받고 5×6 조합에서 문장을 고른다. 얼굴 동작이나 메모가 학습된 의미 추론에 쓰이는 구조는 아니다. [음성 추천 L632–653](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/MainActivity.kt#L632-L653), [영상 추천 L200–215](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/VideoImport.kt#L200-L215), [PhraseEngine](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/PhraseEngine.kt)

0.20과 0.50은 현재 코드의 문턱이며 영아 성능 보정 결과로 확인되지 않았다. 보호자가 수정한 최종 라벨의 정답률을 모델 정확도로 집계하지 않는다.

**일반 클래스가 아이 표현으로 이어지는 경로**도 확인했다. 다음은 입력된 클래스 이름에 현재 코드의 매핑을 적용한 정적 결과이며, 모델이 실제로 아래 점수를 냈다는 뜻은 아니다.

| 원래 클래스 이름 | 현재 남는 단서 | 다음 단계 |
|---|---|---|
| Laughter / Giggle / Baby laughter | 모두 ‘웃음’ | 직접 녹음에서 1위·0.50 이상이면 웃음 미리 추천. 일반 웃음과 아기 웃음의 구분 소실 |
| Babbling | ‘옹알이 후보’ | 직접 녹음은 자동 선택하지 않음. 영상에서는 보호자 확인 버튼 후보로 사용 |
| Speech / Child speech, kid speaking / Speech synthesizer | ‘말소리(화자 미확인)’ | 직접 녹음에서 울음·웃음으로 자동 선택하지 않음 |
| Baby cry, infant cry | ‘울음’ | 일반 울음 전체를 매핑한 것은 아님 |
| Crying, sobbing | 제외 | generic crying을 곧바로 아기 울음으로 옮기지는 않음 |

예를 들어 일반 Laughter 점수 0.65가 한 구간에만 있고 Baby laughter 근거가 없어도 집계 뒤 ‘웃음’ 0.65가 남을 수 있다. 보호자가 이를 확인하면 PhraseEngine의 아이 1인칭 문장으로 이어진다. **현재 부모 확인 단계를 건너뛰어 자동으로 아이 의도를 확정하는 흐름은 아니다.** 그러나 추천의 출처가 합쳐져 보호자가 판단할 정보는 줄어든다. ‘일반 웃음 소리, 화자 미확인’과 ‘아기 웃음 후보’를 구분하고, 최종 ‘아이 소리로 확인’은 별도의 provenance로 남기는 것이 적절하다. [매핑·집계](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/SoundAnalyzer.kt#L121-L137), [확인 UI](https://github.com/yw8837/jigeum/blob/f83887c/outputs/MoaAndroid/app/src/main/java/com/moa/babylanguage/MainActivity.kt#L856-L876)

### 4.1 InfantNet에서 가져올 것

핵심은 작은 CNN으로 구분 가능한 과제부터 단계화한 점이다. 논문은 아이/성인 94.12%·97.01%, canonical/non-canonical 76.17%·77.03%를 보고하지만 이는 서로 다른 과제와 모델이다. 웃음과 울음은 같은 상위 범주로 합친 시험도 있어 지금 앱의 3사건 분류 정확도로 읽을 수 없다. 기본 시험은 같은 15가족에서 나눈 자료이며, 별도 가족 제외 시험에서는 최대 3% 하락을 보고한다. **아이 독립 평가가 아예 없다고 평가해서도 안 되지만, 15가족의 연구를 한국어 스마트폰 제품 성능으로 가져와서도 안 된다.** [원문 표2·일반화 절](https://arxiv.org/pdf/2005.12412)

적용안은 ‘아이/성인→울음·웃음·비울음 발성’의 계층형 실험이다. 첫 단계를 하드 게이트로 잘못 막으면 영아 발성을 모두 잃으므로 end-to-end 사건 성능도 함께 평가한다. canonical babbling을 발달 판정 기능으로 바로 연결하지 않는다.

### 4.2 voc2vec의 높은 전체 정확도를 그대로 믿으면 안 되는 이유

원논문 Donate-a-Cry 시험의 voc2vec-ls는 Accuracy 0.793, UAR 0.378, macro-F1 0.311이다. 전체 정답률만 보면 소수 범주의 약점이 가려진다. 10-fold CV를 했다는 설명만으로 아이·가족 독립 분할이 보장되지는 않는다. 최신 저장소는 2025년 4월 HuBERT 기반 변형도 추가했으므로 2025년 2월 논문 수치를 최신 가중치에 그대로 붙이지 않는다. [논문 표4](https://arxiv.org/html/2502.16298v1), [최신 모델 설명](https://github.com/koudounasalkis/voc2vec)

적용안은 권리 검토 후 **고정 임베딩+같은 작은 분류기**로 YAMNet과 비교하는 것이다. 먼저 전체 대형 모델을 휴대폰에 넣거나 125시간 사전학습을 재현할 필요는 없다. 성능 이득이 확인되면 교사 모델·증류 후보로 검토하되 증류도 원 모델과 데이터의 사용 조건을 확인한다.

### 4.3 VTC와 BabyHuBERT는 화자 혼동에 더 직접적이다

2020 VTC는 10언어·260시간의 아동 중심 자료로 누가 언제 발성했는지를 다뤘다. 2026년 6월 개정 BabyHuBERT는 40개 이상 언어의 13,000시간 자료에서 학습했다고 보고한다. 최신 VTC 저장소의 2.2 평균 F1은 68.3, key-child F1은 68.5로 표시되어 있다. 평균 하나가 영아 사건의 정답률인 것은 아니다. 아이에게 부착한 마이크라는 조건 때문에 부모가 손에 든 전화와도 다르다. [2020 원논문 소개](https://www.isca-archive.org/interspeech_2020/lavechin20_interspeech.html), [BabyHuBERT v3](https://arxiv.org/html/2509.15001v3), [VTC 결과](https://github.com/LAAC-LSCP/VTC#3-model-performance)

2025 VTC 연구는 구조·표현 변경보다 데이터 적합성과 양에서 더 큰 개선을 얻었다고 보고한다. 이는 지금 앱에서도 동일한 결과를 보장하지 않지만 한국어 가정·스마트폰 평가를 먼저 확보할 이유가 된다. [2025 연구](https://arxiv.org/html/2506.11074v1)

### 4.4 얼굴 모델은 좌표와 행동을 따로 평가한다

InfAnFace에서는 기본 HRNet의 영아 테스트 NME가 12.82에서 영아 맞춤 모델 5.30으로, 실패율이 22.5%에서 2.5%로 바뀌었다. 이 수치는 해당 68점 랜드마크 데이터의 결과이며 MediaPipe 478점 성능이나 감정 정확도가 아니다. 회전 증강·영아 도메인 미세조정·어려운 자세별 분석이라는 방법을 참고한다. [InfAnFace 원문](https://arxiv.org/html/2110.08935v3)

Infant AFAR는 공통 AU4·6·12·20 등을 다뤘고 데이터 간 일반화 시험을 별도로 했다. AU 발생은 관찰 가능한 얼굴 행동이므로 감정 이름보다 직접적인 검증 단위다. 다만 얼굴 행동 하나에 ‘배고픔’ 같은 의도 라벨을 붙일 근거를 제공하는 것은 아니다. [Infant AFAR 원문](https://pmc.ncbi.nlm.nih.gov/articles/PMC9646921/)

### 4.5 한국어 자료의 연령과 접근 조건을 수정해서 기록한다

Ko 소개 페이지의 초기 발화 평균은 13개월이지만 원논문 표1의 공개집단은 **14개월**이다. 공개 말이전 집단 10명은 6개월2일~9개월23일, 초기발화 10명은 12개월15일~16개월3일이다. 10~11개월과 17~18개월을 채우지 못한다. 가정처럼 꾸민 실험실이며, 엄마와 아기의 착용 마이크를 합친 stereo 자료라는 점도 스마트폰과 다르다. 과도한 울음 때문에 원자료 한 녹음을 제외했으므로 울음 평가셋의 대표성에도 주의한다. [공식 소개](https://talkbank.org/childes/access/EastAsian/Korean/Ko.html), [원논문 표1·방법](https://talkbank.org/childes/access/EastAsian/0docs/ko2020.pdf)

ACLEW 논문의 SEEDLingS 원자료 표는 6~17개월이고 현 HomeBank 소개는 연구 목표·자료를 6~18개월로 설명한다. 실제 사용할 파일의 월령을 확인해야 한다. ACLEW의 공개 주석 존재가 전체 원음의 공개나 상업 활용 허가를 의미하지 않는다. [ACLEW 원문](https://talkbank.org/homebank/access/0docs/soderstrom2021.pdf), [SEEDLingS 소개](https://talkbank.org/homebank/access/Password/Bergelson.html)

## 5 구현할 관찰 파이프라인 명세

### 5.1 원본과 추론 결과를 다루는 계약

온디바이스 원본 미보관·자동 업로드 없음이라는 현재 구조를 유지한다. 연구용 데이터 보관·외부 전송은 이 문서의 승인 범위가 아니다. 향후 별도 평가 프로젝트를 승인할 때만 정확한 자료·담당자·저장소·사용 목적·보관 기간·철회 방법을 정한다. 임베딩도 자동으로 익명 데이터라고 취급하지 않는다.

분석 중 메모리 객체의 권고 필드는 다음과 같다.

- `windowStartMs`, `windowEndMs`, `sourceType`, `modelVersion`, `preprocessVersion`
- `qualityFlags`: lowLevel, clipped, noisy, overlapSuspected, occluded, unstable, outOfScope
- `rawEventScores`, `speakerTypeScores`, `faceObservation`, `targetSelectionStatus`
- `decision`: suggested / ambiguous / insufficient / unsupported / failed
- `reason`: lowQuality / conflictingEvidence / unfamiliarInput / insufficientDuration 등
- `parentConfirmedEvent`, `parentContext`, `observationProvenance`

기술 로그에 아이 이름·원음·영상·문장 전문을 기본 저장하지 않는다. 장기 저장 schema를 바꾼다면 기존 기록·JSON 복원을 유지하는 명시적 마이그레이션과 별도 검토를 한다.

### 5.2 오디오의 첫 개선 실험

1. 현재 구현을 E0 기준선으로 동결한다
2. E2는 같은 YAMNet을 쓰되 raw class와 timestamp를 유지하고 검증셋으로 클래스별 문턱·집계만 조정한다
3. E4는 YAMNet 고정 임베딩+선형 또는 작은 MLP를 쓴다
4. E4의 추가 비교군은 구간 시계열 집계나 작은 temporal head를 추가한다
5. E5는 권리를 통과한 voc2vec/BabyHuBERT 임베딩으로 같은 분류기를 학습한다

E 번호는 8.1절 실험표와 같다. E3의 품질·화자 처리는 별도 비교하여 작은 분류기 자체의 효과와 섞지 않는다.

모든 비교는 동일한 아이 분할·학습 예산·라벨 정의·평가 입력을 사용한다. 파라미터 탐색 횟수까지 기록한다. 학습 자료가 작으면 복잡한 모델을 늘리기보다 오류 유형과 라벨 일치도를 먼저 확인한다. 학습 시 noise/mixup 등을 쓰더라도 검증·최종셋에는 같은 원본의 변형이 섞이지 않는다.

분류 출력은 하나의 과도한 의미 클래스보다 두 축이 적합하다.

- 소리 유형: 울음 / 웃음 / 비울음·비웃음 아이 발성 / 말소리 / 기타 / 판독 불가
- 화자 또는 출처: 아이로 확인 가능 / 성인 / 겹침 / TV·기기 / 불명

초기에는 ‘아이 발성’과 ‘옹알이’의 범위를 명확히 한다. squeal·growl·첫 단어까지 모두 옹알이 정답으로 강제하지 않는다. 더 세밀한 canonical/non-canonical 구분은 주석자 합의와 월령별 표본이 충분해진 뒤 연구 항목으로 둔다.

### 5.3 얼굴 관찰의 첫 개선 실험

1. 픽셀 축을 보정한 입 비율의 공통 함수를 만든다
2. 정적 입 열림과 시간에 따른 입 움직임을 서로 다른 사건으로 둔다
3. 단일 프레임 양성을 그대로 전체 장면으로 확장하지 않는다
4. 연속 양성 지속시간과 on/off 문턱을 개발셋에서 정한다. 긴 평활화가 짧은 움직임을 없애는지도 비교한다
5. 가림·측면·작은 얼굴·타깃 불명·프레임 누락이면 상태를 보류한다
6. 실제 timestamp로 오디오 사건 구간과 겹칠 때만 ‘같은 구간에서 입 움직임도 보임’을 표시한다

입 움직임이 소리와 동시 발생해도 화자가 그 아기라고 확정할 수는 없다. 화자 연결 기능을 내보내려면 입이 보이는 무음, 화면 밖 아이, TV 아기 영상, 보호자만 발성하는 사례를 포함한 별도 평가를 통과해야 한다.

### 5.4 문장 선택에도 증거 조건을 건다

큰 생성 모델을 추가하지 않아도 현재 문장 엔진을 더 정밀하게 만들 수 있다. 문장마다 필요한 관찰 태그를 두고 일치하는 후보만 반환한다.

- 소리만 확인한 경우 시선·웃는 얼굴·몸짓을 관찰 사실로 추가하지 않는다
- ‘너를 보며’처럼 특정 대상에 대한 시선이 필요한 표현은 보호자 확인이나 검증한 관찰이 있을 때만 사실형으로 쓴다
- 상황 선택은 후보의 주제·정리 순서를 바꾸되 소리 판정값을 뒤에서 덮어쓰지 않는다
- 이벤트 변화가 있는 구간은 단일 감정 대신 ‘소리가 이어지다가 웃음이 들린 순간’처럼 검증된 시간 순서를 활용한다
- 모델 관찰, 보호자 확인, 창작 표현을 데이터에서도 구분한다

이 변화의 효과는 ‘의도 정확도’가 아니라 **관찰과 문장의 불일치 감소, 보호자 수정 시간 감소**로 측정한다.

## 6 판단 보류와 점수 보정

판단 보류는 면책 문구가 아니라 오답 비용을 줄이는 분류기의 기능으로 설계한다.

1. **품질 보류**: 너무 짧음, 무음, 심한 클리핑, 얼굴 가림, 디코더 실패
2. **증거 보류**: 아이/성인 혼동, 상위 후보 충돌, 짧은 단발성 점수만 존재
3. **분포 밖 보류**: TV 소리·음악·동물·극단적 잡음 등 검증 범위 밖 입력
4. **신뢰 가능한 추천**: 해당 클래스의 사전 결정된 운영 기준을 만족한 경우

현재 raw YAMNet 0.8을 ‘80% 확률로 아기 뜻이 맞음’이라고 바꾸지 않는다. 새 모델의 보정도 해당 사건과 평가 도메인에 대한 것이다. 독립 calibration 가족에서 클래스별 신뢰도 곡선을 보고 점수 기반 Platt/등장 빈도 보정, 충분한 표본이 있을 때 isotonic 등 단순 방법부터 비교한다. logits가 있는 모델이면 temperature scaling도 후보지만, 멀티라벨과 상호배타 다중분류를 혼동하지 않는다.

추천 기준은 `품질 통과 AND 사건 점수 문턱 통과 AND 필요한 화자 근거 충족`과 같이 명시한다. 상위 두 점수 차이만으로 모든 불확실성을 해결하지 않는다. 점수가 높은 분포 밖 오답도 별도 시험한다. 월령별 문턱은 각 구간의 독립 표본이 충분할 때만 추가한다.

보고할 항목은 추천한 사례의 오류율과 **추천 비율(coverage)**의 곡선이다. 90%의 어려운 입력을 숨겨 남은 10%만 정확한 시스템을 전체 개선으로 포장하지 않는다. ‘후보 없음’, ‘분석 실패’, ‘판단 보류’도 서로 구분한다.

## 7 데이터와 평가 계획

### 7.1 승인 전에도 진행할 수 있는 일

현재 소스의 계산 함수·매핑·상태 전환 회귀 시험, 합성 PCM의 길이·채널·샘플레이트 시험, 문장 태그 검사, 평가 schema·주석 지침 작성은 아기 자료를 모으지 않고 준비할 수 있다. 아기 데이터가 없으면 실제 영아 분류 성능 확인은 보류된 상태로 명시한다.

### 7.2 단계별 데이터 규모 제안

아래 수는 **예산 계획을 위한 시작안**이며 통계적 충분성이나 출시 보증 기준이 아니다. 실제 사건별 빈도·아이 내 상관·오류율을 본 뒤 필요한 표본을 재산정한다. 모집과 수집을 시작하려면 별도 승인이 필요하다.

**90가족 안은 이후 영아용 모델을 검증하려는 선택적 연구 프로그램이다. 이번 주 보호자가 확인하는 투명한 테스트 베타의 선행조건이 아니다.** 기존 베타의 완료 기준은 기존 출시·사용성·데이터 보존 계획을 따르고, 이번 제안으로 임의 변경하지 않는다. 아기별 정확도 수치를 새로 주장하려는 시점에는 그 주장에 맞는 검증이 필요하다.

| 단계 | 계획 예시 | 목적 | 할 수 없는 주장 |
|---|---|---|---|
| 주석 파일럿 | 12~18가족, 6~8/9~12/13~18개월 균형 | 라벨 정의, 주석 합의, 입력 실패 발견 | 한국 영아 전체 정확도 |
| 개발 비교 | 총 90가족을 예로 train 45 / validation·calibration 18 / locked test 27 | 작은 분류기와 현재 모델 비교 | 작은 하위집단의 확정적 우열 |
| 외부 확인 | 별도 모집·기기·시점의 새 가족 | 실환경 재현, 도메인 이동 | 모든 기종·방언·조건 보장 |

locked test는 세 월령 구간별 예시 9가족을 확보하되 사건별 수가 적으면 더 확보한다. 검증·보정 자료가 부족하면 개발 가족 안의 grouped cross-validation을 사용하며 최종 27가족을 튜닝에 소비하지 않는다. 무작위 가정생활 표본과 사건이 많은 목적 표본을 따로 두어 실제 빈도의 precision과 희귀 사건의 recall을 각각 평가한다.

울음을 유도하거나 수유·위로를 미루지 않는다. 정상 일상에서 이미 생긴 장면만 대상으로 한다. 별도의 연구 동의가 없다면 보호자 기기에서 직접 평가하고 집계만 제공하는 방식도 검토할 수 있지만, 집계 정보와 임베딩의 개인정보성·전송 범위 역시 먼저 정한다.

### 7.3 데이터 분할의 최소 규칙

- 같은 아이의 다른 날짜·월령·클립·영상·오디오는 모두 같은 분할에 넣는다
- 형제자매·부모 목소리·집 배경이 겹치므로 가족 단위를 최상위 그룹으로 둔다
- 한 원본 영상에서 자른 오디오와 프레임, 중복 업로드, 모든 증강본도 같은 그룹이다
- 녹음 세션·기기·원본 파일 hash의 연결표로 누출을 감사한다
- 다른 공개 데이터와 병합할 때 원본 출처 중복을 확인한다
- 데이터 정규화·특징 선택·보정·threshold 튜닝은 개발 부분에서만 한다
- 새 아이 성능과 기존 아이의 나중 세션 개인화 성능을 다른 실험으로 보고한다

TensorFlow 공식 전이학습 예제도 같은 원본에서 나온 임베딩 프레임을 여러 분할에 흩뜨리면 평가가 오염된다고 설명한다. 이번 제품은 그보다 엄격하게 가족까지 묶어야 한다. [YAMNet 분할 안내](https://www.tensorflow.org/tutorials/audio/transfer_learning_audio)

### 7.4 주석 규칙

원음/영상 접근이 승인된 환경에서 두 평가자가 앱 결과와 보호자 원인 추정을 보지 않고 독립 주석한다. 불일치는 제3 검토 또는 합의 절차로 해결하고 합의 이전 점수도 보관한다. ‘모르겠다’, ‘소리가 겹친다’, ‘입이 가려졌다’를 정답 목록에 넣어 억지로 단일 라벨을 만들지 않는다.

오디오는 시작·끝 시점, 들린 사건, 화자 유형, 중첩·TV 여부, 판독 가능 여부를 기록한다. 영상은 타깃 얼굴, 관찰 가능한 입 열림/움직임, 고개 방향·가림·조명·얼굴 크기, 실제 프레임 시점을 기록한다. 68점/478점 전체 좌표를 무조건 주석할 필요 없이 제품 결정에 쓰는 입·눈 등의 공통 지점을 먼저 정한다.

평가자 간 사건별 F1, 구간 겹침, Cohen/Fleiss κ 또는 Krippendorff α 중 라벨 구조에 맞는 지표, 불일치 유형을 보고한다. 주석자 합의가 낮으면 먼저 정의를 단순화하고 예제를 보완한다. ACLEW의 화자→하위 유형→맥락 구조와 다단계 합의 절차를 방법 참고로 삼는다. [ACLEW 주석 연구](https://talkbank.org/homebank/access/0docs/soderstrom2021.pdf)

### 8.2 모델 평가 지표

- 사건별 precision, recall, F1와 macro-F1/UAR. 전체 accuracy는 보조 지표
- infant→adult 및 adult/TV→infant 혼동 행렬
- 사건 시간 검출: onset/offset 허용 오차와 overlap 기준을 시험 전에 고정한 event-F1. window-level F1도 별도 보고
- 사건이 없는 실제 녹음 시간당 오탐, 빈 후보·보류·처리 실패 비율
- 얼굴 검출 실패율, 입 주변 NME와 판정 F1, 같은 장면의 화면비·회전별 일관성
- 보정: Brier score, 클래스별 reliability curve, ECE. ECE 하나만으로 신뢰성 통과 처리하지 않음
- 선택적 추천: risk–coverage 곡선, 고정 coverage에서 오류 비교, 고정 precision에서 coverage 비교
- 속도: cold/warm 추론 p50/p95, 10초 입력 후 대기, 메모리 peak, 모델 크기, 발열·취소·실패율

신뢰구간은 클립을 독립 표본으로 수천 개 재표집하지 말고 **가족/아이 단위 cluster bootstrap**으로 계산한다. 변화량도 같은 가족을 짝지어 계산한다. 표본 수가 적은 조건에서는 평균 하나보다 가족별 분포와 실패 사례를 우선 보여 준다. 예측 실패를 조용히 제외해 denominator를 줄이지 않는다.

### 8.3 출시 판단의 시작안

다음은 **향후 새 자동 추천·단정 수준을 올리는 정책을 설계할 때** PM과 평가 담당자가 합의할 시작안이다. 논문이 보증하는 기준, 현재 앱의 측정 결과, 이미 승인된 출시 기준이 아니다. 기존의 보호자 확인형 베타를 이 숫자 때문에 갑자기 차단하자는 뜻도 아니다.

1. 좌표·시간·클래스 매핑의 결정론적 회귀 시험은 모두 통과
2. 새 영아용 자동 추천 정책은 클래스별 precision 목표를 먼저 정한다. 예를 들어 점추정 90% 이상과 95% 신뢰구간 하한 80% 이상을 검토할 수 있지만, PM 결정·calibration·표본 검토 전 적용하지 않는다
3. 위 기준을 통과한 coverage를 공개하며 충분한 빈도가 없는 클래스는 수동 확인 경로로 둔다
4. 보류를 포함한 전체 사건 recall과 성인/TV 오탐이 기준선보다 악화되지 않는지 확인한다
5. 새 모델 선택은 macro-F1뿐 아니라 동일 coverage의 오류, 지연·메모리·저사양 기기 실패를 함께 본다
6. 특정 월령·소음·기기에서만 좋아지면 그 조건을 명시하고 전체 개선이라고 부르지 않는다

표본 수가 적어 신뢰구간 기준을 판단할 수 없다면 ‘통과’도 ‘모델 실패’도 아니다. 추가 독립 자료가 필요한 상태다. 목표 숫자는 test를 보기 전에 결정하고 결과를 보고 유리하게 바꾸지 않는다.

## 9 보호자 맥락의 기여를 모델 정확도와 분리하는 시험

보호자 맥락은 제품 가치를 높일 수 있다. 이를 센서 모델이 더 정확해졌다는 증거로 잘못 읽지 않도록 두 시험을 나눈다.

### 사건 정확도 시험

독립 주석을 정답으로 두고 아래를 비교한다.

- A: 오디오 모델 단독
- B: 영상 관찰 단독
- C: 같은 시점의 오디오+영상
- D: C에 보호자 상황을 추가한 별도 모델 또는 규칙

D가 좋아져도 소리 검출 정확도와 문장/상황 적합성 개선을 따로 보고한다. 상황만 사용한 기준선도 두어 ‘수유 전이면 배고픔’ 같은 지름길이 성능을 지배하는지 확인한다. 문맥을 가린 상태와 실제 문맥에서의 사건 정답이 다른 문제인지도 점검한다.

### 보호자 사용 시험

앱의 추천을 보여 주기 전에 보호자가 들은 사건과 상황을 먼저 기록하는 조건을 둔다. 추천 노출 후 같은 보호자의 ‘맞다’ 응답만 정답으로 삼으면 동조·확증 효과가 생긴다. 모델+맥락, 맥락만, 보호자 직접 선택 조건을 순서 균형을 맞춰 비교하고 같은 장면을 반복 보여 주는 학습 효과를 줄인다.

평가 항목은 최종 문장의 관찰 불일치, 첫 후보 채택, 수정한 단어·의미, 완료 시간, 질문 수, 피로도, 모델이 알지 못한 사실을 안다고 오해한 비율이다. 만족도·선호는 효용 지표이며 영아 마음의 정답률이 아니다.

‘이 아기에게 5번 확인받으면 개인화 완료’처럼 데이터 없이 적은 예시 수를 약속하지 않는다. 향후 개인화는 사건 정답 학습, 기기 품질 보정, 문장 취향 학습을 분리하고 **새 아이 시험과 기존 아이의 미래 세션 시험**을 각각 한다.

- 완료: 기존 보호자 확인 흐름 유지, 불필요한 원격 전송·영구 저장 없음. 문턱을 임의 변경하지 않음

## 부록 합성 기하 회귀 검산

아래 코드는 Python 표준 라이브러리만 사용한다. 네 점은 위·아래 입술과 왼쪽·오른쪽 입꼬리의 합성 픽셀 좌표다. 좌표 변환 후 정규화하고 다시 올바른 입력 W·H로 계산했을 때 비율 0.1이 보존되는지 확인한다. 실제 모델·영아 사진·영상은 사용하지 않는다.

```python
from math import hypot, isclose

points = [(800., 440.), (800., 450.), (750., 445.), (850., 445.)]

def mouth_ratio(points, width, height):
    normalized = [(x / width, y / height) for x, y in points]
    def distance(i, j):
        return hypot(
            (normalized[i][0] - normalized[j][0]) * width,
            (normalized[i][1] - normalized[j][1]) * height,
        )
    return distance(0, 1) / distance(2, 3)

cases = []
for angle in (0, 90, 180, 270):
    if angle == 0:
        p, w, h = points, 1600, 900
    elif angle == 90:
        p, w, h = [(900-y, x) for x, y in points], 900, 1600
    elif angle == 180:
        p, w, h = [(1600-x, 900-y) for x, y in points], 1600, 900
    else:
        p, w, h = [(y, 1600-x) for x, y in points], 900, 1600
    cases.append((f"rotation_{angle}", mouth_ratio(p, w, h)))

cases += [
    ("uniform_scaled", mouth_ratio([(x*.32, y*.32) for x,y in points], 512, 288)),
    ("letterbox_512", mouth_ratio([(x*.32, y*.32+112) for x,y in points], 512, 512)),
    ("mirror", mouth_ratio([(1600-x, y) for x,y in points], 1600, 900)),
    ("crop", mouth_ratio([(x-700, y-400) for x,y in points], 200, 100)),
]
for name, value in cases:
    assert isclose(value, .1, abs_tol=1e-12), (name, value)
    print(name, round(value, 8), "PASS")
```

이번 검산 결과: rotation 0/90/180/270, uniform_scaled, letterbox_512, mirror, crop의 8개 사례 모두 0.1·PASS. 합성 검산의 통과는 Android 실제 좌표 변환, MediaPipe 추론, 영아 입 판정의 성능 검증을 대체하지 않는다.
