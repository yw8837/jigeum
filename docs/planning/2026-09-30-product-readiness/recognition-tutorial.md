## 1 목적과 선택한 방식

보호자가 일상에서 소리·장면을 담을 때 흔한 혼동을 줄이고, 결과를 직접 확인해 즐겁게 한마디를 남길 수 있도록 돕는다. 튜토리얼의 목표는 첫 사용의 시행착오를 줄이는 것이며, 영아 인식 정확도 향상이 이미 입증됐다는 뜻은 아니다.

**첫 안내 한 화면의 세 가지 팁 + 입력 화면의 한 문장 도움말 + 필요할 때 펼치는 설명**으로 구성한다. 긴 슬라이드, 필수 동영상, 강제 연습 녹음은 추가하지 않는다. 아래 상태표·QA·개발 제한은 개발자를 위한 명세이며 사용자 화면에 한꺼번에 노출하는 경고문이 아니다. 각 화면에는 기본 한 문장, 해당 상태의 문구 하나만 우선 표시한다.

- 첫 안내는 확인·건너뛰기 모두 가능하고, 어느 버튼도 센서를 켜거나 파일 선택기를 열지 않는다
- 각 입력 화면에서 도움말을 펼쳐도 현재 화면·선택·메모·문장 초안을 유지한다
- 음성·직접 입력은 무료다. 카메라·저장영상은 기존 전체 이용권 확인 뒤 기능 화면에 들어가고, 실제 실행은 별도 버튼으로 시작한다
- 모델이 관찰한 단서, 보호자가 고른 상황, 아이 시점의 표현을 구분한다
- 아기를 먼저 돌본다. 소리를 얻기 위해 울음을 유도하거나 위로·수유 등 돌봄을 미루도록 안내하지 않는다
- 기존 입 비율 계산·시간 정렬 개선 작업은 별도로 진행한다. 튜토리얼로 기술적 오류를 해결했다고 보고하지 않는다

검토한 대안은 상시 긴 설명과 필수 단계형 튜토리얼이다. 전자는 반복 사용에 부담이고 후자는 기록 진입을 막으므로 채택하지 않는다. 이번 안은 기존 입력 흐름 안의 제한된 변경이다.

## 2 첫 안내의 정확한 문구

홈의 데이터 로딩이 끝난 뒤 조건을 만족할 때만 표시한다. 한 화면의 스크롤 가능한 안내이며 자동 페이지 넘김은 없다.

두 버튼은 안내만 닫고 원래 홈에 머문다. 시스템 뒤로가기·닫기·바깥 영역 탭도 건너뛰기와 같다. ‘동의’ 버튼이나 약관 승인으로 사용하지 않는다. 버튼을 누르기 위해 팁 끝까지 스크롤하거나 일정 시간을 기다릴 필요가 없다.

첫 안내의 카메라·영상 팁은 사용 방법 설명이며 무료 기능 제공 약속이 아니다. 카메라·영상 진입 버튼의 전체 이용권 표기와 기존 유료 기능 안내를 유지한다. 도움말 자체는 모든 사용자에게 무료로 보인다.

## 3 화면별 상시 도움말과 펼친 내용

한 문장 도움말은 화면 폭·글자 크기에 따라 자연스럽게 줄바꿈한다. ‘한 줄’이라는 이유로 한 줄 ellipsis 처리하지 않는다. 현재 긴 설명과 중복될 때에는 같은 의미를 한 번만 보여 준다.

### 3.1 소리 녹음 화면

제목은 기존 흐름을 따르고, 녹음 시작 버튼 앞에 다음 문구를 둔다.

- 상시 도움말: **“TV·음악·보호자 목소리가 겹치지 않는 순간에 담아 주세요”**
- 범위 안내: **“최대 10초만 들어요. 끝나면 직접 들은 소리를 확인해 주세요”**
- 기존 개인정보 설명 유지: **“소리는 기기 안에서 분석하고 원본은 저장하지 않아요”**
- 펼침 버튼: **“소리 담는 팁 보기”** / 펼친 뒤 **“팁 접기”**

펼친 팁은 세 항목으로 제한한다.

1. “휴대폰을 아기 얼굴에 바짝 대지 말고, 안전하게 들 수 있는 자리에서 담아 주세요”
2. “보호자 웃음이나 TV 속 아기 소리도 후보로 잡힐 수 있어요. 누구 소리인지 직접 확인해 주세요”
3. “조용하거나 소리를 내지 않아도 괜찮아요. 녹음 없이 직접 고를 수 있어요”

‘최적 거리 20cm’, ‘주변 소음 30dB 이하’, ‘10초를 꽉 채우면 정확’ 등 검증되지 않은 수치는 넣지 않는다. 현재 파형 애니메이션을 실제 입력 음량계로 소개하지 않는다. 녹음 중 큰 파형을 만들려고 아이 가까이 이동하거나 더 큰 소리를 유도하게 하지 않는다.

주 행동은 기존 **“녹음 시작”**, 녹음 중 **“여기서 마치기”**다. 무료 대체 버튼은 **“녹음 없이 직접 선택하기”**로 제안한다. 이 버튼은 기존 직접 입력 흐름으로 연결하며 아기 소리를 자동 선택하지 않는다.

### 3.2 카메라 관찰 화면

유효한 이용권으로 화면에 들어온 뒤, 카메라 시작 버튼 전에 표시한다. 권한이 이미 허용됐더라도 카메라는 꺼진 상태다.

- 상시 도움말: **“살펴볼 아이 한 명의 얼굴이 자연스럽게 보이도록, 화면을 천천히 맞춰 주세요”**
- 펼침 버튼: **“장면 담는 팁 보기”** / **“팁 접기”**
- 실행 버튼: 기존 **“카메라 시작”**

펼친 팁:

1. “가능하면 얼굴 앞쪽이 편안하게 밝은 곳에서, 휴대폰을 천천히 움직여 주세요”
2. “손이나 물건에 얼굴이 가려져 있으면 직접 본 장면을 골라도 괜찮아요. 자세나 쪽쪽이를 억지로 바꾸지 마세요”
3. “아이를 안전하게 돌볼 수 있을 때만 사용해 주세요. 화면 밖 소리의 주인은 얼굴만으로 알 수 없어요”

‘조명이 충분해요’, ‘아이 얼굴을 정확히 찾았어요’, ‘여러 사람이 감지됐어요’ 같은 자동 품질 메시지는 새로 만들지 않는다. 현재 한 얼굴 결과만 받으며 밝기·가림·타깃 아이 신원을 측정하지 않기 때문이다. 녹색 정확도 게이지·자동 거리 안내도 없다.

장면의 상태는 ‘모델 관찰 단서’로 표시한다. 입이 벌어졌다는 출력에 배고픔·졸림·기분을 연결하지 않는다. 직접 선택한 ‘눈 맞춤’·‘고개 돌림’을 자동 감지 결과처럼 표시하지 않는다.

### 3.3 저장영상 화면

이용권 확인 후, 파일 선택기를 열기 전에 분석 범위를 알려 준다.

- 상시 도움말: **“소리는 처음 10초만, 얼굴은 영상 전체에서 고른 최대 5개 장면만 살펴봐요”**
- 파일 조건: 기존 **“30초 이내 · 50MB 이하”**
- 보조 설명: **“소리와 얼굴 단서가 서로 다른 순간일 수 있어요. 영상을 재생해 직접 확인해 주세요”**
- 펼침 버튼: **“영상 고르는 팁 보기”** / **“팁 접기”**
- 실행 버튼: 기존 **“영상 고르기”**

펼친 팁:

1. “기록하고 싶은 소리가 처음 10초 안에 담긴 영상을 골라 주세요”
2. “아이 얼굴이 자연스럽게 보이고, TV·음악·보호자 말소리가 덜 겹치는 장면을 골라 주세요”
3. “뒤쪽의 소리나 지나가는 표정은 놓칠 수 있어요. 직접 보고 들은 내용으로 선택해도 괜찮아요”

이 앱 안에서 자르기 기능이 이미 있는 것처럼 안내하지 않는다. 원본 영상을 변경하거나 별도 편집 앱 설치를 선행조건으로 요구하지 않는다. 특정 장면을 못 찾았으면 재촬영을 강요하지 않고 직접 선택 경로를 제공한다.

**이 문구는 f83887c의 분석 범위에 맞춘 것이다.** 첫 10초로 영상 분석 범위를 맞추는 기술 변경이 실제 적용되면 그 빌드의 실제 구간 계약에 맞춰 문구도 변경한다. 이번 튜토리얼 구현만으로 시간 정렬이 완료됐다고 쓰지 않는다. 파일 전체 duration, 실제 분석 구간, 요청 프레임 수와 성공 프레임 수를 혼동하지 않는다.

### 3.4 소리와 상황 확인 및 결과 화면

- 소리 선택 앞: **“후보가 맞는지 직접 확인해 주세요. 맞는 것이 없으면 직접 고르면 돼요”**
- 상황 선택 앞: **“그때 실제로 있었던 상황을 골라 주세요”**
- 표현 후보 앞: **“아이 시점의 표현 예시예요. 우리 아이의 순간에 맞게 고쳐 남겨요”**
- 모델 단서 소제목: **“기기에서 찾은 단서”**
- 보호자 선택 소제목: **“보호자가 고른 소리와 상황”**
- 상세 설명 버튼: **“단서는 어떻게 쓰이나요?”**
- 상세 설명 본문: **“기기는 일반 소리와 일부 얼굴 모양을 살펴봐요. 소리와 상황은 보호자가 확인하고, 한마디는 표현 예시에서 골라요”**

현재 PhraseEngine은 소리·상황·세션 ID를 사용한다. 얼굴·시선이 문장의 내용을 이미 결정한다고 설명하지 않는다. ‘관찰 단서’ 자체가 없거나 모델 실행이 실패했으면 빈 영역을 성공처럼 꾸미지 않는다.

## 4 실제 상태에 연결할 짧은 도움말

상시 팁은 사용자에게 권하는 행동이고 상태 메시지는 코드가 확인한 사실이다. 둘을 같은 신호처럼 다루지 않는다. 오류가 있으면 현재 오류 설명을 우선하고, 관련 없는 조언을 여러 개 덧붙이지 않는다.

### 4.1 음성 상태

| 실제 상태·조건 | 표시할 짧은 문구 | 연결 행동 |
|---|---|---|
| CapturePhase.READY | TV·음악·보호자 목소리가 겹치지 않는 순간에 담아 주세요 | 녹음 시작 / 녹음 없이 직접 선택하기 |
| RECORDING | 필요한 순간을 담았다면 지금 마쳐도 돼요 | 여기서 마치기 / 녹음 중단하고 직접 선택하기 |
| ANALYZING | 소리 단서를 살펴보는 중이에요 | 분석 취소하고 직접 선택하기 |
| REVIEW, problem 없음, cues 비어 있음 | 자동으로 구분한 소리 후보가 없어요. 직접 들은 소리를 골라 주세요 | 기존 소리 선택 |
| REVIEW, problem 있음 | 분석 안내를 확인하고, 직접 들은 소리를 골라도 괜찮아요 | 기존 구체적 problem 문구 + 직접 선택 |
| permissionDenied=true | 마이크 없이도 직접 고르고 기록할 수 있어요 | 녹음 없이 직접 선택하기 / 기존 앱 설정 버튼 |
| 후보에 ‘말소리(화자 미확인)’ 포함 | 말소리 후보예요. 아기 소리인지 직접 확인해 주세요 | 기존 소리 선택 |
| 후보에 ‘웃음’ 포함, 다른 오류 없음 | 웃음 후보에는 보호자나 TV 소리가 섞일 수 있어요. 직접 확인해 주세요 | 기존 소리 선택 |
| 앱 이탈로 녹음 중단 | 앱을 벗어나 녹음을 중단했어요. 다시 시작하거나 직접 고를 수 있어요 | 명시적 녹음 시작 / 직접 선택 |

빈 후보를 ‘너무 시끄러움’, ‘아무 소리 없음’으로 치환하지 않는다. 직접 녹음에는 RMS 기반 무음 판정이 없다. `SoundAnalysis.problem`은 현재 문자열이므로 새 튜토리얼이 한국어 문구를 비교해 원인을 추측하지 않는다. 꼭 세부 분기가 필요하면 기존 PCM 길이 검사·예외 분기에서만 타입화된 reason을 내보내는 작은 변경으로 한정한다. 새 소음·정확도 측정을 만들지 않는다.

후보별 도움말을 동시에 여러 줄로 쌓지 않는다. 우선순위는 처리 오류/권한 → 빈 후보 → 화자 미확인 말소리 → 웃음 후보 → 일반 확인 안내다. 점수의 높낮이를 ‘아기 뜻의 신뢰도’로 표시하지 않는다.

### 4.2 카메라 상태

| 실제 상태·조건 | 표시할 짧은 문구 | 제한 |
|---|---|---|
| active=false | 카메라가 꺼져 있어요. 준비되면 시작해 주세요 | 도움말 닫기로 자동 시작하지 않음 |
| active=true, cameraReady=false, error 없음 | 카메라를 연결하고 있어요 | 밝기·가림을 추측하지 않음 |
| WAITING, cameraReady=true | 아이 얼굴이 보이도록 화면을 천천히 맞춰 주세요 | 아직 품질 판정 전의 행동 팁 |
| NO_FACE | 지금 화면에서 얼굴을 찾지 못했어요. 화면을 보고 직접 확인해 주세요 | ‘아이 없음’ 또는 ‘어두움’으로 단정하지 않음 |
| FACE_VISIBLE | 얼굴 모양을 찾았어요. 살펴볼 아이인지 직접 확인해 주세요 | 아이 신원·단독 얼굴 확인을 주장하지 않음 |

| warning!=null | 자동 얼굴 관찰을 사용할 수 없어요. 직접 본 장면으로 계속할 수 있어요 | 기존 실제 warning 설명 우선 |
| error!=null | 카메라 안내를 확인하거나, 직접 선택으로 계속해 주세요 | 구체적 원인은 기존 error만 사용 |

권한 거절은 `hasPermission=false`만으로 추정하지 않는다. 아직 요청하지 않은 경우와 구분해야 하므로 실제 permission callback에서 거절된 사건만 사용한다. 여러 얼굴·역광·가림·흔들림 감지 배지는 이번 범위에 없다.

### 4.3 저장영상 상태

| 실제 상태·조건 | 표시할 짧은 문구 |
|---|---|
| 선택 전 | 소리는 처음 10초만, 얼굴은 영상 전체에서 고른 최대 5개 장면만 살펴봐요 |
| pickerPending=true | 영상 선택 화면을 열었어요 |
| analyzing=true | 영상의 일부 장면과 첫 10초 소리를 살펴보고 있어요 |
| audio.status=NO_TRACK | 영상에 오디오 트랙이 없어요. 화면을 보고 장면을 고를 수 있어요 |
| SILENT | 처음 10초에서 소리를 거의 감지하지 못했어요. 직접 들어 확인해 주세요 |
| NO_CUES | 처음 10초 소리를 자동으로 구분하지 못했어요. 직접 들어 골라 주세요 |
| CUES | 처음 10초의 일반 소리 후보예요. 누구 소리인지 직접 확인해 주세요 |
| UNSUPPORTED / FAILED / TIMEOUT | 소리 분석을 마치지 못했어요. 영상을 직접 듣거나 직접 선택으로 계속해 주세요 |
| modelAvailable=true, analyzedFrames>0, faceFrames=0 | 살펴본 장면에서는 얼굴을 찾지 못했어요. 영상을 보고 직접 골라 주세요 |
| modelAvailable=false | 자동 얼굴 관찰을 사용할 수 없어요. 영상을 보고 직접 골라 주세요 |
| 프레임 분석 일부 실패 | 일부 장면만 확인했어요. 영상을 직접 보고 함께 확인해 주세요 |
| 형식·크기·길이 오류 | 기존 실제 오류 문구 유지 + 다른 영상 고르기 / 무료 직접 선택으로 계속하기 |

개발 시 `VideoFrameSummary.sampleCount`는 요청한 프레임 수가 아니라 디코딩에 성공한 수다. 부분 얼굴 분석 실패는 이 수와 `analyzedFrames`를 비교하며, 요청 실패까지 알 수 있는 것처럼 표시하지 않는다.

SILENT는 기존 첫 10초 RMS 검사 결과이며 영상 전체의 무음이나 실제로 아기가 소리를 내지 않았다는 판정이 아니다. 얼굴 0건도 샘플에서 미검출됐다는 의미다. 선택 취소는 오류로 알리지 않고 이전 선택·결과가 있다면 유지한다.

## 5 권한과 이용권 순서

### 무료 소리 경로

홈 → 소리 화면과 팁 표시 → 사용자가 ‘녹음 시작’ → 필요한 경우 OS 마이크 권한 → 허용되면 사용자가 시작한 녹음 수행.

튜토리얼 ‘확인했어요’, ‘건너뛰기’, 팁 펼침·닫힘은 권한 요청이나 녹음 시작으로 연결하지 않는다. 직접 선택에는 마이크 권한이 필요 없다. 권한에서 돌아와 안내를 다시 열었다는 이유로 두 번째 녹음이 시작되면 안 된다.

### 카메라 경로

홈 카메라 선택 → 기존 `enterPaid(CAMERA)`와 media session 확인 → 권한이 없으면 이용권 화면 → 유효하면 카메라 화면과 팁 표시 → ‘카메라 시작’ → 필요한 경우 OS 카메라 권한 → 시작.

### 저장영상 경로

홈 영상 선택 → 기존 `enterPaid(VIDEO_IMPORT)`와 media session 확인 → 유효하면 영상 화면과 범위 팁 표시 → ‘영상 고르기’ → OS 파일 선택기 → 돌아온 callback에서 이용권·session·화면 생존 확인 → 분석.

안내 화면이나 펼친 도움말은 `authorizeMedia`를 대체하지 않는다. 안내를 읽는 사이 이용권이 만료되면 다음 유료 행동은 막고 기존 정책대로 처리한다. 늦은 카메라 권한·파일 선택 응답이 다른 화면이나 문장 초안을 덮어쓰지 않게 한다. 구매 복원·유료 전환 완료 뒤에도 튜토리얼이 센서·선택기를 자동으로 열지 않는다.

## 6 도움말을 다시 여는 방식과 초안 보존

### 진입점

- 기존 안내 탭: **“소리·장면 담는 팁”**. 모든 팁을 무료로 열람
- 기존 안내 탭의 해당 도움말 안: **“처음 안내 다시 보기”**. 첫 세 가지 팁 재생
- 소리·카메라·저장영상: 3절의 화면별 ‘팁 보기’ 버튼
- 결과/소리·상황 확인: **“단서는 어떻게 쓰이나요?”**

입력 화면에서 팁을 누르면 **같은 Composable의 inline 영역을 펼친다.** Page.GUIDE로 이동하거나 입력 화면을 unmount하지 않는다. 따라서 도움말을 여닫는 것만으로 녹음 상태, `selectedUri`, `summary`, `heardSound`, `manualNote`, 소리·상황·메모, `BabyExpression.sessionId`, 수정한 문장을 지우지 않는다.

녹음·카메라 동작 중에는 팁을 펼쳐도 센서를 새로 시작하거나 재시작하지 않는다. 현재 녹음/카메라 상태와 중지 버튼이 항상 확인 가능해야 하며, 설명이 이를 화면 밖으로 밀어내면 고정 행동 영역 또는 별도 스크롤 영역을 사용한다. 전체 안내 replay는 홈/안내 탭의 비센서 화면에서만 열어 활성 센서 위를 가리는 modal을 만들지 않는다.

분석 중 팁을 펼쳐도 분석을 자동 취소하지 않는다. 취소는 명시적 버튼으로만 한다. 앱 백그라운드 이탈 시에는 기존 중단·정리 정책을 유지하고, 복귀 시 자동 센서 재시작은 하지 않는다.

### 언제나 가능한 무료 대체 경로

| 위치 | 표시 버튼 | 행동 |
|---|---|---|
| 소리 준비/권한 거절 | 녹음 없이 직접 선택하기 | 같은 RecordScreen의 REVIEW로 이동, 직접 소리·상황 선택 |
| 녹음 중 | 녹음 중단하고 직접 선택하기 | 녹음 종료·RAM 원음 폐기 후 직접 선택. 자동 소리 선택 없음 |
| 분석 중 | 분석 취소하고 직접 선택하기 | job 취소·원음 폐기 후 직접 선택. 늦은 분석 응답 폐기 |
| 소리 결과 | 후보가 맞지 않으면 직접 골라 주세요 | 기존 선택 폼 유지 |
| 카메라/영상 오류·닫힌 상태 | 무료 직접 선택으로 계속하기 | media session/작업 종료 후 무료 직접 입력으로 이동 |
| 카메라/영상에서 이전 문장 초안이 남아 있음 | 만들던 문장 계속하기 | 새 초안을 만들거나 지우지 않고 기존 TRANSLATE/session 복원 |
| 이용권 화면 | 기존 무료 계속하기 버튼 | 기존 접근 정책 유지 |

기존 초안이 있으면 초안 계속하기를 우선한다. 도움말·fallback은 그 초안을 지우거나 새 미디어 결과로 덮어쓰지 않는다. 직접 입력 폼에 이미 입력한 상황·메모가 있으면 분석 취소 뒤에도 유지한다. 소리 라벨은 보호자가 다시 확인해야 하고, 취소된 분석의 cue를 정답처럼 남기지 않는다.

카메라·영상 입력 도중의 원본 URI·미디어는 새로운 영구 초안 데이터로 저장하지 않는다. 기존 메모를 다른 화면으로 넘길 필요가 있으면 사용자가 고른 문자열만 전달하고, 튜토리얼 때문에 영상 원본을 저장하지 않는다. 현재 Source enum에 MANUAL이 없으므로 튜토리얼을 위해 임의의 기록 schema 확장을 하지 않는다.

## 7 표시 상태와 기기 내 설정

### 최소 영구 설정

전용 로컬 preferences에 `recognitionIntroHandledVersion: Int`, 초기값 0을 둔다. 이번 문구 버전은 1이다. 이 값은 ‘읽고 이해함’·동의·정확도 학습 여부가 아니라 **자동 안내를 이미 처리했는지**만 의미한다. 서버·분석 SDK·계정·JSON 기록 백업에는 넣지 않는다.

### 첫 사용과 재표시 규칙

1. `loaded=true`, 홈, 활성 입력 작업 없음, 저장된 문장 초안 없음, handledVersion<1일 때만 자동 표시를 검토한다
2. 기존 기록이 있는 업그레이드 사용자는 자동 modal을 생략하고 handledVersion을 1로 둔다. 안내 탭에서 언제든 다시 볼 수 있다
3. 새 설치 또는 기록·설정이 없는 경우 첫 홈에서 한 번 표시한다
4. 확인·건너뛰기·닫기·시스템 뒤로가기·바깥 탭으로 명시적으로 닫으면 handledVersion=1
5. 화면을 연 것만으로 처리 완료로 저장하지 않는다. OS에 의해 중단되면 재진입 시 아직 처리하지 않은 안내로 남을 수 있다
6. 회전·재구성에서는 같은 표시 상태를 복원해 겹쳐서 두 번 띄우지 않는다. 초안 복구 화면을 안내로 가리지 않는다
7. 일반 업데이트는 값을 유지한다. 단순 카피 수정으로 매번 재노출하지 않는다
8. ‘처음 안내 다시 보기’는 재생만 한다. 값을 0으로 돌리거나 센서 권한을 초기화하지 않는다
9. ‘모든 기록 삭제’는 튜토리얼 설정을 초기화하지 않는다. 아기 기록 삭제와 안내 설정을 연결하지 않는다
10. 앱 데이터 지우기·정상적인 새 설치에서는 로컬 설정이 없어져 첫 안내가 다시 나온다. 외부 JSON 기록 복원은 안내 설정을 덮어쓰지 않는다

현재 manifest는 OS backup을 비활성화한다. 이후 설정이 바뀌면 이 preferences가 클라우드 백업·기기 전송에 들어가지 않도록 기존 데이터 추출 규칙을 함께 검토한다. 설정 쓰기 실패가 무료 사용을 막거나 센서 실행을 유발하면 안 된다. 해당 프로세스에서는 재팝업을 막고, 로그에 개인 기록을 남기지 않는다.

### 일시 상태

- `introVisible`과 `expandedHelpSection`: 화면 복원용 작은 UI 상태만 사용
- 팁 표시를 위해 녹음 길이·음량·영상 밝기·아기 프로필을 새로 수집하지 않음
- 기존 enum·필드에서 `TutorialHint`를 순수하게 도출. 비어 있는 상태를 임의로 ‘소음’·‘가림’으로 채우지 않음
- 새 상태를 만들더라도 기존 사실의 명칭 정리에 한정. 프레임 품질 모델이나 새 분류기를 숨겨 추가하지 않음
- UI 문자열 비교로 상태를 알아내지 않음. 늦은 callback에는 기존 media session/작업 생존 검사를 유지

## 8 접근성 요구사항

- 세 팁에 제목과 읽기 순서를 제공하고, 번호·아이콘·색만으로 의미를 전달하지 않는다
- 팁 영역은 200% 글자 크기·작은 화면·가로 화면에서 스크롤 가능하고 텍스트 잘림이 없다
- 확인·건너뛰기·직접 선택·닫기·녹음 중지의 터치 영역은 최소 48dp를 설계 기준으로 둔다
- TalkBack에서 첫 안내의 제목부터 순서대로 읽고, 닫은 뒤 시작점에 focus를 돌려준다
- 펼침 버튼은 펼침/접힘 상태를 접근성 속성으로 제공한다. 팁을 펼쳐도 녹음 중지 버튼에 접근 가능하다
- 팁을 읽는 시간 제한·자동 전환·강제 애니메이션·소리 재생을 두지 않는다
- 카메라 매 프레임 상태나 녹음 매초 진행을 TalkBack live announcement로 반복하지 않는다. 상태 텍스트는 읽을 수 있고, 시작·중지·권한 실패 같은 주요 전환만 한 번 알린다
- 녹음 중 실제 음량을 재지 않는 장식 파형은 음량계로 읽히지 않게 한다
- 도움말 본문과 오류 본문이 겹칠 때 오류를 숨기지 않는다. 단순 회색 작은 글씨만으로 중요한 범위·fallback을 표현하지 않는다

## 10 Codex 구현 순서와 범위

1. 현재 checkout의 실제 분석·이용권·초안 계약을 재확인한다. 이 문서의 기준 이후 코드가 바뀌었다면 문구부터 맞춘다
2. 첫 안내와 로컬 처리 설정, inline 팁 구성요소·문자열·접근성 속성을 구현한다
3. 기존 상태만 읽어 상황별 한 문장 도움말을 연결한다. 오류·권한·유료 확인은 기존 흐름을 재사용한다
4. 무료 fallback을 빠뜨리지 않고, 기존 draft/session·메모 보존과 늦은 callback을 시험한다
5. 단위/Compose/기기 시험 결과를 구분해 보고하고 접근성·텍스트 범위를 실제 화면에서 확인한다

이번 범위에 정확도 점수·품질 측정기·새 모델·아기 원본 수집·서버 로깅·자르기 편집기·발달 또는 의료 판정은 포함하지 않는다. 앱 이름, 확정 무료·유료 정책, 결제 준비 상태도 변경하지 않는다. 계산 수정과 시점 보존은 앞서 승인된 별도 정확도 작업안을 따른다.
